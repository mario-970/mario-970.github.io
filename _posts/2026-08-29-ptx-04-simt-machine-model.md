> 本文是 [PTX 专栏](/ptx/) 第 4 期，对应官方文档 §3.1–3.2。

## TL;DR

GPU 的执行核心是一组可扩展的**流多处理器（SM，Streaming Multiprocessor）**。每个 SM 内部是多个**标量处理器核（SP，Scalar Processor）**、一个多线程指令单元和一块片上共享内存。硬件把线程块切成固定大小的 **warp**（一批并行线程），同一 warp 里的线程同时从同一个程序地址出发，但各自用独立的指令地址和寄存器状态往下走——这就是 **SIMT（单指令多线程）**。SIMT 的关键在「单线程语义」：每一条指令描述的都是**一个**线程的行为，而不是像 SIMD 那样把向量宽度写进指令。当 warp 内线程因数据依赖的条件分支走向不同路径时，硬件会**串行执行每一条被选中的路径**，关掉不在该路径上的线程，最后再汇合。自 Volta 起，硬件进一步支持**独立线程调度**，让线程能在子 warp 粒度分叉、重汇合。

## 一、概念铺垫：一群线程怎么落到有限的硬件上

前三期讲了线程的层级（grid → block → thread）和数据的层级（寄存器 → 共享 → 全局）。这些是**软件模型**：程序员眼里有成千上万个线程，每个线程跑同一份代码、处理一个数据元素。但物理上，GPU 芯片里不可能为每个线程都铺一条独立的取指、译码、执行流水线——那既不现实，也没必要。

于是需要一个「桥」：把海量的软件线程，高效地映射到数量有限的物理执行单元上。NVIDIA 给出的答案是 **SIMT**。它的核心思路是一句朴素的话：**让一批线程共用一条指令流，但各自保留自己的数据状态**。这样，取指、译码这些最贵的开销被分摊到一整批线程上，而每个线程又不必牺牲「我处理我的那个元素」的独立性。

§3.1–3.2 要回答的就是：这个「桥」具体长什么样，以及它有一个怎样的关键副作用——分支分歧。

## 二、文档语义：§3.1 SM 阵列与 SIMT

§3.1 的措辞可以拆成七句话来读。

**第一句，SM 阵列与块的分发。** GPU 围绕着一组可扩展的多线程 SM 构建。host 启动一个 kernel grid 时，grid 里的 block 被**枚举**后，分发给**有空闲执行容量**的 SM；一个 block 的所有线程在**同一个 SM** 上并发执行；当一个 block 结束时，新的 block 会被派到这个腾出来的 SM 上。所以「block 和 SM」不是一对一绑定的，而是动态填坑的关系——block 是调度单位，SM 是执行场地。

**第二句，SM 的内部结构。** 一个 SM 由三类东西组成：多个 **SP 核**（真正干活的标量执行单元）、一个**多线程指令单元**、以及**片上共享内存**（这块留到第 5 期专门讲）。SM 在硬件里创建、管理、并发执行线程，而且**调度零开销**；它还实现了一种「单指令屏障同步」。轻量线程创建 + 零开销调度 + 快速屏障，这三样合起来支撑起**极细粒度并行**：给每个数据元素（图像的一个像素、体数据的一个体素、网格计算的一个单元）分一个线程这种分解方式，靠的就是它。

![Hardware Model](/images/ptx/hardware-model.png)

*图 4：Hardware Model（官方文档 §3.1 Figure 4）——一组带片上共享内存的 SIMT 多处理器（SM）。*

这里值得追问一句：为什么「零开销调度」这么关键？因为 GPU 靠**大量线程把访存延迟盖住**——当一个 warp 因为读全局内存而停顿（一次内存访问动辄几百个时钟周期），SM 可以**零开销地**切到另一个就绪的 warp 继续发射指令。这种切换没有上下文保存/恢复的代价，所以「线程越多，延迟被藏得越好」。这正是 SIMT 能让「一个数据元素一个线程」的极细粒度分解成立的底层原因：线程廉价到可以随便开，开得越多，硬件手里就有越多空闲 warp 可切。

**第三句，SIMT 的定义与 warp。** 为了同时管理跑着好几套不同程序的几百个线程，SM 采用了 SIMT 架构。它把每个线程映射到一个 SP 核上，每个标量线程**独立执行**，拥有**自己的指令地址和寄存器状态**。SM 的 SIMT 单元把线程组织成一批批并行线程来创建、管理和调度，这一批就叫 **warp**——这个词来自织布（weaving），人类最早的一门「并行线程」技术。同一个 warp 里的线程从**同一个程序地址**同时出发，但之后就各自自由地分支、独立地执行。

**第四句，warp 怎么切。** 一个 block 被切成 warp 的方式是**固定不变**的：每个 warp 装着**连续、递增的 thread ID**，第一个 warp 从 thread 0 开始装。也就是说，warp 不是随便挑的，而是按 thread ID 顺序机械地切分（§3.2 明确了 warp 里是 32 个线程）。

```text
一个 128 线程的 block，被切成 4 个 warp：
  warp 0 = thread  0 ..  31      ← 第一个 warp 从 thread 0 开始
  warp 1 = thread 32 ..  63      ← 连续、递增的 thread ID
  warp 2 = thread 64 ..  95
  warp 3 = thread 96 .. 127
```

**第五句，指令发射与分支分歧。** 每次发射指令时，SIMT 单元挑一个**就绪**的 warp，把它要执行的下一条指令发给这个 warp 里的**活跃线程**。一个 warp 同一时刻只执行**一条公共指令**，所以当 warp 里所有线程的路径一致时效率最高。一旦线程因为**数据依赖的条件分支**走了不同的路（分歧，divergence），warp 就**串行执行每一条被选中的路径**，把不在当前路径上的线程**关掉（disable）**，等所有路径都跑完后，线程再**汇合**回同一条执行路径。注意一个关键限定：**分歧只发生在 warp 内部**；不同的 warp 之间永远独立执行，不管它们跑的是相同还是不同的代码路径。

```text
warp 内 32 个线程遇到 if (v > 0)：

  setp 给每个线程算出一个谓词（有的为真、有的为假）
        │
        ├─ 谓词为真的线程 ──► 执行「真」路径  ┐
        │                                   ├─ 串行执行两条路径
        └─ 谓词为假的线程 ──► 执行「假」路径  ┘
                                          │
                                  最后在汇合点重新聚到同一条路径
```

**第六句，SIMT 与 SIMD 的差别。** SIMT 和 SIMD（单指令多数据）很像——都是一条指令控制多个处理单元。差别在于：SIMD 向量组织把**向量宽度暴露给软件**（程序员要写 `vadd4` 这种显式带宽度的指令、手动管理分歧），而 SIMT 的指令描述的是**单个线程**的执行和分支行为。SIMT 因此既能写「每个线程独立标量执行」的线程级并行代码，也能写「线程协同」的数据并行代码。就正确性而言，程序员**几乎可以无视 SIMT 行为**；但想让性能好，就得让 warp 内尽量少分歧。文档给了个精当的类比：这跟传统代码里**缓存行**的角色一样——为了正确性可以无视缓存行大小，为了峰值性能就必须在代码结构上考虑它。反过来，纯向量架构则要求软件自己把 load 合并成向量、自己管理分歧，这一整套脏活累活在 SIMT 里由硬件接管了。

**第七句，一个 SM 能同时装几个 block。** 这取决于每个线程要多少寄存器、每个 block 要多少共享内存——因为 SM 的寄存器和共享内存要在这一批 block 的所有线程之间**切分**。如果每 SM 的寄存器或共享内存连**一个 block 都装不下**，kernel 会**启动失败**。

## 三、文档语义：§3.2 独立线程调度

§3.2 讲的是 SIMT 这条线在 Volta 架构上的一次重要演进。

**Volta 之前**：warp 里 32 个线程**共用一个程序计数器（PC）**，外加一个标记哪些线程活跃的 active mask。后果是：处于分歧区域、或执行状态不同的同一 warp 线程，**无法互相发信号或交换数据**；那些靠锁或互斥量保护细粒度数据共享的算法，**很容易死锁**——因为「抢锁的线程」和「持锁的线程」可能恰好卡在同一个 warp 的两种状态里，谁也等不到谁。

拿一个具体场景看死锁是怎么发生的：

```text
同一 warp 里的 T0、T1 抢一把互斥锁：
  T0 抢到锁 → 进入临界区 → 等 T1 产生某个条件；
  T1 没抢到锁 → 在锁上自旋 → 等 T0 释放锁。
```

在「单 PC + active mask」的旧模型里，T0 和 T1 没法各自推进：T1 自旋的时候，warp 只能执行「自旋」这一条公共指令流，T0 即使持锁、想往下走，也被一起卡在自旋里出不来。于是 T0 等 T1、T1 等 T0，死锁就此产生——这不是数据竞争，而是调度粒度过粗导致的「谁也动不了」。

**Volta 起**：引入了**独立线程调度（Independent Thread Scheduling）**，让线程之间**完全并发**，不管它们在不在同一个 warp。硬件为**每个线程**单独维护执行状态——包括它自己的 PC 和调用栈——并且能在**单线程粒度**上让出执行，要么为了更充分地利用执行资源，要么让一个线程等另一个线程把数据产出来。一个**调度优化器**负责把同一 warp 里的活跃线程重新编组成 SIMT 单元。这样既保住了过去那种高吞吐的 SIMT 执行方式，又多了灵活性：线程现在能在**子 warp 粒度**上分叉、重汇合。

这一段最后给了一个重要的提醒：如果开发者还抱着旧架构「warp 同步」的假设写代码，独立线程调度会让实际参与执行的线程集合和预期大不一样。任何**依赖 warp 同步的代码**（比如无同步的 intra-warp 归约）都需要重新审视，确保在 Volta 及之后的架构上仍然正确。

所谓「warp 同步代码」，指的是利用「同一 warp 的 32 个线程天然锁步、一条指令同时驱动」这个旧假设、从而**免掉显式同步**的写法。典型的例子是 intra-warp 归约：老式写法里，warp 内相邻线程直接交换数据，靠的就是「大家肯定还在同一步」这个隐含前提，不写任何 `bar.sync`。独立线程调度把这个前提打破了——线程各自有 PC、可以各自让出执行，同一 warp 的线程不再保证锁步。所以这类代码的隐含假设不再成立，要么改成显式同步，要么换用显式说明数据在 warp 内如何流动的机制。

## 四、反汇编与讲解：分歧在 PTX 里的样子

前面都是文字描述，现在用一个真实的内核，看「数据依赖的条件分支」落到 PTX 里长什么样。

CUDA 源码：

```cuda
__device__ __noinline__ int foo(int x) { return x * 2; }
__device__ __noinline__ int bar(int x) { return x + 100; }

__global__ void divergeKernel(int *out, const int *in) {
    int i = threadIdx.x;
    int v = in[i];
    if (v > 0) {
        out[i] = foo(v);
    } else {
        out[i] = bar(v);
    }
}
```

真实 PTX（Compiler Explorer，NVCC 13.3.0，`-arch=sm_90a -ptx -O3`，指令原样贴入，行尾 `//` 注释是我标注的对应 CUDA 源码行）：

```nasm
.visible .func  (.param .b32 func_retval0) foo(int)(
        .param .b32 foo(int)_param_0
)
{
        ld.param.u32    %r1, [foo(int)_param_0];   // 读入参数 x
        shl.b32         %r2, %r1, 1;               // x * 2（乘 2 的幂 = 左移 1 位）
        st.param.b32    [func_retval0+0], %r2;     // 返回 x * 2
        ret;
}
.visible .func  (.param .b32 func_retval0) bar(int)(
        .param .b32 bar(int)_param_0
)
{
        ld.param.u32    %r1, [bar(int)_param_0];   // 读入参数 x
        add.s32         %r2, %r1, 100;             // x + 100
        st.param.b32    [func_retval0+0], %r2;     // 返回 x + 100
        ret;
}
.visible .entry divergeKernel(int*, int const*)(
        .param .u64 divergeKernel(int*, int const*)_param_0,
        .param .u64 divergeKernel(int*, int const*)_param_1
)
{
        ld.param.u64    %rd2, [divergeKernel(int*, int const*)_param_0];   // 读 out 指针（参数 0）
        ld.param.u64    %rd3, [divergeKernel(int*, int const*)_param_1];   // 读 in 指针（参数 1）
        mov.u32         %r5, %tid.x;                // int i = threadIdx.x;
        cvt.s64.s32     %rd1, %r5;                  // i 转 64 位（供地址计算）
        cvta.to.global.u64      %rd4, %rd3;         // in 转 global 地址
        mul.wide.s32    %rd5, %r5, 4;               // i * 4（元素字节大小）
        add.s64         %rd6, %rd4, %rd5;           // 算 in[i] 的字节地址
        ld.global.u32   %r1, [%rd6];                // int v = in[i];
        setp.gt.s32     %p1, %r1, 0;                // v > 0 的结果放进谓词 %p1
        @%p1 bra        $L__BB2_2;                  // 谓词为真的线程 → foo 路径
        bra.uni         $L__BB2_1;                  // 其余线程 → bar 路径

$L__BB2_2:                                          // out[i] = foo(v) 路径
        { // callseq 1, 0
        st.param.b32    [param0+0], %r1;            // 把 v 写入参数槽
        call.uni (retval0),
        foo(int),
        (
        param0
        );
        ld.param.b32    %r6, [retval0+0];           // 取 foo 返回值
        } // callseq 1
        bra.uni         $L__BB2_3;                  // 跳到汇合点

$L__BB2_1:                                          // out[i] = bar(v) 路径
        { // callseq 0, 0
        st.param.b32    [param0+0], %r1;            // 把 v 写入参数槽
        call.uni (retval0),
        bar(int),
        (
        param0
        );
        ld.param.b32    %r6, [retval0+0];           // 取 bar 返回值
        } // callseq 0

$L__BB2_3:                                          // 汇合点
        cvta.to.global.u64      %rd7, %rd2;         // out 转 global 地址
        shl.b64         %rd8, %rd1, 2;              // i * 4（64 位）
        add.s64         %rd9, %rd7, %rd8;           // 算 out[i] 的字节地址
        st.global.u32   [%rd9], %r6;                // out[i] = 返回值
        ret;
}
```

逐行对应关系已标在上面的注释里，这里不再逐条复述，只把三个关键点拎出来讲：

**其一，整段代码没有一条向量指令。** 从 `mov.u32 %r5, %tid.x` 到 `st.global.u32 [%rd9], %r6`，全是 `mul.lo.s32`、`add.s64`、`setp` 这类**标量指令**。这正是 §3.1 第六句说的 SIMT 与 SIMD 的差别：SIMT 的指令描述的是**单个线程**的行为，宽度不写进指令，而是由硬件把同一条标量指令发给 warp 里所有活跃线程来体现。

**其二，分歧的源头是「每线程自己的谓词」。** `setp.gt.s32 %p1, %r1, 0` 把 `v > 0` 的结果放进**每线程各自的**谓词寄存器 `%p1`。对同一个 warp，有的线程 `%p1` 为真、有的为假——条件本身是数据依赖的，每个线程答案不同。

**其三，`@%p1 bra` 与 `bra.uni` 的分工就是分歧机制。** `@%p1 bra $L__BB2_2` 是**谓词化分支**：只有 `%p1` 为真的线程跳去 `foo` 路径，其余线程停在原地；紧接着的 `bra.uni $L__BB2_1`（`.uni` = uniform，全 warp 统一跳转、无需谓词）把剩下的线程送去 `bar` 路径。于是 `$L__BB2_2` 和 `$L__BB2_1` 两个基本块**同时躺在代码里**——这正对应 §3.1 第五句的「warp 串行执行每一条被选中的路径」：硬件先跑 `foo` 路径（此时 `bar` 线程被 disable），再跑 `bar` 路径（此时 `foo` 线程被 disable），最后都通过 `bra.uni $L__BB2_3` 汇到写回点。

需要说明一点：PTX 是 per-thread 的，`@%p1 bra` 只是**声明**了每个线程的分支去向；「串行执行两条路径、关掉另一条路径上的线程」这个动作，是 SIMT 单元在硬件上的调度行为，PTX 代码里看到的表象就是「两条路径都在，谓词决定谁走哪条」。

**对照：编译器常把分歧消掉。** 上面这个例子的分支体是 `noinline` 函数调用，无法被谓词化，所以才保留了真实的分支。如果把分支体换成「两条路径都只是算一个值」，nvcc 前端会直接把它谓词化成一条 select，根本不分叉。比如：

```cuda
__global__ void branchKernel(int *out) {
    int i = threadIdx.x;
    if (i & 1) {
        out[i] = i * 10;
    } else {
        out[i] = i * 100;
    }
}
```

真实 PTX（NVCC 13.3.0，`-arch=sm_90a -ptx -O3`，指令原样贴入、略去头部，行尾 `//` 为标注）：

```nasm
        mov.u32         %r1, %tid.x;                // int i = threadIdx.x;
        and.b32         %r2, %r1, 1;                // i & 1（取最低位，判奇偶）
        setp.eq.b32     %p1, %r2, 1;                // (i & 1) == 1 → 谓词 %p1
        selp.b32        %r3, 10, 100, %p1;          // %p1 真选 10，假选 100
        mul.lo.s32      %r4, %r3, %r1;              // i * (10 或 100)
        mul.wide.s32    %rd3, %r1, 4;               // i * 4（字节偏移）
        add.s64         %rd4, %rd2, %rd3;           // 算 out[i] 的字节地址
        st.global.u32   [%rd4], %r4;                // out[i] = 结果
        ret;
```

`and.b32` 只是普通的按位与（`i & 1` 取最低位判奇偶，不是「编译器识别出 warp」这类说法）。关键是 `setp` + `selp` 这对组合：比较出每线程谓词后，`selp`（select with predicate）让 `%p1` 为真的线程选 10、为假的线程选 100——**一条指令同时给出 warp 里每个线程各自的结果**，没有任何 `bra`、没有任何串行化。

对比这两个内核就清楚了：SIMT 鼓励的正是「让编译器能把分歧谓词化」的写法。分支体越简单、越能被折叠成一个 select，warp 就越不必真正分叉，也就越接近 §3.1 说的「所有线程路径一致」的最高效状态。反之，一旦分支体里有函数调用、循环、屏障这类无法谓词化的东西，分歧才现形为 `@p bra`。

## 小结

- GPU 执行核心是**可扩展的 SM 阵列**；block 是调度单位，被动态分发给有空闲容量的 SM，一个 block 的所有线程在同**一个** SM 上并发执行。
- 每个 SM = 多个 **SP 核** + 多线程指令单元 + 片上共享内存，硬件调度线程**零开销**。
- **SIMT**：每个线程映射到一个 SP 核，独立持有指令地址和寄存器状态；SIMT 单元把 block 按连续 thread ID 切成 **warp**（32 线程），一个 warp 同一时刻执行一条公共指令。
- **分支分歧只在 warp 内**：数据依赖的条件分支会让 warp 串行执行各路径、关掉不在路径上的线程，最后汇合；不同 warp 之间永远独立。
- SIMT 与 SIMD 的差别：SIMD 把向量宽度暴露给软件，SIMT 指令描述**单线程**行为；正确性可无视 SIMT，性能才需要考虑少分歧（类比缓存行）。
- 一个 SM 能装几个 block 取决于每线程寄存器 + 每 block 共享内存，装不下会**启动失败**。
- **Volta 起**的独立线程调度：每线程独立 PC 与调用栈，可子 warp 粒度分叉重汇合；依赖旧 warp 同步假设的代码需重审。
- 真实 PTX 里，分歧表现为 `@%p1 bra` + 两个基本块 + 汇合点；简单分支则被谓词化成 `setp` + `selp`，不分叉。
