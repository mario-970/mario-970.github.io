## TL;DR

- **attention 的数值与近似今天最有料**：FA3 在 BF16 下的梯度爆炸被定位到一条**守恒律被破坏**——softmax 分数梯度沿每行求和本应为零，舍入到 BF16 后留下的小非零和把「key 的均值」漏进 query 梯度，训练后期 key 变大、attention 变尖时泄漏被放大；**GProj** 用每行两次 rank-one 修正把零和恢复，query/key 梯度中位误差从 **219% / 13% 压到 0.34% / 0.37%**，代价是每步多 **4.7%** 时间，端到端追平 FP32 attention。另一路是直接**近似 softmax**：B200 上 tensor core 吞吐比 SFU 的 exp 快两个数量级，把分辨率预算放在**行最大值附近**（Rowmax-PoT）后，patch 过的 **FP8 attention 前向在 8K causal 快 12.4%、非 causal 快 25.8%**，代价是 BF16 路径上困惑度涨 0.09–0.49%。
- **稀疏 attention 这两天集中解决「省了算力但没省带宽」的老问题**：**PQ-HSA** 把 IVF-PQ 索引给**未选中 token** 的近似分数通过「按倒排表求和 × 表均值」塞回同一个 softmax，128K / 1–2% 预算下 macro accuracy 从 0.71 提到 **0.83**，vLLM 插件里 decode attention 比 FA3 内核快 **1.6×**；**WaveAlign** 只对 query 行**重排序**（SVD 分组 + 按 K/V 块数降序排 wave），L2 命中率 **28.5–36.4% → 79.4–89.1%**、HBM 读流量最多降 **92.1%**、内核 1.25×，不改任何现有 sparse kernel 语义。
- **量化与选核侧的三个「不需要校准」结果**：**QuantForge** 用 LLM 驱动的程序演化做出 MXFP4 定点量化器 **HiRes**（七任务 Robust Fit 0.09300 最低）；**RAM** 证明 RTN 量化误差**谱平坦**，单个高斯探针就能无校准地估出每张量的敏感度（20 个探针到 1.3–1.4%），再用背包在字节预算下分配位宽；**CUTLASS 选核**用一个 490 万 kernel 的数据集训练 LTR 模型，把候选配置补上**可静态计算的硬件行为估计**，selection regret 相对结构基线最多降 **40%**、相对 NVIDIA matmul 启发式降 **64.2%**。Release Notes 本期只有 CCCL Python 1.2.1，芯片动态无新条目。

## 三、arXiv 论文（算子内核）

- **[Hardware-Aware Features for CUTLASS Kernel Selection](https://arxiv.org/abs/2609.35587)**（`2609.35587`，09-28）：CUTLASS 对单个算子会暴露**上万个语义等价的内核**，穷举 autotune 代价高，而「不执行就选核」很难——解析式选择器依赖手写性能规则，学习式选择器直接吃原始配置参数、得从数据里反推硬件后果。这篇提出的做法是**给候选配置补上一层「静态可算的硬件行为估计」**，把 `Hardware-Aware` 表示喂给 learning-to-rank 模型：作者构造了 **490 万个 CUTLASS kernel** 的数据集，训练 GBDT 与神经网络排序器。在留出的**穷举评测问题**上，硬件感知表示把 selection regret 相对结构基线**最多降 40%**、相对 **NVIDIA 的 matrix-multiply 启发式降 64.2%**；跨精度（cross-precision）与 epilogue 融合的迁移实验显示，显式表示「候选引发的硬件行为」在 CUTLASS GEMM 内部是一个有用的归纳偏置。对算子库而言，这提供了一条**免实测的选核**路线，且特征是可静态计算的，不依赖 profiler。

- **[Broken Symmetry in BF16 Attention: Why FlashAttention Gradients Blow Up Late in Training](https://arxiv.org/abs/2609.34272)**（`2609.34272`，09-28）：用 **FlashAttention-3** 在 50B token 上预训练 450M transformer，前 25B token 一切正常，随后**梯度范数涨了三个数量级**、loss 比 FP32 attention 高 **0.2 nats**，全程**没有一个 NaN**；只把**两层的 attention backward 换成 FP32 重算**就消掉了几乎全部超额梯度。已知的那部分原因是前向 softmax 里的一个 **fused multiply-add**（此前只被当作极端输入的 NaN 场景，FA3 一直没修），修掉它能止住爆炸，但 **query 梯度仍然错得比它本身还大**。剩下的误差来自一条**被破坏的守恒律**：softmax 的分数梯度沿每一行求和应为零，这使 query 梯度对「key 作为一个整体落在哪里」不敏感；把它舍入成 BF16 后留下的小非零和会把 **key 的均值泄漏进梯度**，而泄漏量恰好随训练后期 key 变大、attention 变尖而放大。作者给出 **GProj（gauge projection）**：在 cast 之后用**每行两次 rank-one 修正**把零和恢复，把剩余的中位 query/key 梯度误差从 **219% / 13% 降到 0.34% / 0.37%**，与 FP32 attention 持平，代价是**每步训练多 4.7% 时间**；匹配条件下的从零训练能收敛到与 FP32 attention 相同的 loss，而 FA3 与 key smoothing 都会失稳。对写 fused attention 内核的人，这是一条「**attention 反向的数值约定**」级别的结论，而不只是调参。

- **[WaveAlign: Cache-Aware Query-Row Scheduling for Sparse Attention in Long-Video Generation](https://arxiv.org/abs/2609.34814)**（`2609.34814`，09-28）：长视频生成让 DiT 的序列极长，attention 是主要瓶颈；**动态稀疏 attention 省了计算量，实际加速却很有限**，原因是**不规则的 query 行执行方式打坏了 L2 局部性、推高 HBM 流量**。WaveAlign 把 **query 行重排序**写成一个优化问题、分两步近似：第一步对稀疏 mask 的行做 **低秩 SVD**，把 K/V 访问模式相近的 query 行分到一组，提高**同时调度行之间的 K/V 重叠**；第二步利用 GPU 的流式调度，把每个 **wave 内的行按 K/V 块数降序排列**，让当前 wave 的短行后面紧接下一个 wave 的长行，从而**跨 wave 边界对齐 K/V 访问**，共享块在被换出前先被复用；另有一个**自适应 skip 模块**丢掉不划算的重排。它只做 query/mask 的**行置换**，因此**保持稀疏 attention 语义不变、不需要改任何现有方法或后端 kernel**。跨两种 GPU、两个视频 DiT、四种稀疏 attention 方法：L2 命中率从 **28.48–36.35% 提到 79.38–89.06%**，HBM 读流量**最多降 92.11%**，内核最多 **1.25×**、端到端最多 **1.17×** 加速且画质无损。这是个典型的「**内核不动、调度层拿收益**」的工作。

- **[QuantForge: Discovering Residual Decompositions for MXFP4 Post-Training Quantization](https://arxiv.org/abs/2609.34680)**（`2609.34680`，09-28）：严格 **MXFP4 W4A4** 下要保精度，得同时协调坐标变换、块编码误差与残差传播，而「哪种算法分解是对的」**在搜索之前并不已知**。QuantForge 让 LLM 驱动的程序演化来探索这些选择，但不止看分数：它**记录互相竞争的解释**、挑选能**区分这些解释的控制实验**、并检查后继代码是否真的实现了结论；这种「残差编译」在原始解释被否定时仍能保留有用程序，重测修订后的程序又暴露出下一个要处理的误差。流程最终发现 **HiRes**——一个固定 MXFP4 量化器：先整形坐标、再细化合法码字分配、最后沿 **attention 与 MLP 路径**回收误差，**每一级都作用在前一级执行后才测得的残差上**。结果：七个任务上取得**最低的七模型 Robust Fit（0.09300）**与 **32B 上最低的量化 Fit-7**。在等预算（各 240 次 evaluator 调用）的对比中，QuantForge 在 **8 次运行里有 6 次**达到留出迁移目标，文本记忆与反思记忆各 3 次、纯分数演化只有 1 次，且新评估的程序更少。

- **[AReaL-TIK: Stateful Agentic Optimization of Unified RL Kernels through an Optimization IR](https://arxiv.org/abs/2609.35140)**（`2609.35140`，09-28）：RL 后训练通常**用两套不同的 GPU kernel 分别做 rollout 与 policy update**；同步 PPO / GRPO 下两者的数值不一致会扰动「当前 token 概率 / rollout 时概率」的比值。用 policy-update 后端重算 rollout log-prob 可以消掉这个偏差，但要**多跑一次前向**。若统一内核做到**逐位一致（bitwise-consistent）**，且 policy 快照与概率处理方式匹配目标函数时就能复用；难点在于**优化必须在不破坏这种一致性的前提下跨执行形态成立**。**KernelBraid** 从一个手工调好的逐位一致实现出发，其**优化 IR** 把「实现与改动」同「数值要求、工作负载测量、推导历史」绑定，agent 协调改动并保留已验证的中间版本，**只有通过正确性检查、且在各类工作负载上限内改善总延迟才允许晋级**。H20 上 12 组端到端训练配置：相对带 log-prob 重算的 AReaL **平均 1.10× 吞吐**，平均训练奖励比四舍五入到 **1.00×**；单层 profiling 在 15 个「模型 × GPU」组合上**汇总阶段时间平均 1.40×**；算子级评测覆盖 **A100 / H20 / H200 上的 10 个算子，全部通过规定的逐位检查**；统一 attention 搜索用 7M LLM token 就把汇总工作负载延迟做到起始实现的 **2.52×**。代码已开源。

- **[E3J: An Efficient and Open-Source Backend for Euclidean Equivariant Operations on GPU and TPU](https://arxiv.org/abs/2609.35099)**（`2609.35099`，09-28）：几何深度学习里的**欧氏等变算子**（张量积、消息传递卷积）此前基本被 CUDA 闭源后端把持。**e3j** 用**优化过的 CUDA kernel 加 Pallas kernel**，配合算法改动，在**前向与反向**都做到 SOTA 吞吐与耗时，并提供 **JAX 绑定、同时覆盖 GPU 与 TPU**。在机器学习势（MLIP）用例上，用 MACE 跑 water box NPT 模拟相对 **cuEquivariance 最多快 34%**，且**完全开源**；**张量积算子在 H100 上达到最高显存带宽 80% 以上**的效率，消息传递卷积前向在多数情形下**吞吐翻倍以上**。那个专门的 **Pallas TPU kernel** 让大规模等变训练首次在 TPU 上可行：**TPUv6e 上达到 80% 以上带宽，比 e3nn-jax 高最多一个数量级**。以 Apache 2.0 发布在 GitHub / PyPI，属于可直接替换的算子库。

- **[Approximating Softmax in Pretrained LLMs: Model Sensitivity and Kernel Acceleration](https://arxiv.org/abs/2609.33586)**（`2609.33586`，09-27）：在 **Blackwell B200** 上 **tensor core 吞吐比 SFU 的 exp 快两个数量级以上**，于是 fused attention 内核里「求 exp」这一步成了暴露出来的瓶颈。问题是预训练模型到底在哪一步需要多准。作者在 **十个冻结的 decoder-only 模型（0.5B–72B）**上做推理期 softmax 近似，发现：**softmax 分配概率的位置数和行内分辨率都可以大幅削减**，但**把同样多的位置改成均匀权重会明显掉点**；并且**固定分辨率预算放在哪里同样重要，靠进行最大值的位置始终更优**；把扰动在「标量失真」上对齐后，不同模型会给出**符号相反**的响应。据此提出 **Rowmax-PoT**——一种以**每行最大值**为锚点的**粗粒度对数权重表示**，以及它在 **FlashAttention-4** 中的硬件特化 **Rowmax-H15**：B200 上 patch 后的 **FP8 attention 前向在 causal 8K 时 host 侧调用延迟快 12.4%、非 causal 8K 快 25.8%**，causal 16K 时**单次前向的板级能耗降 8.4%**；在 **BF16 内核路径 2K** 上单独测量，Rowmax-H15 使五个模型（来自三个家族）的困惑度上升 **0.091–0.492%**。这是「**用近似换 SFU 瓶颈**」的完整闭环：敏感度刻画 + 表示设计 + 内核落地。

- **[PQ-HSA: Reusing Product-Quantized Scores for Hybrid Sparse-Approximate Attention](https://arxiv.org/abs/2609.33746)**（`2609.33746`，09-27）：长上下文解码时 attention 受显存带宽限制，稀疏 attention 只读一部分 key，**多数方法给未读 token 直接记零权重**，于是输出只依赖 KV cache 的一小部分，预算小的时候精度掉得厉害——尤其是**需要跨上下文聚合信息**的任务。PQ-HSA 的做法是：先用建在缓存 key 上的 **IVF-PQ（倒排文件 + 乘积量化）索引**为每个被索引 token 算出近似分数以便排序，而**排序后这些分数恰好近似了被丢弃 token 的 attention logit**；然后 hybrid 地处理——**被选中的 token 用原始 K/V 参与 attention**，**未选中的「背景」则通过这些分数进入同一个 softmax**，按**倒排表求和**并乘以该表的**均值 value**。在 128K、**1–2% 检索预算**下，它在 Llama-3.1-8B 与 Qwen3-30B-A3B 上比 Quest、SnapKV 更准，macro accuracy 接近全 attention；同一个选择器下，**背景项把 8B 的 macro accuracy 从 0.71 提到 0.83**。工程上：在**单张 NVIDIA H20 的 vLLM 内**，decode attention 调用比 **FlashAttention-3 内核快 1.6×**，且加速随上下文长度增长（作者用 8B–30B 拟合了成本模型给出起效的上下文长度）；**vLLM 插件在两个引擎版本上运行、无需改引擎源码**。代码已开源。

- **[Where Activation Sparsity and KV-Cache Sparsity Cross in LLM Decoding](https://arxiv.org/abs/2609.33889)**（`2609.33889`，09-27）：单序列解码每一步都要重读**投影权重（流量固定）**与 **KV cache（流量随上下文增长）**；**激活稀疏削前者的流量、KV 稀疏削后者**，但两者报出的加速比很难比较，因为各自都依赖上下文长度和所对标的 dense attention 内核。这篇先推导出一个 **byte crossover**——两条支路节省量相等的上下文长度，连同各自及二者组合的**理想加速上界**，且只需模型维度与 keep ratio 即可算出；随后在**真实文本 dense prefill 之后**，在两张 GPU 上从 **2K 到 128K** token 实测两条支路及其组合，dense 与 sparse 模式**走同一个 split-K attention 内核**读 cache。实测：**短上下文投影支路领先、长上下文 KV 支路领先**，加速比在扣除固定内核开销前贴合字节上界；把单独扫出来的固定开销加进去后，字节账本能在 **4.1K token 以内**预测出三组 keep ratio、第二个模型、第二张 GPU 的实测交叉点。两个可直接踩到的坑：把 dense 基线换成 **masked attention 而非 split-K 来计时，会让同一个 KV 策略的表观加速比虚高约 5×**；而在 KV 选择策略上，**attention 打分的 KV 选择在 127K 内仍能答对 passkey 与 multi-key 排布，KV 窗口则大面积漏掉**。在匹配困惑度预算下，激活稀疏与该选择组合比任一单支路**解码快 14–26%**。代码在 `github.com/js-lee-AI/ByteCross`。

- **[Quantization Error Is Spectrally Flat: A Single Random Probe Is a Calibrated, Data-Free Sensitivity Estimator](https://arxiv.org/abs/2609.33923)**（`2609.33923`，09-27）：单个**随机高斯探针**就能给出某层**量化误差平方 Frobenius 范数的无偏估计**，而它之所以好用，是因为 **round-to-nearest 误差在谱上是平坦的**。作者在来自 **35B MoE 与 9B dense** 的 **1683 个张量**上验证：有效维度是同形状 i.i.d. 噪声值的 **0.93–0.96 倍**，MoE 上这个中位数**从 2-bit 到 8-bit 不变**；探针的变异系数可由张量形状预测——**单个探针把每张量敏感度测到 4–7% 以内，20 个探针到 1.3–1.4%**。**RAM** 把该估计量的**传播形式**用于**面向预算的混合精度量化，完全不需要校准数据**：携带网络自身输入统计的高斯探针在**六个位宽**上给每个张量打分，再用**背包求解器在精确字节预算下分配位宽**，并加了防止灾难性 2-bit 赋值的保护；**一次探针扫描可服务任意预算**。两个反直觉结论：在 Qwen3.5-35B-A3B 上**孤立分数与传播分数对张量的排序相互独立（Spearman −0.01）**，但**传播探针与真实激活下 GPTQ 的分层目标 rank 相关 0.81–0.83**，而孤立估计量与之无关；而且**那个目标本身就是错的分配目标**——在 Qwen3.8-27B 上等字节比较，**block-output 探针胜过厂商 IQ3_M 混合与一个按真实激活目标分配的 oracle**，Qwen3-8B 上则与 HAWQ-V2 打平。跨 7 个架构（8B–122B）、对 400B 模型单机 **9 分钟**完成探针计时，在测试的 MoE 模型上比同尺寸均匀 4-bit 方案的中位 WikiText-2 困惑度低 **3.5–13.6%**。
