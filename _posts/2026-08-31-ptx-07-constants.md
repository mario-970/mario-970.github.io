> 本文是 [PTX 专栏](/ptx/) 第 7 期，对应官方文档 §4.5–4.5.3。

## TL;DR

PTX 的常量分三种：**整数**、**浮点**、**谓词**。整数常量一律是 64 位，类型只有 `.s64` 或 `.u64`，字面量支持十进制、十六进制、八进制、二进制四种写法，加 `U` 后缀强制无符号；浮点常量一律是 64 位双精度、**没有** C 的 `f` 后缀，但提供一种 C 没有的写法——`0F3FC00000` 这样的十六进制位模式，直接指定精确的 IEEE 754 位；谓词常量就是整数常量，按 C 规则 0 为 False、非 0 为 True。

## 一、概念铺垫：常量是「带类型的字面量」

上一期讲了 PTX 的语句和标识符怎么组织，这一期讲语句里最细的一类零件——**常量**。常量是直接写在源码里的字面值，比如 `42`、`1.5`，它既可以用来做数据初始化，也可以直接做指令的操作数（比如 `add.s32 %r2, %r1, 100` 里的 `100`）。

常量的关键不在「写个数字」，而在「这个数字是什么类型」。同样一个 `42`，是 32 位还是 64 位、有符号还是无符号，直接决定它在 `div`、比较这类「行为依赖类型」的运算里怎么算。所以 §4.5 通篇都在回答一个问题：**一个常量字面量，它的类型到底是什么、由什么决定**。弄懂这一点，才不会被后面指令集里那些「同一个数字、不同后缀」的写法绕晕。

## 二、文档语义：三种常量

### §4.5.1 整数常量：都是 64 位，四种进制

整数常量有两条硬规矩。**其一，一律 64 位，类型只有 `.s64` 或 `.u64`。** 这点最反直觉：在 PTX 里写 `42`，它的类型不是 32 位 `int`，而是 64 位的 `.s64`。真正的「大小」是在使用时才决定的——每个整数常量在使用处，按所在指令或数据初始化声明的类型，转换到合适的大小。所以 `add.s32 %r2, %r1, 100` 里那个 `100`，是 `.s64` 常量被截到 32 位当作立即数。

**其二，字面量支持四种进制，语法沿用 C。** 先看图：

```text
同一个整数 42，四种进制写法（§4.5.1）：
  十进制      42
  十六进制    0x2A
  八进制      052
  二进制      0b101010
  无符号后缀  42U          ← 紧跟 U，强制为 .u64
```

对应文档给的四条正则：十六进制 `0[xX]{hexdigit}+U?`、八进制 `0{octal digit}+U?`、二进制 `0[bB]{bit}+U?`、十进制 `{nonzero-digit}{digit}*U?`。注意十进制不能以 `0` 开头（那是八进制的 `0`），这也是 C 的老规矩。`U` 后缀可以紧跟在任何进制的字面量后面，把它标记成无符号。

那么一个整数字面量到底是 `.s64` 还是 `.u64`？文档的规则是：**字面量本身非负，默认是 `.s64`；只有两种情况变 `.u64`——值大到放不进 `.s64`（超过 2⁶³−1），或者显式写了 `U` 后缀**。所以 `42`、`0x1234`、`0123` 都是 `.s64`；而 `0xfabc123400000000`（高位超了）、`42U`、`0x1234U` 都是 `.u64`。这个「有符号/无符号」不是随便标的，它决定常量在除法、有序比较这类运算里的行为——那是下一期常量表达式的主题。

文档在末尾还提了一个预定义整数常量 **`WARP_SZ`**：它表示目标平台每个 warp 的线程数，迄今所有架构都是 32。它和上一期 §4.4 表格里的 `%tid` 一样，是语言自带的量，用户不能重定义。

### §4.5.2 浮点常量：双精度、无后缀，另有十六进制位模式

浮点常量也有两条规矩，第一条和整数对称，第二条是 PTX 特有的杀招。

**其一，一律 64 位双精度，且没有后缀。** 浮点字面量可以写「可选小数点 + 可选带符号指数」，但和 C/C++ 最大的不同是：**没有后缀字母来指定大小**，字面量永远是 64 位双精度。也就是说 PTX 里没有 `1.5f` 这种「float 后缀」，你写 `1.5` 它就是 `.f64`。和整数一样，真正的精度在使用处按指令类型转换——`mov.f32` 要它，就截成单精度。

**其二，十六进制位模式——精确指定机器表示。** 这是 C 没有、PTX 独有的写法，用来「我要的正是这一个位模式」的场景。先看图：

```text
同一个浮点值 1.5，两种写法（§4.5.2）：
  十进制浮点       1.5           ← 64 位双精度，无后缀
  十六进制位模式   0F3FC00000    ← 精确的单精度 IEEE 754 位模式（8 个十六进制数字）
  十六进制位模式   0D3FF8000000000000  ← 精确的双精度 IEEE 754 位模式（16 个十六进制数字）
```

规则是：`0f` 或 `0F` 开头、后跟 8 个十六进制数字，是**单精度**浮点；`0d` 或 `0D` 开头、后跟 16 个十六进制数字，是**双精度**浮点。文档给的例子是 `mov.f32 $f3, 0F3f800000;`，注释写着「1.0」——因为 `0x3F800000` 正是 1.0f 的 IEEE 754 位模式。

为什么要这种写法？因为浮点十进制字面量在转换时可能引入舍入，而「精确位模式」能保证你拿到**恰好**那个二进制值——比如要表示一个特定的 NaN、无穷大，或者一个经过精确舍入的常量，写十进制会「失真」，写位模式就不会。注意文档的一句限定：这种 32 位十六进制写法保留的是**精确的单精度值**，不能参与常量表达式（下一期会看到常量表达式的规则）。

### §4.5.3 谓词常量：整数常量按 0/非 0 解释

谓词常量最简单：**整数常量可以直接当谓词用**。对谓词类型的数据初始化和指令操作数，整数常量按 C 的规则解释——**0 就是 False，非 0 就是 True**。

这和第 4 期讲过的谓词机制连起来看：谓词寄存器 `%p` 存的本来就是「真/假」二值，而整数常量要填进谓词位置时，就用「是否为 0」来折算。所以 `@0` 表示永不执行，`@1` 表示无条件执行，`@42` 也是无条件执行——因为 42 非 0。

## 三、反汇编与讲解：常量的真身是「位模式」

常量是语法规则，最好用真实反汇编看它在 PTX 里最终长什么样。下面两段都来自 Compiler Explorer（NVCC 13.3.0，`-arch=sm_90a -ptx -O3`）。

先看一个直接存常量的内核，它同时踩到整数常量和浮点常量：

```cuda
__global__ void constKernel(int *out, float *fout) {
    int i = threadIdx.x;
    out[i] = 42;      // 整数常量
    fout[i] = 1.5f;   // 浮点常量
}
```

真实 PTX（指令原样贴入，略去参数与地址计算的铺垫行）：

```nasm
        mov.u32         %r2, 42;            // 整数常量 42，直接作立即数
        st.global.u32   [%rd6], %r2;        // out[i] = 42
        mov.u32         %r3, 1069547520;    // 1.5f 的位模式，写成十进制整数
        st.global.u32   [%rd7], %r3;        // fout[i] = 1.5f
```

这里有两个值得盯的点。`mov.u32 %r2, 42` 里的 `42` 是整数常量作立即数——它本来是 `.s64`，在 `mov.u32` 的使用处被转成了 32 位。更有意思的是下面那行：`1.5f` 没有变成 `mov.f32 ... 1.5`，而是变成了 `mov.u32 %r3, 1069547520`。为什么？因为 `fout[i] = 1.5f` 本质是「往内存写 32 位的位模式」，编译器直接算出 1.5f 的 IEEE 754 位模式——`1069547520` 就是 `0x3FC00000` 的十进制写法——然后用 `mov.u32` 按位搬进去，连浮点寄存器都省了。这印证了一件事：**浮点常量的真身是一个位模式**，十进制写法只是它的「马甲」。

再换一个让浮点常量真正参与运算的内核，看它用哪种写法：

```cuda
__global__ void constKernel(float *out) {
    out[threadIdx.x] = threadIdx.x * 1.5f + 0.5f;
}
```

真实 PTX（指令原样贴入）：

```nasm
        cvt.rn.f32.u32  %f1, %r1;                           // threadIdx.x 转成 float
        fma.rn.f32      %f2, %f1, 0f3FC00000, 0f3F000000;  // %f1 * 1.5 + 0.5
        st.global.f32   [%rd4], %f2;                       // out[i] = 结果
```

这一次，`1.5f` 和 `0.5f` 以文档 §4.5.2 说的那种**十六进制位模式**现身了：`0f3FC00000` 是 1.5f，`0f3F000000` 是 0.5f，都精确对应各自的 IEEE 754 单精度位模式。`fma.rn.f32` 是融合乘加（`d = a*b+c`），整条指令读作「`%f1` 乘 1.5 再加 0.5」。

把两段放到一起，就是一个完整的对照：同一个 `1.5f`，当它只是被「存」时，编译器用十进制整数 `1069547520` 表示它的位模式；当它参与「算」时，编译器用十六进制浮点字面 `0f3FC00000` 表示同一个位模式。**两种写法、一个位模式**——这正是 §4.5.2 的核心：十六进制写法存在的意义，就是让你能直接、精确地写到位模式本身。

## 小结

- 常量三种：整数（`.s64`/`.u64`）、浮点（`.f64`）、谓词（整数常量折算）。
- 整数常量一律 64 位，支持十/十六/八/二进制四种写法 + `U` 后缀；默认 `.s64`，放不进 `.s64` 或写 `U` 才变 `.u64`。
- 浮点常量一律 64 位双精度、无 `f` 后缀；另有 `0F`（8 位十六进制，单精度）和 `0D`（16 位十六进制，双精度）精确位模式写法。
- 谓词常量：整数常量按 0 = False、非 0 = True 解释。
- 预定义常量 `WARP_SZ` = 32。
- 真实反汇编：`42` 作立即数；`1.5f` 存时写成位模式整数 `1069547520`（=0x3FC00000）、算时写成十六进制浮点 `0f3FC00000`——同一位模式的两种写法。
