## TL;DR

- **通信与权重同步这期给出了两条「省资源」的硬结论**：**T-CCL** 把 collective 的数据搬运与归约**都卸载给 TMA**、每个 collective 变成一串流水化的异步 TMA 操作，于是 AllReduce/AllGather/ReduceScatter 在资源不受限时比 NCCL 快至 **2.4×**、资源受限时 **3.42×**，而 **SM 占用相同或更少**——收益直接体现在 overlap 上：GEMM-通信重叠案例里算子级加速从 NCCL 的 **1.12× 提到 1.25×**（两卡）/ **1.04× → 1.14×**（四卡），接进 vLLM 当通信后端端到端吞吐最高 **1.31×**；**NeMo-DCR** 则把「bit-exact」当成用稀疏性的前提——BF16 训练实测**每步只有约 1% 的权重改变存储值**，只传这些变化却保证接收端得到**与 dense refit 逐位相同**的参数与 buffer，1T 模型跨 region 的 refit 从 **87.5 分钟压到 150 秒**（3% 变化率，中继树），30B–1T 上比「只传输运的全量」快 **12–40×**。
- **低位宽这期的主线是「精度与硬件单元对齐」以及「免校准」**。**SSR** 指出三元权重 LLM 天然带 **50–90% 稀疏**，而 BitNet/RSR/RSR++ 这些三元方法不利用稀疏、通用稀疏格式又忽略三元特性，于是做了一套专用三元格式 + **随稀疏度伸缩的计算树**，三元 GEMM 在 45–95% 稀疏度下比 RSR++ 快 **2.1–11.3×**、Llama-3 1B 端到端 **3.5–6.3×**；**AlignQuant** 把 **GPU 友好的二维权重 tile** 当作精度分配、紧凑存储与执行的**共同单位**（每 tile 存一种表示，相位专用 kernel 复用同一份打包模型、把低位权重展开成 INT8 计算），3B–14B 四个模型上相对 BF16 最高 **2.50×** 生成加速、上下文到 64K。免校准一线上，**ApexQuant** 证明**新的随机旋转把残差送回超球面均匀分布**，于是能在读权重前算出某层需要几趟递归重量化、且**每个前缀都是合法的更低码率模型**；**SoloQ** 用结构化 **K-RPBH 旋转**得到可预测的边缘分布，把扩散 LM 的 W4A4 做成数据无关，并对块扩散模型加了 **commit-time KV-cache 量化**（只压已提交的持久状态），NVFP4 下峰值显存降 **2.61×**、端到端 **2.24×**；**TRACE** 则在 RL 侧把**训练与 rollout 两条 FP4 路径的舍入对齐**（用 rollout 侧结果指导训练侧舍入），另加选择性保留深层 mantissa/scale 的量化信息缓存，rollout 最高 **5.4×** 加速且 RL 表现与 BF16 rollout 相当。**ActTune** 把「层间精度分配」与「GPU 频点/功耗上限选择」接成同一个决策（共享常驻量化权重库让切换不必重排权重），相对 BF16 实现推理最快 **2.02×**、**每次成功任务能耗降最多 76.8%**。
- **注意力侧的看点是把「非规则」换成「结构性」**：**BASA** 用**跨 DiT 块的结构化窗口平移**让被窗口边界分开的 token 在后续层通信，从而**不引入任何不规则算子或自定义 kernel**、直接跑现有 attention 后端，实测加速达到理论估计的 **90% 以上**（FLUX）、Wan 上注意力 **4.52×**；**PHBA** 把精确注意力从固定滑窗换成 **top-k 块稀疏检索**，并给每个命中块配一个**块边界上由门控线性递推构造的 prefix state**，Triton 实现流式处理路由块与前缀状态、不物化中间张量；**CNet** 则给出一个可搬的 **O(N log N) 因果 DFT mixer**（三角掩码 DFT 走 Bluestein/chirp-z 分解）。最后一条来自部署侧：**《Lost in the bf16 Cast》**审计三家三元 LM 的导出管线，发现文档化的 **bf16 cast 会把整数码静默改写**（不一致率 0.83–1.77%，BitNet 2B-4T 为 1.530%），在按 lr/ULP 匹配的微调终点上把 Falcon-E-1B-Base 的贪心 GSM8K 严格准确率从 **58.79% 打到 0.78%**——**量化码本身是待持久化的量**。

## 三、arXiv 论文（算子内核）

**多卡通信与权重同步**

- **[T-CCL: Resource Efficient and Performant Collective Communication using Tensor Memory Accelerator](https://arxiv.org/abs/2610.07098)**（`2610.07098`）：集合通信库通常靠**堆 GPU 线程**换带宽/时延，代价是**巨大的 SM 侧资源占用**——而通信与计算并发时，这部分占用恰恰是从计算手里抢的。T-CCL 换了一条路：把**数据搬运与归约都卸载给 TMA**（Tensor Memory Accelerator），每个 collective 表示成**一串流水化的异步 TMA 操作**，在保住带宽的同时压低 SM 足迹。AllReduce / AllGather / ReduceScatter 上比 NCCL 快至 **2.4×**（通信资源不受限）、**3.42×**（资源受限），与 NCCL 近期的 symmetric-memory kernel 有竞争力，且实测 profile 中占用的 SM **相同或更少**。最能说明问题的是 GEMM-通信重叠案例：把通信后端从 NCCL 换成 T-CCL，**算子级相对串行基线的平均加速从 1.12× 升到 1.25×（两卡）、1.04× 升到 1.14×（四卡）**——省下的 SM 直接还给了重叠执行的 GEMM；接进 vLLM 作为通信后端，端到端吞吐比 vLLM 的自动后端派发最高 **1.31×**，在会话型与 decode 型两类负载、每个评测 batch size 上都领先。对算子组：这篇的价值是**把 collectives 的 SM 足迹当成一等指标**——在同一块 GPU 上跑 kernel 的人应该按「通信占了多少 SM」而不是只看通信带宽来验收通信库。

- **[NeMo-DCR: Bit-Exact Delta-Compressed Refit for Scalable Agentic RL at Trillion-Parameter Scale](https://arxiv.org/abs/2610.08430)**（`2610.08430`）：agentic RL 把训练与 rollout 拆分部署，于是每次策略更新都要先抵达 rollout 集群；一次 1T checkpoint 在**两个 AWS region 之间全量传输要 87.5 分钟**。作者先量了一件事：**BF16 训练中每步只有约 1% 的权重改变其存储值**。利用这个稀疏性的既有系统各有缺陷——重实现放置规则、拼装完整张量、算术重建数值、或用跨集群 collective，且**没有一个能从 refit 中途失败中完整恢复**。NeMo-DCR 只传变化，却做到 **bit-exact**：接收端拿到的参数与 buffer 位**与 dense refit 完全相同**。做法上，放置靠**固定仿射映射**把变化从训练分片投影到 checkpoint 的**规范坐标**、残余变化走转换兜底、再由**服务运行时的原生 loader** 落位；精确性靠**可压缩的 XOR 掩码**承载仿射类变化（投影与 loader 都保持存储位）、**覆写**承载其余变化；两者**就地应用**，重试直接覆盖半写状态，`joint commit` 把策略与基线绑定以供下一个 delta 对齐；效率靠 object storage 或**中继树**在 delta 构造期间流式传输，全程不用跨集群 collective。结果：即便变化率升到 3%/5%，30B–1T 模型的 refit 也比「只做传输的全量 checkpoint」参照快 **12–40×**；1T 中继树 refit 在 3% 变化率下用 **150 秒**替代 87.5 分钟。对算子组：**bit-exact 是使能条件而非副产物**——正因为逐位可比，才能安全地把「1% 变化」当成可传输的稀疏结构，这和 10-06 期 TurboPairFormer 用有序归约换逐位可复现是同一类约束在系统层的投影。

**低位宽格式与量化 kernel**

- **[SSR: Sparse Segment Reduction for Ternary GEMM Acceleration](https://arxiv.org/abs/2610.08403)**（`2610.08403`）：三元 LLM 通过权重三元化拿到大幅压缩，**且常伴随 50–90% 的稀疏**；但现状是两头不落地——三元专用方法（BitNet、RSR 及其改进 RSR++）**不利用稀疏结构**，而通用稀疏格式**又忽略三元特性**，双重优化机会被浪费。SSR 让两者在同一套机制里合流：一个**专用三元数据格式**，加上**随稀疏度伸缩的计算树**（segment reduction 的稀疏化版本），系统性地吃掉稀疏模式。理论上稀疏度 **>50%** 时其渐进复杂度就优于 RSR++，实测则在**所有**稀疏度上都更快：三元 GEMM 在 **45–95% 稀疏度下比 RSR++ 快 2.1–11.3×**；Llama-3 1B 推理端到端 **3.5–6.3×**、内存比 RSR++ 省 **4.9%**。对算子组：结论是「**值域只有 3 个**」与「**高结构化稀疏**」应当**合并进同一个数据格式与计算树**，分开处理就必然在某一侧吃亏——这正是既有方法各自漏掉一半的原因。

- **[AlignQuant: Tile-Aligned Mixed-Precision Quantization for Efficient LLM Generation](https://arxiv.org/abs/2610.07457)**（`2610.07457`）：细粒度混合精度的承诺很直白，但**局部的精度选择会与 GPU 规整的存储与计算单元冲突**——精度边界不落在硬件 tile 边界上，压缩就换不成加速（precision-boundary mismatch）。AlignQuant 的对策是让**GPU 友好的二维权重 tile 同时充当精度分配、紧凑存储与执行三者的共同单位**：精度因此能沿输出通道跟随敏感度；校准上联合 prefill 与 decode，用**量化激活下按语言模型 loss 梯度加权的投影输出扰动**给精度打分，相位归一化后在**全局权重存储预算**下把高精度分配给对任一相位重要的 tile；执行侧每个 tile 只存**一种**选定表示，**相位专用 kernel 复用同一份打包模型**、把低位权重**展开成 INT8 计算**（激活 8-bit）。四个 3B–14B 模型上相对 BF16 最高 **2.50×** 生成加速且保住质量，评测覆盖三块 GPU、上下文到 **64K**。代码在 `github.com/HanzhiZhang-Ulrica/AlignQuant`。对算子组：这是「**混合精度要拿到实测加速，粒度就得锚在硬件 tile 上**」的一个完整样本，代价是每个相位一套 kernel——精度分配单位 = 存储单位 = 执行单位，三者错位就没有收益。

- **[ApexQuant: Data-Free Elastic Quantization by Residual Re-Isotropization](https://arxiv.org/abs/2610.07904)**（`2610.07904`）：又一条**免校准 + 一份产物多档精度**的路线，但机制与前几期不同：它**递归地重新量化残差**，作为已有量化器之上的精化层。理论结论是关键——**一次新的随机旋转会把每个残差送回超球面上的均匀分布**，由此可以刻画**逐趟误差的衰减速率**，于是**在读入任何权重之前**就能算出某层达到目标权重空间误差需要几趟；又因为每一趟的输出都更细，**每个前缀本身就是合法的更低码率模型**（一份产物服务多个精度档）。实现上给了三个可互换的阶段：scalar、**E8**、**trellis**。验证覆盖四个开源 LLM，以及**地球观测与医学**这类拿不到同分布数据的域（影像按限制性许可到达、或受患者隐私约束）；4-bit 下与全精度相差在几个百分点内，2-bit 上给出所测**最好的那一支**，且**完全 data-free**。对算子组：与 10-06 期 StagQ 是同一诉求（多精度共享一份码流）的不同机制——StagQ 用细化平面，ApexQuant 用残差旋转，而后者把「需要几趟」变成**可以在读权重前预算的量**。

- **[SoloQ: Calibration-Free Quantization for Diffusion Language Models](https://arxiv.org/abs/2610.07121)**（`2610.07121`）：扩散语言模型（dLLM）做低比特**权重-激活**量化的难点在于**激活分布会随掩码状态与去噪步漂移**，所以既有 PTQ 都依赖校准数据。SoloQ 免校准：把权重与激活映射到**归一化的旋转基**里，其**边缘分布可预测**——结构化 **K-RPBH 旋转**加一个轻量重标定修正即构成数据无关的量化；**可预测的旋转后分布**同时支持**分布匹配码本**与**硬件原生 NVFP4** 两种落点。针对块扩散（block-diffusion）模型，它还加了 **commit-time KV-cache 量化**：只压**已提交的持久状态**，不扰动正在去噪的那一块。评测覆盖全序列 dLLM（LLaDA、Dream）与块扩散 dLLM（Fast-dLLM v2、Nemotron-Labs-Diffusion）：4-bit 下保住精度、在知识与推理密集基准上优于需校准基线；NVFP4 下峰值显存降 **2.61×**、端到端推理加速 **2.24×**。对算子组：**量化的时机**进了 kernel 调度——KV-cache 只在提交点被压缩，等价于把「不可量化窗口」写进了执行图。

- **[TRACE: Rollout-Guided Quantization-Aware Training for FP4 Reinforcement Learning of MoE Language Models](https://arxiv.org/abs/2610.07767)**（`2610.07767`）：RL 后训练的 rollout 生成吃掉大量算力与显存，低位 rollout 是顺理成章的省钱方向；但既有 FP4 RL 方法**分别在训练路径与 rollout 路径上优化量化精度**，并不直接压缩**两条量化执行路径之间的差异**。TRACE 让**rollout 侧的量化结果反过来指导训练侧的 FP4 舍入决策**（train-rollout alignment），直接减小该差异；同时做了**量化信息缓存**——**有选择地保留更深层的 mantissa 与 scale 信息**，把引导机制引入的存储与通信开销压下去。四个大规模 MoE 模型、推理/代码/长程 RL 任务上：FP4 权重/激活 + **FP4 KV-cache rollout** 的 RL 表现与 BF16 rollout 相当，rollout 最高 **5.4×** 加速，且优于「先 BF16 训完再事后 FP4 量化」的路线。对算子组：这是一条容易被忽略的账——**训练与推理各自「最优」的 FP4 舍入不是同一个**，梯度最终吃的是两条路径之间的失配。

- **[ActTune: Action-Aware Precision and GPU Operating-Point Adaptation for Energy-Efficient Vision-Language-Action Inference](https://arxiv.org/abs/2610.08444)**（`2610.08444`）：VLA 策略每次控制都要调一次推理，GPU 能耗因此是任务执行的**经常性成本**；但作者先立了一个正确的指标——**单次推理省能不等于每次成功任务省能**（数值误差会让任务失败、变慢的推理会拖长执行）。其两条观察是：量化敏感度**随动作类别、随层、随权重/激活而变**；而数值精度会**改变工作负载本身**，从而移动有利的 GPU 工作点。ActTune 于是把两件事接成同一个决策：一棵轻量决策树**直接从「配置-动作误差」上学**分裂与叶子处的精度配置，在每次策略调用前选定精度；控制器**预测下一段工作负载**并**异步施加**选定的**频率-功耗上限对**（查表在延迟预算下离线校准）；一个**共享的常驻量化权重库**保证配置切换**不需要权重重构、也不额外跑策略评估**。LIBERO 上相对 SOTA 平均成功率最多 **+2.3%**；相对原始 BF16 实现推理最快 **2.02×**，配合工作点自适应**每次成功任务能耗降最多 76.8%**。对算子组：**精度配置与频点/功耗上限是同一决策的两个维度**，而常驻权重库是这个决策能在线执行的前提——否则每次切换都要重排权重，省下的能耗还不够。

**注意力与 kernel 实现**

- **[PHBA: Prefix-State Hybrid Block Attention](https://arxiv.org/abs/2610.08527)**（`2610.08527`）：混合架构用线性序列模型 + softmax 注意力兼顾长上下文效率与精确检索，但既有设计（如 NHA）把**精确注意力限制在固定的局部窗口**里。PHBA 把滑窗换成 **top-k 块稀疏检索**，并给**每个被检索到的块**配一个**紧凑的 prefix state**——它由**块边界上的门控线性递推**构造、概括该块之前的上下文，于是**在同一层内**既能用精确 token 命中远距离证据、又能用压缩状态携带历史。工程侧配套了 **hardware-aware 的 Triton 实现**：**流式**处理被路由的 token 块与 prefix state，**不物化大的中间张量**。实验显示长上下文与检索表现优于强线性/混合基线，并保住训练与推理效率。对算子组：检索的**单位从 token 变成「块 + 前缀状态」**，需要的是**流式 gather 与聚合**，而不是标准 attention kernel 的一个变体——前缀状态的构造是逐块的递推，天然可以与前一块的计算流水起来。

- **[Backend-Agnostic Sparse Attention for Fast High-Resolution Visual Generation](https://arxiv.org/abs/2610.08772)**（`2610.08772`）：DiT 高分辨率生成的瓶颈是注意力的二次复杂度；分窗口注意力高效但**窗口之间不通信、留下网格状伪影**，细粒度滑窗质量好但**计算不规则**——于是理论复杂度与实际加速之间出现大缺口，且每个硬件后端都得配一套专门 kernel。**BASA** 的做法是把不规则性消掉：用**跨 DiT 块的结构化窗口平移（shifted local-window）**，让**被某一层窗口边界分开的 token 在后续层里相遇**，以此实现全局信息交换、消除窗口伪影；关键是它**不引入额外的不规则算子、也不需要自定义 kernel**，因此可以直接部署在**现有 attention 后端**上。实测：FLUX 上加速达到**理论估计的 90% 以上**，Wan 上注意力 **4.52×**，生成质量有竞争力。对算子组：这是「**把非规则访存换成结构性稀疏 + 层间平移**」的又一例——稀疏注意力要拿到实测加速，通常不是靠更聪明的 kernel，而是先**让访存模式规整到既有 kernel 能吃**。

- **[CNet: A Complex-Valued Deep Learning Framework with Wirtinger Autodifferentiation and FFT--Hadamard Convolution](https://arxiv.org/abs/2610.08592)**（`2610.08592`）：C++/CUDA 的**复数神经网络**框架，用 **Wirtinger（CR-微积分）导数**做梯度下降——网络是一串作用在幅度向量上的**复数、常常还是酉（DFT）**的操作，分类是 Born 规则测量 $p_k = |z_k|^2/\|z\|^2$ 而非实 logits 上的 softmax。工程纪律值得注意：**每一层都同时提供 CPU 参考实现与 CUDA kernel，并对有限差分校验**，计算图按 batch 克隆以适配 GPU。基元之上，它把恒等式 $\mathrm{conv}(x,k) = \mathrm{IFFT}(\mathrm{FFT}(x)\cdot\mathrm{FFT}(k))$ 变成**可学习的复数卷积网络**，并新增一个 **$O(N\log N)$ 的因果 Fourier mixer**——**三角掩码 DFT 用 Bluestein / chirp-z 分解求值**；另配真 Adam 与降内存推理模式。三个研究里第一个是复数版 FNet 式因果序列模型：调好之后在字符级语言模型上**追平或超过参数对齐的实值因果 FNet，且用不到一半的训练步数达到其收敛质量**；另两个是无线调制分类（RML2016.10a）与相干衍射成像的瓶颈分析，用来定位复数网络还缺哪些算子。代码在 `github.com/crasmarum/CNet`。对算子组：**三角掩码 DFT 仍可用 FFT 类分解做到 $O(N\log N)$** 这条本身就可搬——掩码注意力的「因果性」并不必然要求放弃快速变换。

**工具链与部署正确性**

- **[GPU Acceleration of Awkward Arrays: Using Python cuda.compute](https://arxiv.org/abs/2610.08238)**（`2610.08238`）：Awkward Array 是高能物理里表示和操作**嵌套、变长数据**的常用 Python 库，此前的 GPU 化尝试指出了**不规则访存、细粒度 kernel 发射、操作可组合性**三处限制。这篇给的是基于 **Python CCCL（`cuda.compute`）** 的 CUDA 执行模型：**不再需要自写 CUDA kernel**，改用高层 Python 接口；CCCL 路径还能把**多个 Awkward 操作融合成更少的 kernel**，正面解决早期实现的 **kernel launch 开销**；**惰性执行**让表达式图在生成 kernel 之前先被构造与优化，改善锯齿数组、组合操作与归约类分析工作流的表现；此外用户自定义 Python 代码可以**以极少样板**进入 GPU 执行路径而不破坏既有分析语义。对算子组：这是 `cuda.compute`（CCCL）作为**Python 侧 kernel 融合层**的一个实际落地样本——它的比较对象不是手写 CUDA，而是「**每个元素级操作各发一个 kernel**」的 eager 模式，而融合的边界由表达式图决定。

- **[Lost in the bf16 Cast: Exporting Ternary Language Models Can Revert Most Low-Learning-Rate Code Changes](https://arxiv.org/abs/2610.07853)**（`2610.07853`）：三元 LM（BitNet b1.58、Falcon-E、BitCPM）用**高精度潜权重**微调，部署时由一个导出步骤生成三元码，而**三家实验室文档化的管线都先把潜权重 cast 到 bf16**。这篇把这套管线审计了一遍，结论相当刺眼：在已发布的 checkpoint 上，对**出厂潜权重**做 fp32 量化与**部署用的码**不一致的比例是 **0.83–1.77%**（Falcon-E、BitCPM），**BitNet 2B-4T 为 1.530%**；Falcon-E/BitCPM 的不一致**多数是乘积恰好被 bf16 舍入落到阈值上、再由 ties-to-even 映射到零**，而未改动的 `onebitllms` exporter 能**逐字节复现全部四个 Falcon-E 发布**。影响在微调终点上被放大：当学习率按「名义 lr 与 bf16 ULP 之比」匹配时，文档化导出把 **Falcon-E-1B-Base 的贪心 GSM8K 严格准确率从 58.79% 降到 0.78%**、**BitCPM-CANN-0.5B 从 36.13% 降到 0.39%**；单是 bf16 存盘再重载，就让 **BitNet 2B-4T 的严格准确率掉 27.54 个点**（而 last-number 准确率反而升，说明是数值路径被改写而非模型变差）。两种兼容做法——**直接写训练量化器产出的码**，或**调整 bf16 输入直到未改动的工具吐出该码**——在三个模型上都满足「相对在线评测严格准确率非劣 4 个点」的判据。对算子组：**导出/序列化是量化算子链路里被低估的一环**——bf16 这个中间表示会**静默改写整数码**，因此**码本身**（而不是它的浮点潜表示）才是应当持久化与校验的量。
