## TL;DR

- **「用低精度硬件凑出高精度 GEMM」今天被写成了一个可求解的组合优化问题**：把 Ozaki 家族（INT8 余数模法模拟 FP64，及其 FP8/FP4 变体）统一成「每个模数上有一组低精度 GEMM 实现方式，求最少 GEMM 次数的模数+方式组合」，并给出全家族的下界。结果是**首个 FP6 方案**、比此前任何方案都少 GEMM 的 FP8 方案、以及被下界证明在限定模数范围内最优的 FP4 方案；三张 Blackwell 上实测 INT8/FP8/FP4 方案都快过原生 FP64，**B300 上最多 83×**。
- **attention 反向的「行和为零」守恒律今天又出现一次**：**Delta-Matching** 独立地把这条不变量在 **block-scaled FP8** 下恢复，声称可在**不做架构改动、不缩小 global batch、不加辅助前向输出**的前提下，让 attention core 的**每一次前反向 matmul 都用 FP8**，训练 loss 与 BF16/FP32 混精持平——与昨日 FA3 那篇的 GProj 是同一根因的两种解法。另一头，**RLX** 把「编译器 + 运行时」塞进**一个 Rust 代码库**、用统一 IR 覆盖 **14 个后端**，并让不合法化直接**编译失败**而不是静默回退。
- **线性注意力 / MLA 的 state 与 KV 量化今天集中爆发**：**LeapQuant**（8-bit recurrent state，per-window 量化 + outlier 补偿 token，kernel 级 **2.05–3.70×**）、**STEPQuant**（6-bit delta-rule state，按「误差大小 × 记忆寿命」分配精度，SGLang 内核下**服务端总显存最多降 68.7%**）、**QuantMLA**（content + RoPE **双路 INT4**，128K 下物理布局 **3.59×** 压缩、整任务吞吐 **5.168×**）、**WUSH-KV**（数据自适应二阶变换，2-bit 追平或优于 OSCAR）。视频 DiT 侧 **PSA** 发现 attention 存在**周期性对角条纹**结构，用**单个 CUDA kernel** 覆盖所有稀疏模式、MFU 追平 FA3，端到端 **1.57× / 1.37×**；同时 **2609.37261** 给出否定性结论：**uniform 意义上的 attention 近似不存在真正次二次的算法**，即使允许对 KV cache 做多项式预处理。Release Notes 本期只有 CCCL v3.4.3，芯片动态无新条目。

## 三、arXiv 论文（算子内核）

- **[RLX: A Unified Multi-Backend Tensor Compiler and Distributed Runtime in Rust](https://arxiv.org/abs/2609.37916)**（`2609.37916`，09-29）：生产 ML 栈通常把图编译与内核执行拆在不同层、甚至用不同语言写，导致**后端行为、部署保证与性能回退难以端到端推理**。RLX 用**单个 Rust 代码库**把编译器与运行时两种角色合到一套**原始算子级、三层 IR** 上，并配一份**透明的 dispatch 契约**：每个算子被解析为 native、common-IR 或 rewritten lowering 三种归宿之一，且**legalization 不可能时直接让编译失败**，而不是悄悄回退。同一份 IR 面向 **14 个运行时设备**（cpu/metal/mlx/ane/cuda/rocm/oneapi/tpu/hexagon/gpu/vulkan/opengl/directx/webgpu）加两条专用代码生成路径（Cortex-M INT8、FPGA），吃 safetensors/GGUF/ONNX/rten，支持 F16/BF16/F64/C64 与 INT4/INT8 量化流（AMP/PTQ/QAT），并通过 TCP 与 RDMA 上的 tensor-/pipeline-parallel 集合通信扩展。它还把范围扩到科学计算：**CSR LU/CG/matvec 与 LAPACK 支撑的分解**等稀疏/稠密线性代数扩展、以及 3D Gaussian Splatting 算子。评测在同一台机器、统一输入生成与 p50 口径下对标 PyTorch、TensorFlow、JAX、candle、burn、tch、rten、MLX、CoreML、IREE、Glow、TensorRT、tinygrad：all-MiniLM-L6-v2 上 **RLX-Metal 在每个 batch 都最快**（batch 32 时 16.6 ms vs PyTorch-MPS 26.7 ms），MNIST 训练表里 **graph-fused MLP 取得最高吞吐 946,487 img/s**（NumPy+BLAS 787,349 img/s），并在 Qwen3 参考检查上保持 **100% top-1 一致**。对算子组来说，值得关注的是它把「**dispatch 失败即编译失败**」当作一等契约——这正是多后端算子库最难维护的那部分语义。

- **[Parameterized Stripe Attention for Efficient Video Generation](https://arxiv.org/abs/2609.37001)**（`2609.37001`，09-29）：视频 DiT 的推理延迟主要来自**全时空注意力**，而现有稀疏 attention 卡在一个**灵活性与效率的两难**：预定义 mask 无法刻画多样的 attention 模式，运行时决定的 mask 又带来额外开销、牺牲硬件效率。作者认为根因是**缺少对 DiT attention 的统一结构刻画**，并给出这一刻画：视频 DiT 的 attention 在**时间与空间两个维度上都呈现周期性对角条纹（periodic diagonal stripe）结构**。**PSA** 把这种条纹规律**参数化**，用一套表示统一多种 attention 模式、从而让**单个硬件高效的 CUDA kernel 处理所有稀疏模式**，达到 **FlashAttention-3 级别的 MFU**；稀疏配置由一个**免训练的离线搜索**逐 head 决定，在给定误差容忍度下最大化稀疏度。HunyuanVideo 与 Wan 2.1 上相对 **FA3 基线端到端加速 1.57× / 1.37×**，画质退化在可接受范围内。这是「**先找出结构，再用一个 kernel 吃掉所有 mask**」的典型打法，与本月早前 WaveAlign 的「内核不动、调度层拿收益」正好互补。

- **[Efficiently Approximating Attention Is Hard](https://arxiv.org/abs/2609.37261)**（`2609.37261`，09-29）：已知的运行时下界只能排除**近似精确**的快速 attention 算法，于是留下一个实践上更要命的开放区间：**是否存在一个带「哪怕很弱但一致」近似保证的高效算法？** 这篇给出否定答案——在标准复杂度假设下，**没有任何真正次二次的算法能对所有输入一致地达到非平凡的加性或相对近似保证**。该不可能性成立于「**已知算法尚未在近线性时间内取得强近似保证**」的最宽松参数区间，并且扩展到几类实践上相关的放宽：**即使允许对 KV cache 做多项式时间的预处理**，也不存在能取得非平凡一致近似保证的高效算法，**也不存在能识别出「获得大量 attention 的一小组 key」的高效算法**。后半条直接落到稀疏 attention 的立论基础上：**基于打分选 key 的做法没有一致保证**，所以当前 sparse attention 的收益必然来自输入分布的结构性假设（如 PSA 找到的条纹），而不是算法层面的普遍保证。

- **[QuantMLA: Function-Aligned Dual-Path Quantization for Low-Bit MLA KV Caching](https://arxiv.org/abs/2609.36760)**（`2609.36760`，09-29）：MLA 用紧凑 cache 支撑多头注意力，但**cache 内存仍随上下文与 batch 线性增长**，且它的 **content 路径与解耦 RoPE 路径是两条数值性质不同的支路**。这篇先建立 **MLA 双路量化误差的系统模型**，刻画两者对 attention 输出失真的不同影响，并解释**RoPE 路径误差为何被显著放大**。据此提出 **QuantMLA**：为两条路径分别推导**特定变换空间**，使得变换后的计算**保持全精度语义**，同时**可离线完全折叠进模型参数**、**不引入任何在线变换开销**；在这个空间里用**功能对齐的目标**学变换——content 路径做 **attention 输出重构**（同时覆盖 matching 与 aggregation 两类耦合误差），RoPE 路径做 **positional QK 重构**（保住 attention logit 中由 RoPE 贡献的分量），并给出输出失真的理论界。跨四个 MLA 模型家族，QuantMLA 实现了（据作者所知）**首次 content cache 与 RoPE cache 的联合 INT4 缓存**且精度退化极小；把 content cache 进一步压到 **INT2**、RoPE key cache 保持 INT4，在困难的推理与代码基准上仍有竞争力。工程侧是本文的硬货：作者写了**原生低比特 MLA attention kernel，把解包与反量化直接融进 attention 计算**，物理 cache 布局在 **128K 上下文下压缩 3.59×**；在一个 **cache 压力型 serving 负载**下，**整任务输出吞吐比 BF16 高 5.168×**。代码将在接收后放出。

- **[WUSH-KV: KV Cache Quantization with Data-Adaptive Transforms](https://arxiv.org/abs/2609.38121)**（`2609.38121`，09-29）：KV cache 的显存与带宽开销随上下文长度和 batch 增长，是长上下文推理的瓶颈。**WUSH-KV** 把 **WUSH** 变换用到低比特 KV 量化上——WUSH 从**矩阵乘积两个因子的二阶统计量**构造数据感知变换以压低量化误差。具体做法是用校准数据分别为 key 与 value 构造变换，其中 **value 变换折叠进模型权重**、**key 变换在 RoPE 之后施加**，且变换可与带裁剪的量化器配对。作者还证明：对其中一种量化器 **QuEST INT**，在温和假设下 **WUSH 变换是近乎最优的**。用它做端到端时，WUSH-KV 降低了逐层重构误差，并在所测变换中取得**最低的端到端困惑度**；集成进 **SGLang** 时采用 OSCAR 风格的**百分位裁剪仿射量化**，在 **2-bit** 下于所有评测模型与下游任务上**与 OSCAR 变换持平或更优**。对做 KV 量化内核的人，这条的价值在于「**变换要贴着矩阵乘积双方的二阶统计来设计**」这个准则被推到了近似最优的位置，且变换可离线折叠、不增加运行时开销。

- **[LeapQuant: Efficient Linear Attention with Accurate Recurrent State Quantization](https://arxiv.org/abs/2609.38166)**（`2609.38166`，09-29）：Gated DeltaNet、Kimi Delta Attention 这类**混合线性注意力**把上下文压进**固定大小的 recurrent state**，大幅降低长上下文成本，但**反复读写与更新这个 state 本身成了推理瓶颈**。直接低比特量化 state 会掉点严重，原因是**舍入误差在逐步 state 更新中累积**，外加 state 里存在**outlier 行与 outlier 列**。**LeapQuant** 是免训练方法，两招配合达成 **8-bit recurrent state 的近无损**：其一 **per-window quantization**——**跨过一个 token 窗口、只在窗口末尾量化一次 state**，窗口内输出用**固定低比特 state 加高精度缓冲更新**算，从而掐断误差的逐步累积；其二保留 state 中最大的 outlier 作为少量**高精度 Compensator Token**，让它们**与真实 token 共享同一条更新路径**，再对剩余残差做平滑后才量化。跨 Qwen、Kimi、GLM 三个模型家族，在 **NVIDIA B200、RTX PRO 6000、RTX 5090** 上，精度与 FP32 基线相当的前提下取得 **kernel 级 2.05–3.70×、端到端 1.47×** 的加速。「**只在窗口边界量化 + 把 outlier 留在高精度路径**」这两条，对任何带**递推 state** 的算子都是可直接搬的模板。

- **[STEPQuant: When and Where Errors Matter in Delta-Rule Recurrent State Quantization](https://arxiv.org/abs/2609.38169)**（`2609.38169`，09-29）：与 LeapQuant 同一天、同一问题域，但走的是 **PTQ 校准**路线。作者先给出一组观察：delta-rule 递推 state 的量化误差影响取决于两个互补维度——**时间上**，长期存活记忆里的误差会**跨很多解码步持续**；**空间上**，不同 key 行的误差对模型输出的影响不同，而 state 的量级**沿行与沿列都变化剧烈**。**STEPQuant** 据此**按误差大小与记忆寿命分配精度**，并**联合拟合 key 行尺度与 value 列尺度**，拟合依据是 state 分布以及 key 行对输出误差的影响。在 Qwen3.8-27B 与 Kimi-Linear-48B-A3B-Instruct 上，**标称 6-bit 预算下精度接近 FP32 state**，**4-bit 配置优于均匀 INT8**；集成进 **SGLang** 并配优化过的 GPU kernel 后，6-bit STEPQuant 取得 **5× 以上的 recurrent-state 压缩**，**服务端总显存最多降 68.7%**。代码开源在 `github.com/Dreamer-Toby/STEPQuant`。两篇并读可以看出这一子领域的共识正在收敛：**state 量化的关键不在位宽，而在「哪些元素活得久、哪些元素影响大」**。

- **[Delta-Matching: Closing the Final Gap of Native 8-bit Training for LLMs](https://arxiv.org/abs/2609.37852)**（`2609.37852`，09-29）：**可靠的 FP8 attention 一直是从头 8-bit 训练的最后一道坎**。作者推导**前反向不一致如何产生 stale delta**，并实测它如何扭曲训练动力学：stale-delta 的混合精度实验在 **569M 参数上只有温和的 loss 差距**，但到 **1.67B 与 5.29B 就出现明显 loss 上升与下游退化**；**QK normalization、NoPE（去掉位置编码）、以及降学习率的上下文扩展**都只能缓解或推迟、无法消除。这一模式说明根子是**累积的优化误差**，小模型与短训练会把它掩盖掉。**Delta-Matching** 的做法是证明：在给定数值假设下它**恢复了 softmax 梯度的「行和为零」不变量**，从而允许 **attention core 的每一次前向与反向 matmul 都使用原生 block-scaled FP8**，且**不需要改架构、不缩小 global batch、不产生辅助前向输出**；在所测架构、规模与训练阶段上，训练 loss 与下游表现均**追平 BF16/FP32 混精**。实现、训练好的模型与数据配方都将放出。**这与昨日收录的 2609.34272（FA3 在 BF16 下的梯度爆炸）是同一根因的两种解法**：那篇用 **GProj** 在 cast 后用每行两次 rank-one 修正恢复零和、代价是每步多 4.7% 时间；这篇把它做成 FP8 训练链路里的原生环节。两天之内同一不变量在 BF16 与 FP8 两个方向被分别独立解决，基本可以认为**「attention 反向的零行和」已经从工程细节升格为必查项**。

- **[FP64 Is All You Want, INT8 Is All You Need, FP4/6/8 Is All You Have](https://arxiv.org/abs/2609.37693)**（`2609.37693`，09-29）：**Ozaki scheme II** 用**成对互素模数上的余数**把 FP64 矩阵乘模拟成 INT8 矩阵乘，此后又出现了 FP8 与 FP4 的变体。这篇把这一族方案**统一处理**，并把「**选哪种方案**」写成一个**组合优化问题：最小化低精度 GEMM 的次数**。给定「每个模数上、由低精度 GEMM 计算模积的有限种方式」，算法要找出**模数与方式的组合使 GEMM 次数最少**，适用于任意格式、累加器与内维度；作者同时推导出**整个方案族上 GEMM 次数的下界**。把它用到当前 GPU 的格式上，得到：**首个 FP6 方案**、一个**比此前任何方案都少 GEMM 的 FP8 方案**、以及一个被下界证明**在其模数落在给定范围内的整个子族中最少 GEMM** 的 FP4 方案。在三张 **Blackwell GPU** 上实现后，INT8、FP8、FP4 三种方案都**快过原生 FP64，B300 上最多 83×**。对做 GEMM 与精度模拟的人，这篇的实际产出是**一张可查表的最优方案表 + 一个下界**——把「用低精度凑高精度」从经验配方变成了可优化的目标函数。

- **[Replay the Curvature: Accurate and Scalable NVFP4 Quantization for Large Language Model Inference](https://arxiv.org/abs/2609.36654)**（`2609.36654`，09-29）：**NVFP4** 让每 **16 个 E2M1 权重共享一个 E4M3 block scale** 以改善局部动态范围利用率，但**在 GPTQ 里选这个 scale 很难**：量化一列会更新其后各列，因此**孤立评估一个 block 会误判它的最终重构误差**。大模型还有第二重困难——**全精度权重、校准激活与二阶状态无法同时驻留单卡**，而按整层分配设备又会让每个耗时层求解串行化。**Schur Replay** 的做法是**复现每个 block scale 所引起的 GPTQ 更新**，并在**计入未量化列带来的补偿之后**给该 block 的误差打分；配套执行基础设施**只驻留当前活跃层**、把激活**分级放在 device / host / disk**、导出后即刻**退役全精度层**、并把**独立输出行分到各 tensor-parallel rank**。算法加基础设施在 **Qwen3.5-397B-A17B 与 Llama-3.3-70B-Instruct** 上、七个基准中取得 **99.35% 与 100.84% 的 BF16 问题加权恢复度**；在 397B 模型上，**逐层耗时相对 ModelOpt 降 15.17×、相对 LLM Compressor 降 23.14×**，且每 GPU 显存占用更低。这是「**算法必须在真实精度格式与真实显存约束下同时成立**」的一个完整样本。

- **[Scale Sensitivity in Low-Bit Post-Training Quantization: Curvature of the Quantization Error Landscape](https://arxiv.org/abs/2609.37416)**（`2609.37416`，09-29）：GPTQ 一族 PTQ 在**均匀网格**上最小化逐层重构误差，而**网格的 scale 必须选**——常见的 max 基准选择在低比特下退化剧烈。这篇研究目标函数**对 scale 的敏感度**：对权重为 i.i.d. 高斯、校准激活有效秩足够大的层，证明**随宽度增长，归一化的 round-to-nearest 损失以高概率、对所有 scale 一致地收敛到「标准高斯上均匀量化器的均方误差」**，并在宽随机初始化 MLP（奇 Lipschitz 激活、各向同性高斯校准数据）上验证了有效秩条件。该极限目标有**唯一的非退化极小点**，其 scale **随量化级数严格递减**，且**对相对 scale 误差的曲率随比特宽度近似指数衰减**。五个 LLM 上的 GPTQ 实验与趋势一致：**scale 规则在 2–3 bit 下显著影响困惑度，6 bit 以上几乎无影响**，且局部敏感度度量随位宽的变化与高斯曲率吻合。两个实用结论：**高斯最优 scale 直接用在原始权重上会失败**；但在 **Hadamard 不相干化处理之后，3 bit 及以上它无需任何搜索就能匹配最优的搜索规则**，2 bit 下仍明显更差。对写量化内核的人，这给出了「**多少比特以上可以停止调 scale**」的理论依据。

- **[Mira: Memory-Efficient MoE Inference Using Adaptive Caching and Predictive Expert Staging](https://arxiv.org/abs/2609.38090)**（`2609.38090`，09-29）：单卡跑 MoE 的难点是**专家参数占满显存**，而 token 级路由**动态、不可预测且高度偏斜**；此前的 offloading 与缓存方案本质上是**反应式**的——必须等 router 输出才能搬专家，于是缓存利用率低、紧显存预算下**无法把传输与计算重叠**。**Mira** 改为**主动式**：用**轻量逐层预测器提前两层预判专家使用**，据此做**主动预取**；预测结果喂给一个由 **token 级路由遥测**管理的两级 **HOT + STAGE GPU 缓存**，把高频专家常驻、把预测到的专家暂存；为压低传输开销，它给专家参数实现了**自定义压缩格式**，减少元数据、提升打包效率，精度损失很小。整套**集成运行时**协同预测器、缓存策略与量化传输，最大化通信与计算的重叠。相对 SOTA 基线，显存受限 GPU 上**平均吞吐 5.71×**、**TTFT 加速 11.71×**、**beam search 平均加速 3.84×**。其中**为传输而设计的专家参数压缩格式**，是算子侧可直接借鉴的一块。

- **[Behavioral Capacity Certificates for Quantized Language Models](https://arxiv.org/abs/2609.37887)**（`2609.37887`，09-29）：激活与 KV cache 的精度**不改变存储的权重，却改变模型实际算什么**，而直接按权重码字下界的方法**会给行为不同的部署记同样的复杂度、给行为相同的权重码字重复计费**。**BCC** 改为按**行为**计费：把「权重、scale、激活与 cache 规则」组成的**完整实现**按**诱发同一受限 loss** 聚合，用量子化的先验质量计复杂度——**量化把多个实现合并时共享质量会降低复杂度惩罚**，并给出一条**盈亏平衡律**判断这笔节省能否覆盖验证成本。三步部署流程各自有实验支撑：**前向-only 的筛选**按「候选扰动保持参考预测的频率」挑逐层位宽，质量与 Hessian 引导的选择相当而预处理更便宜；**margin 认证单元**找出可剪枝或可翻转符号而不改变部署行为的权重，在 OLMoE-1B-7B 与 SmolLM2-1.7B 上所有允许组合都保持全部声明预测，独立探针给出「新文本上任何允许组合改变预测」的概率界；第三步给出部署模型**总体 loss 的界**，对完整解码器非空且比压缩码路径更紧。一条对算子配置很实用的观察：**在同等 cache 显存下，给 key 高于 value 的精度会得到更低的 NLL 与更高的预测一致性**（GPT-2、Qwen2.5、SmolLM2），并在 GPT-2 审计中获得更紧的复杂度界。
