## TL;DR

- **工具链侧等来了本窗口唯一一条正式 release：CCCL 3.5**。三件事都直接改算子写法——CUB 的调参面（threads per block、items per thread、向量化、算法选择）第一次以**公开 API** 暴露（`cuda::execution::tune(...)` + policy selector，按 compute capability 返回 `cub::ReducePolicy` / `cub::ScanPolicy`），不再靠编译期宏或抄内部 policy；`cub::DeviceScan` 支持**逐次运行可复现的浮点求和**（`determinism::run_to_run` 选定固定归约序）；新增 `cub::DeviceBatchedTopK`（每 segment 一个 block、48 KiB smem、float key 上限 8192）。**「可复现」正在从论文里的技巧变成库里的开关**——这与 10-06 期 TurboPairFormer 的有序归约、10-07 期 NeMo-DCR 的 bit-exact refit 是同一条线，只是这次落到了 standard 库里。
- **低位宽这期的主线是「把旋转省掉、把码本冻结」**：**CurveTQ** 指出 QTIP/Proteus 这类最强 2-bit 权重量化器**每步解码都要把随机正交旋转撤回来**，而旋转的作用只是抹平 Hessian LDL 分解对角线上的**块内曲率差异**——于是把对角线权重直接放进 **Viterbi 分支度量**、在原始基底下加权搜索，**不用旋转**，三项下游精度还高出 **1–3 个点**，解码器在所有测试 batch size 与位宽下**三者最快**；**CanonQ** 则把「源规范化」与「任务适配」拆开，用固定旋转 + 能量归一化把异构张量（权重/激活/KV）映射到**规范坐标**，从而让**一份冻结的高斯参考码本跨层跨模型复用**，W2A4KV2 下 WikiText-2 困惑度最多低 **14.28×**；**TR-PTQ** 把注意力从「精度不够」转到「结构误差」——真正拖累整数化的是**归一化层的可学习 scale 与 GELU 的复合近似**（SoftMax 反而鲁棒），于是用共享的 **Taylor Region exp/log 原语**把除法与开方全部搬进**对数域**用整数算，彻底不需要 FP 单元做非线性。
- **稀疏注意力这期给出的是「先算清楚该取多少 key」**：**Attention via Black-Box Vector Search** 用 priority sampling 统一了此前各路做法，证明**只给一个 MIPS 索引时 Θ(√n/ε) 个 key 既充分又必要**，给 Θ(log n) 个索引则只需 O(log n + 1/ε²) 个（近最优），并给出索引数与取回数之间的连续折中——**这是一条可以直接写进 kernel 预算的设计律**；**SPIN** 则攻 indexer 自身开销（每步都要给整个 KV cache 打分），用**基于历史的轻量预测**挑 KV 块，30–40% 稀疏度下 vLLM 输出吞吐 **+14.9%**、中位 ITL **−13.2%**。

## 一、CUDA 开源仓 Release Notes（算子）

### CCCL

- **v3.5.0** — [链接](https://github.com/NVIDIA/cccl/releases/tag/v3.5.0)：CCCL 3.5 把 CUB 的调参权交还给调用方：应用可以在执行环境里通过 `cuda::execution::tune(...)` 传入 **policy selector**，由它按 GPU compute capability 返回算法专属 policy（`cub::ReducePolicy` / `cub::ScanPolicy` 等），从而**在公开的 device-wide API 上定制 threads per block、items per thread、向量化与算法选择**——重复归约/扫描在特定形状上不再只能吃默认 policy（示例用 256 threads、`vec_size=4`、`BLOCK_REDUCE_WARP_REDUCTIONS`、`LOAD_LDG`，并让 items per thread 随 compute capability 取 16/20）。稳定性方面，`cub::DeviceScan` 新增**浮点求和的 run-to-run 可复现**：请求 `cuda::execution::determinism::run_to_run` 即选定**固定归约序**，同一 GPU、同一输入与构建配置下结果逐次一致（覆盖 `cuda::std::plus` 的 inclusive/exclusive sum 与 scan）。新增 `cub::DeviceBatchedTopK`：从大量 segment 中各自独立选出最小或最大的 K 项，`MinKeys` / `MaxKeys` / `MinPairs` / `MaxPairs` 支持固定或可变 segment 长度、K 值也可逐 segment 变化；本版**每个 segment 由一个线程块处理、smem 上限 48 KiB**，默认 policy 下 float key 每段最多 **8192**、double 最多 **4096**；调用方须给出 segment 规模的编译期上界（如 `cuda::args::bounds<1, 8192>()`）并显式声明非确定性、无序输出。另外本版还加入了**接受「存放在 GPU 上的问题规模」的归约**（问题长度本身就是设备端数据时省掉一次 D2H 同步）。对算子组：**「可复现」与「可调参」这两件事同时进了标准库**——前者把 run-to-run 确定性变成一次 require 就能要到的性质，后者意味着与自己手写 reduce/scan 抢性能时，基准不再是 CUB 的默认 policy，而是它按 capability 分派的 policy。

## 三、arXiv 论文（算子内核）

**低位宽格式与量化 kernel**

- **[Few Bits, One Law: Toward W2A4KV2](https://arxiv.org/abs/2610.09202)**（`2610.09202`，CanonQ）：权重、激活、KV cache 三者**同时**低位量化时，各自的分布不同、量化误差还会在网络里互相作用，这是极低比特最难的场景。CanonQ 把问题拆成**源规范化**与**任务适配**两步：固定旋转 + 能量归一化先把异构张量源映射到**规范坐标**，于是**一份冻结的高斯参考码本可以在层之间、模型之间复用**，不必每层重新学码本；随后在统一的 scalar/vector 接口上做联合训练，让网络去适配权重/激活/cache 三种误差的**耦合**。理论侧给了冻结码本迁移误差与局部任务损失的界，并推导出**归一化感知的 straight-through Jacobian 精确形式**，把量化失真与梯度偏置显式连起来。结果：LLaMA3-1B/3B/8B 上 W2A4KV2 联合压缩，WikiText-2 困惑度最多低 **14.28×**、平均零样本准确率高 **57.9%**；收益也延伸到 Qwen3-1.7B、代码生成与数学推理——指令微调的 MobileLLM-Pro-1B 在 W2A16KV16 下 HumanEval pass@1 相对提升 **41.7%**、GSM8K **39.1%**。对算子组：**「跨层复用一份码本」是省钱的那一步**——码本一旦可以冻结，量化就从「每层一套查找表」退化成**共用一次源码本 + 每层只存旋转与尺度**，这正是 kernel 侧最想要的形态。
- **[CurveTQ: Rotation-Free Trellis Quantization of LLM Weights via Curvature-Weighted Search](https://arxiv.org/abs/2610.09212)**（`2610.09212`）：QTIP、Proteus 这类当前最好的 2-bit 权重量化器有两条固定开销——**每个解码步都要把随机正交旋转撤回来**，且在欧氏度量下用 trellis/lattice 码做搜索，**层 Hessian 只通过编码块之间的 error feedback 起作用**。这篇指出这浪费了 Hessian 的一部分：error feedback 把损失写成**逐坐标舍入误差的加权和**，权重就是 Hessian **LDL 分解的对角线**——现有量化器算出了它却从没读过。把这组权重放进 **Viterbi 分支度量**，搜索就能在**每个编码块内部跟随曲率**；这同时解释了旋转的作用：它只是抹平**块内**的曲率变化，所以**在原始基底下加权与先旋转是等价的两种手段**。实测三项模型上，加权原生搜索与全维随机 Hadamard 相差在**约 1 个下游精度点以内**，而旋转之后再加权几乎无增益。围绕该搜索构建的 CurveTQ 是一个**不需要旋转的 trellis 编解码器**：用分解的尺度场处理权重幅度与边缘形状、闭式分位表，并为每个编码块存一个**起始状态**以便 trellis 适配 error feedback 带进来的残差。2-bit 下三项 4–8B Instruct 模型上比 QTIP 与 Proteus 高 **1–3 个平均下游精度点**——且把我们的 start state 单独给基线，也能把对方抬高 1–3 点；在 35B MoE 上同样领先（据作者所知是首个 trellis 编码结果）。**没有旋转要撤，解码器在所有测试 batch size 与位宽下三者最快**。对算子组：**解码步里省掉一次正交变换**是纯赚——它既是精度收益的来源，也是 kernel 里最实在的那部分延迟。
- **[Dual-QK: Sharp Queries and Flat Keys for Prunable 2-bit KV Caches](https://arxiv.org/abs/2610.09827)**（`2610.09827`）：低比特量化省 KV 存储，query 通道剪枝则进一步省 key-cache 的**读取量**；但旋转式量化为了保持计算不变性，必须对 query 施加同一个正交变换，**这会打散 query 的能量**、削弱「少数大分量可留、大量小分量可剪」的分离度——两条优化正好互相拆台。Dual-QK 用**一对非正交**的 query/key 变换化解：以校准得到的 query/key 统计为基础，把**部分 key 白化**与一个**对齐 query 的基底**结合，既均衡 key 尺度以适配 **INT2**，又让 query 能量集中以便动态通道剪枝；再配 channel-0 保护与 **bucket-relative RoPE** 维持长上下文下的低比特精度。四个模型、五项生成基准加长上下文检索：40% query 通道稀疏度下多数任务优于 OSCAR；128K 上下文相对未剪枝 BF16 达到 **6.8× KV cache 压缩**与**估计 8.3× 的 KV 读取量下降**；其 SGLang 实现在评测配置下解码吞吐最高为未剪枝 BF16 的 **3.75×**。对算子组：**旋转不再是「免费且必要」的那一步**——它同时决定量化误差与可剪性，因此 query/key 的变换要按「谁的统计量」分别设计。
- **[ResidualQuant: KV Cache Quantization for Looped Transformers with 2-Bit Residuals](https://arxiv.org/abs/2610.10381)**（`2610.10381`）：loop（循环复用同一批 Transformer block）提升的是**计算深度而非参数量**，但 KV cache 随 loop 数线性增长，直接卡住 batch size 与吞吐。这篇的观察是 looped Transformer 独有的机会：**不同 loop 之间的 KV 状态高度相似**。ResidualQuant 以**最后一轮的 KV 状态为参考**，其余轮次只存**低精度残差**，并对残差施加最小二乘尺度与旋转、再加**逐轮混合精度**，从而在 **INT2** 下仍能高精度重建。多个 looped Transformer 模型、数学推理与代码生成基准上，精度-显存权衡稳定优于旋转式 KV 量化基线：混合精度配置下精度接近 BF16 而理论 KV 存储降 **80.7%**，同显存预算下比旋转基线最高高 **13.0%** 精度；RTX 5090 上 KV 访存下降带来固定 batch 解码吞吐最高 **2.73×**，更小的内存足迹还允许 **2× 大**的 batch、峰值吞吐最高 **4.15×**。对算子组：**跨 loop 的相似性是 KV 侧新的可利用结构**——残差编码把「每轮各存一份」改成「一份参考 + 多个 2-bit 残差」，访存量与解码吞吐同时受益。
- **[TR-PTQ: High-Accuracy Integer-Only Transformer Post Training Quantization via Taylor Region Reformulation](https://arxiv.org/abs/2610.09969)**（`2610.09969`）：既有 PTQ 常把精度损失归因于「数值精度不够」，因而不得不给非线性层留**浮点回退**。这篇先纠正了归因：真正的误差来源是**结构性的**——归一化层里的**可学习 scale 参数**，以及 **GELU 的复合近似**；而 **SoftMax 对激进量化反而天生鲁棒**。对策是统一的全整数形式：用共享的 **Taylor Region（TR）指数与对数原语**，让除法、开方这类昂贵运算**完全在对数域用标准整数算术完成**，再配合**免校准、outlier-aware 的 LayerNorm 参数优化**，于是非线性环节**彻底不需要浮点硬件单元**。视觉与语言基准上绝对精度损失低于 **1.5%**。对算子组：**「整数-only」的边界不在 SoftMax，而在 LayerNorm 的 scale 与 GELU**——把 exp/log 做成共享的整数原语后，整条非线性链可以待在整数域里，省掉的是 FP 单元与由此产生的类型转换。
- **[OnlineQAT: On-Policy Distillation for Ultra-Low-Bit Large Language Models](https://arxiv.org/abs/2610.09346)**（`2610.09346`）：QAT 能把 4 bit 以下的精度损失找回大半，但现有恢复阶段通常优化在**固定补全或教师生成的答案**上；而部署中的量化模型**面对的是它自己生成的 prefix**，量化误差会把它推进离线恢复数据里根本不存在的状态。OnlineQAT 分两步：先用 block-wise QAT 拿到可用的低比特初始化，再在**学生自生成的回复**上做 on-policy distillation——在每个访问到的 prefix 处，由**冻结的全精度教师**提供**采样的 reverse-KL** 训练信号。Qwen3-1.7B 上在被比较的量化方法中平均最好：W3A16 为 **57.28**、W2A16 为 **32.52**，比 ReasoningQAT 分别高 **2.90** 与 **0.44** 点；结论是**学生自己走过的状态**提供了固定补全训练之外的恢复信号，在 3 bit 处尤其明显。对算子组：与 10-07 期 TRACE 是同一类账——**量化误差会把模型推离训练数据覆盖的分布**，因此恢复训练的数据应当由量化模型自己产生。
- **[Q-PACE: Dynamic Precision Allocation for Quantization-Aware Training](https://arxiv.org/abs/2610.09183)**（`2610.09183`）：QAT 的混合精度需要在训练过程中决定「哪些层留高精度」。Q-PACE 用一个**二阶敏感度模型**来预测损失增量——把它写成**量化噪声 MSE 按逐层曲率系数加权求和**，训练中**周期性用跨层扰动重算这些系数并重新分配精度**。最多 4B 参数的预训练与 SFT 实验里，它稳定优于既有混合精度训练配方，且**在显著更低的总显存预算下达到可比损失**。另一个值得记的观察：**量化敏感度按深度与层类型高度可预测**，且在训练过程中足够稳定，因此重标定可以**低频、廉价**地进行。对算子组：**精度分配是训练期的在线决策，而不是一次性搜索**——系数稳定意味着重算成本可以摊薄，这和 10-07 期 ActTune 把精度配置与频点接成同一决策是同一思路的两个场景。
- **[Layerwise Error Attribution for Fast and Robust Mixed-Precision Post-Training Quantization](https://arxiv.org/abs/2610.09877)**（`2610.09877`）：混合精度 PTQ 要在**全局显存预算**下逐层分配比特，两个难点是分配问题的组合爆炸，以及**对少量、可能被污染校准数据的敏感性**。这篇给出逐层的量化误差**概率分析**，把**传播误差**与**该层引入的局部扰动**分离，并用局部项构造一个**可分离的打分**，从而用一个不需要外部求解器的简单分配算法完成分配；概率化的建模同时带来对**受损数据**的鲁棒性。DRUNet 去噪任务、平均 4 bit/权重的预算下，干净校准时匹配或超过 SOTA 混合精度基线；**校准数据被污染时 PSNR 最多高 7.5 dB**；比特分配速度比所研究的基线**快 28×–2570×**。量化扩散模型上直接套用该框架同样优于 SOTA。对算子组：**分配算法本身的开销此前是被忽略的一项**——28× 到 2570× 的差距说明，很多方案把时间花在了求解器上而不是量化上。
- **[Quantize by Drift: Label-Free Mixed-Precision Post-Training Quantization for Text Embedders](https://arxiv.org/abs/2610.09227)**（`2610.09227`）：文本 embedder 做混合精度 PTQ 需要逐模块的敏感度信号，而最直观的信号——「量化某模块后检索质量掉多少」——需要部署方往往没有的**相关性标注**。这篇测了一个免标注替代量：**量化诱导的表示漂移**——量化单个模块、重新编码语料、记录输出 embedding 相对全精度位置移动了多远；被观测的对象很具体，就是**dense retriever 实际据以排序的那个输出表示**。五个 embedder 上，配置级漂移把抽样混合精度方案对**留出检索质量**的排序能力做到 macro Spearman **0.911**，且该敏感度可跨校准语料与检索域迁移；模块漂移可以**在序上组合一致、但数值上不可加**；由相关性导出的敏感度**没有一致增益**。预注册实验（三个此前未动过的 embedder）中，相对 LieQ 准则的方向性假设 **3/3** 成立、无崩塌，在 2/3 的情形下优于一个双侧 LieQ steelman；**但在主预算下，漂移的数值低于同预算的均匀精度（三个模型分别 −0.99、−0.85、−1.01 点）**，因为它如设计所愿地压低了模块与整体漂移。作者的结论是：输出漂移是一个**稳健的粗粒度敏感度信号，但不是普适最优的分配目标**——在均匀精度这个强工作点周围的细粒度再分配仍是未解问题。对算子组：**这是一条诚实的负结果，值得按负结果来读**——「有信号」不等于「该信号就是优化目标」，把漂移当分配目标反而会输给什么都不做的均匀精度。
- **[Shared Low-rank Basis Factorization for Data-free Mixture-of-Experts Compression](https://arxiv.org/abs/2610.09342)**（`2610.09342`）：MoE 用稀疏路由把容量与算力解耦，但参数量带来存储与serving 压力。这篇先把三类压缩路线（**专家剪枝 / 专家合并 / 权重重建**）放在一起分析，并给出**结构性误差界**：剪枝与合并会产生**不随规模消失的误差**，且该误差与**路由、专家异质性**绑定；而权重重建因为**保留专家结构与路由**，避开了这部分结构性代价。据此提出的 SLBF 是一种**免数据**的权重重建方法：用**在专家之间共享的 rank-k 基**获得更强的跨专家共享、更快收敛与更低重建误差，再用一次 **post-hoc gauge fixing** 在不损失表示能力的前提下**去掉冗余参数**。五个 16B–122B 的 MoE 架构上一致优于三类压缩方法的代表工作。对算子组：**MoE 压缩要先问「动没动路由」**——一旦改了专家边界或路由行为，误差就不再随规模衰减，这决定了压缩后的算子图能否与原模型逐层对齐。

**稀疏与低秩注意力**

- **[SPIN: Shadow Predictive Indexer for Sparse Attention](https://arxiv.org/abs/2610.09025)**（`2610.09025`）：indexer 式稀疏注意力只把固定少数重要 token 送进核心注意力，**但 indexer 自己必须在每个解码步给整个 KV cache 打分**——上下文一长，这部分开销本身就成了主要瓶颈。SPIN（Shadow Predictive Indexer）用**轻量的、基于历史的预测**来定位重要 KV 块，从而免去每步全量打分；实现上把 **KV 块与投机解码**当作一等设计考量（而非事后补丁）。长上下文与 agentic 基准上，SPIN 在**30–40% 稀疏度**下保持任务质量；端到端 vLLM serving 中输出吞吐最高 **+14.9%**、中位 inter-token 延迟最多 **−13.2%**。对算子组：**稀疏注意力的账要从 core attention 移到 indexer**——当被稀疏掉的部分已经不是瓶颈时，继续优化 core kernel 收益有限，真正要压的是「每步都得扫全量」的那次打分。
- **[Attention via Black-Box Vector Search](https://arxiv.org/abs/2610.10135)**（`2610.10135`）：稀疏注意力用一小部分 key 去估计全体注意力，其中不少做法依赖最大内积搜索（MIPS）捞出最重的 key。这篇把问题问到底：**如果只给你一个黑盒 MIPS oracle，要取回多少个 key 才能给出 ε-精确的注意力估计？** 答案是把此前各路做法统一到 **priority sampling** 框架下：**只用一个 MIPS 索引时，Θ(√n/ε) 个 key 既充分又必要**；给 **Θ(log n) 个索引**，可以做到只取 **O(log n + 1/ε²)** 个 key，并证明这已近最优；更一般地，作者给出**索引数与取回 key 数之间的连续折中**。更进一步：**若允许对 key 与 query 做增广**，上述下界可以被绕开——存在一个简单的 priority sampling 估计器，**一个索引 + O(1/ε²) 个 key** 即可。接进 LLM 推理后，这些算法优于此前使用的 top-k 与采样方案，且注意力近似的误差随上下文变长表现更好。对算子组：**这是一条可以直接写进 kernel 预算的设计律**——先决定「有几个索引」，再决定「取多少 key」，而不是反过来凭经验调 top-k。
- **[Tucker Bottleneck Attention for Multi-Dimensional Sequence Modeling](https://arxiv.org/abs/2610.09090)**（`2610.09090`）：自注意力的二次代价限制了多维数据的长序列建模。TuBA（Tucker bottleneck attention）利用**低秩张量结构**做全局 token 混合：把隐张量投影进**紧凑的 Tucker 核心**，在**核心上**做多头自注意力与线性投影，再把更新写回原空间，从而做到次二次计算；其自回归扩展在**核心内部做双向交互、在核心之间做因果注意力**。视频预测与全球天气预报上，相对标准自注意力，误差与计算量分别最多降 **24.7% / 66.6%**（视频）与 **37.1% / 85.1%**（自回归天气预报），加速最高 **4.27×**；低秩 Tucker 核心与多帧生成也分别优于全秩注意力与逐帧生成。对算子组：**把注意力搬到低秩核心上执行**意味着 kernel 的输入布局跟着变——核心是紧凑张量而非序列，因果掩码的语义也随之从「token 之间」移到「核心之间」。
- **[CHASE: Channel-Aligned Structure Exploitation for Geometry-Aware Model Engineering](https://arxiv.org/abs/2610.09476)**（`2610.09476`）：GSA（Geometric and Spectral Alignment）用**谱集中度、物理通道对齐、支撑结构、奇异基的变化**来刻画训练好的网络。CHASE 把这些结构直接用到模型设计上，覆盖修改、重构、压缩三类共六个应用：CORA、COEC、CORAM 分别把 GSA 用于参数高效微调、结构化剪枝补偿与模型合并；三个新方法则更贴近算子——**CAGA** 用 GSA 找出**可以共享 KV 表示的注意力头**，并通过几何对齐与低秩子空间提取构造共享的 key/value 头；**SAKV** 用 GSA 判断**哪些相邻层可以共享一份低秩 KV-cache 表示、以及每层组该保留多少秩**；**CAPS** 用 GSA 的谱结构给输出神经元分组，并**为每组单独选择保留哪些输入通道**。实验显示 CAGA 的几何共享头构造**显著改善 MHA→GQA 的转换**，SAKV 与 CAPS 在 KV-cache 压缩与结构化剪枝上优于代表基线。对算子组：**「哪几个头/哪几层可以共用一份表示」是可以从权重几何里直接读出来的**——GQA 转换与跨层 KV 共享因此不必靠试错，共享的 rank 也能逐层组指定。

**数值精度与矩阵乘法算法**

- **[What Bloats Your Floats? Right-Sizing Numerical Precision for Scientific Computing](https://arxiv.org/abs/2610.09089)**（`2610.09089`）：FP64 仍是科学计算的默认实数表示，但硬件趋势持续偏向为 AI 优化的低精度格式——**吞吐与能效压过了全精度能力**。这篇直接质疑 PDE 类仿真中高精度算术的必要性：**空间与时间离散误差已经引入了一层物理噪声地板，它把 FP64 的低位比特整个盖住**，那些位因此不起作用。作者据此提出一个基于**相对空间/时间细化的信噪比（SNR）判据**，用来评估安全降精度的影响，并给出一个**以数据流为中心的自动化工作流**，在复杂科学应用中**针对混合精度子图做定向降低**。天气与气候应用的大规模评测显示，在 GPU 上有策略地降精度可拿到最高 **1.8×** 加速而不损失物理保真度。对算子组：**「需要多少位」应当由问题的噪声地板决定，而不是由格式的默认宽度决定**——这给混合精度子图的划分提供了一条可计算的判据，而不是靠逐 kernel 试。
- **[Part of the Strassen algorithm can speed up matrix multiplication in a parallel pebbling game](https://arxiv.org/abs/2610.08929)**（`2610.08929`）：Partial Strassen 只用**一部分** Strassen 步骤，却比传统实现更快——关键在于它所需的**内存足迹可证明地小**，无论单线程还是多线程。数据上，一、二、三层深度的 Partial Strassen 与 BLAS 对比显示：**三层版本用 BLAS 的 80% 时间完成乘法，内存需求为 2.25×**，对足够大的矩阵理论改进为 **75%**；与经典 Strassen 相比，**随着矩阵规模增大，它因更低的内存消耗而越来越有优势**。作者同时开源了支持任意深度与矩形矩阵乘法的实现。对算子组：**Strassen 的问题从来不是乘法的次数而是中间结果的内存**——把递归限制在少数几层，就拿到了大部分收益又不吃下全部内存代价，这是分块 GEMM 之外一条可直接对比的路径。
