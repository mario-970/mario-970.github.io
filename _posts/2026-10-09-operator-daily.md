## TL;DR

- **工具链侧本窗口唯一一条正式 release 是 cuDNN Frontend v1.31.0**，两条实质更新都在「低位宽参战训练」这条线上：**FP4 投影权重可以训练了**（MXFP4 QKVG、NVFP4/MXFP4 输出投影都挂在 MXFP8 训练记录上，data-gradient GEMM 直接吃调用方转置好的 FP4，NVFP4 输出梯度用**两级 scale** 避免 block-scale 地板吃掉小梯度），以及 **GQA 梯度折叠先累积 FP32 partials 再转换**；SM107 gated attention block 从 v1.30 的推理扩展到训练（`GatedAttentionBlockBwd`）。其余是主机侧净收益：v1.30 的 prepared launch 铺满 dense / packed THD / paged / split-KV / block-scaled 全部前向家族，共享同一个 native binder，并加了进程内 compiled-plan memo。
- **稀疏注意力这期三篇打的是同一个靶子：稀疏掉 KV 之后，tile 反而喂不满了**。**QUILT** 抓的是相邻 query 选中的 KV 高度重叠——现有 kernel 各自独立处理 query，反复加载与反量化同一批 KV，于是把相邻 query **合起来执行**、用 `Shift-and-Compare Set Decomposition` 把不规则集合运算变成规则的数据并行原语并与注意力流水线重叠，kernel 延迟最多 **−55.1%**、处理的 KV 数据 **−55.9%**、TTFT **−36.8%**；**PageWeaver** 从另一头解——按**选中页的亲和度**把 query 分组成 union 以填满 Tensor Core tile，用一次有界 GPU 搜索产出 query ID、再由一个 ID-aware 的 two-CTA kernel 消费，**不物化重排后的 Q 张量也不产生跨页 partial**，FP8 KV 下 H200 上对 FlashInfer 拿到 **1.70×** 完整调用加速；**iCATS** 则指出不规则 cluster 尺寸带来的 padding 让 kernel 利用率掉下去，用 **tail-merging** 把尾部合并。三篇合起来说明一件事：稀疏注意力的账已经从「取多少 key」转到「取出来的 KV 怎么排布才不浪费 SM 上的 tile」。
- **数值格式这期有一条罕见的「负结果 + 可计算阈值」**：`FP8 is All You Need` 的 TME 模型把 Ozaki Scheme II 模拟 fp64 的时间算成「tensor core 项与 HBM 带宽项取 max，加每输出重建项」，却漏掉了**每输入的 deconstruction 成本**（每个 fp64 操作数在进 MMA 之前都要在 SIMT 上做 scaling、rounding、对 r 个模数逐一取模）。补上这一项后得到闭式的操作性强度阈值 **OI\* = c_q·r·P_fp64/(8·P_int)**，在 B300 上约 **0.56 FLOP/B**——低于它的 kernel 无论 tensor core 多快都赢不了原生 fp64。于是 GEMV、SpMV、低 batch GEMV 只有原生性能的 **0.3–0.9×**，7 点 stencil 是 **1.8×** 而非原论文声称的 3.1×；dense GEMM 不受影响。

## 一、CUDA 开源仓 Release Notes（算子）

### cuDNN Frontend

- **v1.31.0** — [链接](https://github.com/NVIDIA/cudnn-frontend/releases/tag/v1.31.0)（2026-10-08）：把 FROST attention 从推理推进到更多训练负载，并让重复的 graph 启动走共享的 native 参数绑定。**native SDPA 执行 + 有序张量绑定**：v1.30 引入的 prepared launch 这版铺开覆盖 dense、packed THD、staged conversions、paged attention、split-KV、block-scaled 输出与 output gate 等前向家族，graph / standalone / staged 三条路径共用同一套 prepared-host 契约，生产路径里 Python 侧的 forward framing 及其 fallback 分支已删除；**ordered graph bindings** 允许调用方直接传张量元组/列表配 `tensor_uids`，省掉每次调用重建 UID 字典（cuDNN 后端与 FROST 接受同一形式，`execute_plan_at_index` 也支持）；**native half-backward binding** 统一了半精度反向入口（量化反向与 standalone compact-GQA 反向仍各自持有显式 binder）。prepared launch 复用不可变的 geometry 与绑定元数据、每次调用读取当次传入的 buffer（含 64 位物理 stride/Stats 寻址、device-context 处理、以及输入变化的 CUDA Graph 重放）；另加一层**进程内 compiled-plan memo** 挡在持久化 cache 前面（同一 kernel/options/设备可不重新 trace、编译或读盘，cache 格式不变，`CUDNN_FRONTEND_COMPILED_CACHE_INPROCESS_MEMO=0` 关闭）。**gated attention block 反向**：v1.30 引入的实验性 SM107 gated attention block 这版支持训练，训练前向产出一份显式 saved record（覆盖 projection、可选 QK-RMSNorm、RoPE、SDPA、sigmoid gate、输出投影），`GatedAttentionBlockBwd` 对这份 record 求导——**BF16/FP16 反向**算输入、投影权重与归一化权重梯度，可选 gate-backward fusion 直接把 SDPA 的 delta 供上、可选 weight-gradient overlap 把两个权重梯度 GEMM 放到 side stream 上用显式事件依赖；**per-tensor FP8 反向**按原样使用 FP8 训练记录（设备端梯度量化、current/delayed 两种 scale 模式、FP8 投影 GEMM），**MXFP8 反向**用 block-scaled 投影 GEMM 与 **Rubin 的 MXFP8 SDPA backward row**，两者的 **GQA 梯度折叠都先累积 FP32 partials 再做最终转换**；**FP4 投影权重可训练**——MXFP4 的 QKVG 投影、NVFP4 或 MXFP4 的输出投影都通过 MXFP8 训练记录支持，data-gradient GEMM 消费调用方转置好的 FP4 产物而 weight-gradient GEMM 继续用 8-bit 操作数，NVFP4 的输出梯度转换用**两级 scale**避免小梯度掉到 block-scale 地板以下；packed sequences 支持 BF16/FP16 前后向，native FP8/MXFP8/FP4-weight 反向仍限 dense。概览里还提到新增 graph-attention API 与 JAX Kimi Delta Attention。对算子组：**FP4 正式参与训练（含梯度侧的 GEMM 与两级 scale）以及 GQA 梯度折叠的 FP32 累加，是这版最实质的两条**——低位宽不再只是推理格式，反向链路里的量化点、累加精度与 scale 层级都成了要按 kernel 对齐的实现细节。

## 三、arXiv 论文（算子内核）

**稀疏注意力与 KV cache 的 kernel 执行**

- **[QUILT: Rethinking Sparse-Attention Prefill through Shared Query Execution](https://arxiv.org/abs/2610.11134)**（`2610.11134`）：稀疏注意力省的是计算，但现有 kernel 往往**逐个 query 独立处理**，把相邻 query 共享的那批 KV 一遍遍重新加载与反量化。这篇的观察是**邻近 query 选中的 KV 重合度很高**，于是提出 QUILT：把相邻 query **合并执行**、复用共享 KV，直接砍掉冗余访存与计算。实现上有三处关键：`Shift-and-Compare Set Decomposition`（SCSD）把不规则的集合运算转成现代加速器擅长的**规则数据并行原语**，并与注意力计算**流水线重叠**以隐藏其开销；cascaded sharing 在多个粒度上分层捕获复用；tile-aware 执行策略在**共享粒度与硬件 tile 利用率**之间取平衡，并**有选择地截掉低重要度的 query 专属尾部**以消除用不满的 tile。LongBench 上跑 GLM-5.3 与 DeepSeek-3.2、分别在张量并行与序列并行下：相对当前最好的稀疏注意力 kernel，平均 kernel 延迟最多 **−55.1%**、处理的 KV 数据最多 **−55.9%**、TTFT 最多 **−36.8%**，精度损失可忽略。对算子组：**「复用」在 prefill 期的物理含义就是让相邻 query 共享同一次 KV 加载与反量化**——这要求 kernel 的调度单位从单 query 变成 query 组，而 SCSD 给出了怎么在不规则支撑集合上把这件事做成规则访存。
- **[PageWeaver: KV-Guided Query Unions for Sparse Attention](https://arxiv.org/abs/2610.11201)**（`2610.11201`）：动态稀疏注意力把每个 query 的 KV 支撑限制得很小，但**支撑小并不等于 GPU 干得高效**——query union 靠共享页加载来填满 Tensor Core tile，而它划不划算**取决于哪些 query 被分到一组**。PageWeaver 用**选中页的亲和度**来组 query 组，同时保持每个 query 原本的支撑与完整的输出所有权；一次**有界 GPU 搜索**产出 query ID，一个 **ID-aware 的 two-CTA kernel** 直接消费这些 ID，**不物化重排后的 Q 张量、也不产生跨页的 partial 输出**（另附一个直接做 KV-page union 的实现作为非局部复用与归约代价的对照）。FP8 KV 全程下，H200 的 Union8 实现在六份 capture 上相对被测 FlashInfer 路径拿到 **1.70×** 的几何平均完整调用加速；online regrouping 在五份 64K 上下文 capture 上再降 **3.26–7.66%** 延迟；整模型 prefill 吞吐比被测原生路径高 **7.88–14.36%**。作者也如实报告了边界：增量 regrouping 的收益小得多（32K/64K 上中位 **0.47–0.73%**，8K 上出现回退），且在 B300 上存在**准备开销 + 更强的原生 kernel 把优势吃掉**的情形。对算子组：**「稀疏」的收益要先扣掉分组本身的开销**——这篇真正贡献的是把 execution-group 复用与在线利用它的完整代价分离开来度量。
- **[iCATS: Fast Video Generation via Interaction-Aware Sparse Attention and Timestep-Adaptive Sparsity](https://arxiv.org/abs/2610.11302)**（`2610.11302`）：免训练的稀疏注意力是 DiT 上最实用的加速手段，但「估计重要性 → 导出稀疏 mask」这一步必然引入近似误差。iCATS 三处改进：重要性估计上，指出**按 query-key 点积交互聚类**比此前各自按特征相似度独立聚类更准，并把该目标重写成**一个廉价的二次型**；稀疏 mask 构造上，不改 top-p，而是观察到**不同去噪时间步对稀疏误差的容忍度不同**，改用 **SNR 引导的稀疏度调度**动态调整；硬件执行上，用 **tail-merging 策略**把不规则 cluster 尺寸造成的 padding 开销压下去，提升 GPU kernel 利用率。HunyuanVideo-T2V-13B 上 **2.03×** 加速、PSNR 31.017 dB，Wan2.1-T2V-14B 上 **1.55×**、29.301 dB。对算子组：**稀疏 mask 的不规则性最终一定会在 SM 上以 padding 的形式还回来**——tail-merging 是把这条账显式记出来并用调度抹平。
- **[WAM-Cache: Staleness-Bounded KV Reuse for Efficient World Action Models](https://arxiv.org/abs/2610.11401)**（`2610.11401`）：World Action Model 用预训练视频 DiT 的表征去条件化 action expert，闭环控制里视频 DiT 每个 chunk 都要跑一次、把当前观测编码成逐层的 KV 供 action expert 查询，**这次 prefill 占了每 chunk 的大头，而现有免训练加速手段都还让它保持稠密**。WAM-Cache 跨 chunk 保留逐层 KV，只重算一个**稀疏的 refresh 集**。值得记的是它的负结果：**「刷新视觉上漂移了的 token」这条直觉启发式即使配上能预知真值 KV 漂移的 oracle，也远低于稠密基线**——决定下游动作精度的**是 action expert 往哪里注意，而不是什么动过**。因此 refresh 集改为 action expert 的**交叉注意力**并上**视觉潜变量 surprise**，再加一条**严格的 age 上界**抑制误差累积。Fast-WAM 上，RoboTwin 2.0、LIBERO 与真机实验里视频 DiT 的 prefill FLOPs 降 **32–42%**，仿真中与稠密策略差 **0.7–1.8 个百分点**、真机上 2.5 个点。对算子组：**KV 复用的选择准则要按「下游谁在读」来定，而不是按「上游谁变了」**——这条与 10-08 期 SPIN 把账从 core attention 移到 indexer 是同一类重新定位瓶颈的思路。
- **[VFold: Symmetry-Aware Cross-Layer Value Cache Compression](https://arxiv.org/abs/2610.12338)**（`2610.12338`）：长上下文下 KV cache 主导显存，利用**层间 cache 相似性**压缩是现成方向，但多数做法要求改动模型结构并在解码时引入可观开销。VFold 提出**对称性感知的 value cache 合并**策略：在不带来有害性能退化、也不增加解码期结构开销的前提下压缩 value cache，并且能**与既有压缩技术叠加**——和高压缩比量化或 key cache 剪枝组合，可以到达任一方单独达不到的压缩比而只增加极小代价。对算子组：**value 侧存在一块被长期忽略的可利用容量**——key 侧有剪枝、量化都已经做了不少，value 侧的层间冗余此前基本没被当成一等结构来用。

**低位宽量化**

- **[Rounding in Preconditioner Space: Redesigning 4-bit AdamW Optimizer-State Quantization](https://arxiv.org/abs/2610.12444)**（`2610.12444`）：量化 AdamW 的优化器状态省的是持久化存储，但**量化误差会顺着 moment 的递推传下去、扰动后续的自适应更新**。这篇换了一个坐标来设计：**rounding space**——量化器在相邻两个重建电平之间做选择时所在的那个坐标系。对二阶矩，**对着零附近那个量化单元做局部分析**即可看到：**状态上的平均误差小，并不蕴含下一步 preconditoner 上的平均误差小**；再借一个一维二次构造说明，在 state space 与 preconditioner space 下取整会给出**定性不同的优化动力学**。据此给出两条路线：**ZIP-SR**（Zero-Inclusive Preconditioner-space Stochastic Rounding）在二阶矩码本里**保留零**，并在 **preconditioner 空间**计算随机取整概率；**ZE-EDEN** 则用**排除零**的二阶矩码本、再对量化后的二阶矩块做重缩放，以缓解正量化地板造成的 preconditioner 失真。两者的一阶矩都用 4-bit NormalFloat（NF4），并在训练最后 **10%** 对 LM-head 的一阶矩做定向随机取整。GPT 与 Llama 风格预训练、**130M 到 2.7B** 参数量：两种配置在每个评测规模上都缩小了 TorchAO 4-bit AdamW 相对 32-bit AdamW 的平均验证损失差距，最大缩小 **70%**；全参数 SFT 下验证损失低于 TorchAO 且接近 32-bit。对算子组：**优化器状态的量化不该在参数空间做取舍判据**——真正决定下一步更新质量的是 preconditioner，取整概率因而应当在那里计算。
- **[When Lower Reconstruction Loss Hurts: Distributionally Robust Refinement for Low-Bit LLM Quantization](https://arxiv.org/abs/2610.11226)**（`2610.11226`）：仅权重的 PTQ 高度依赖**最小化重建损失**来保住低精度下的模型质量。这篇给出了一个直接的否定：**最小化该损失所偏好的权重，并不必然带出更好的下游表现**，甚至反例就发生在**同一份校准数据**上——重建损失更低的权重，在同一校准数据上的表现可以更差；其分析进一步说明，**当输入激活分布发生变化时，那些在校准数据上重建损失更低的权重，损失反而可以更高**。据此提出的 DRQ 是一个事后精修流程，**在一组受约束的输入激活分布上最小化最坏情况重建损失**；它只在**已有的量化网格内**调整代表量化权重的整数码，**量化参数与推理算子都不变**。实验上 DRQ 提升了六种代表性 PTQ 方法（含 AWQ、GPTQ、ParoQuant）量化出的模型，稠密与 MoE 均有效，且**不增加推理开销**。对算子组：**这是「整数码可以事后重排、而网格与 kernel 不动」的一条干净证据**——精修落在码字上，意味着它不需要新的算子，只需要重跑一次编码。
- **[Deflating the Hessian: Rank-4 W4A4 Quantization for Multimodal Diffusion Transformers](https://arxiv.org/abs/2610.11315)**（`2610.11315`）：在 diffusion transformer 上，低秩支路能把 4-bit 权重-激活（W4A4）PTQ 的损失找回来——把每个权重分解成**低位残差 + 高精度低秩分量**。既有低秩 PTQ 对此有两条毛病：**低秩补偿与残差量化被分开优化**，因而往往需要更高的秩；或者依赖二阶权重更新却**没有显式建模激活量化误差**，而这一项在 4 位下格外显著。这篇把低秩辅助的 W4A4 PTQ 建为**一个耦合的校准问题**并从联合目标推导求解器：**消去输出侧的低秩因子**后得到一个「**deflated Hessian**」，它会把**已经由低秩分量解释掉的残差误差折价**；同时引入**激活噪声代理**来压制激活量化误差。五个 diffusion 骨干上，rank-4 稳定优于 rank-4 SVDQuant；在 SANA-1.6B、FLUX.1-schnell、FLUX.1-dev 上以**小 8× 的秩**超过 rank-32 SVDQuant，且量化速度快 **6.25×**；Qwen3-8B 上 rank-4 把 MMLU 从 61.50% 提到 **68.17%**（对 rank-32 SVDQuant）。对算子组：**「低秩 + 低位残差」的度量的关键在如何处理重复计账**——把已被低秩分量吃掉的那部分残差从 Hessian 里折掉，秩才降得下来；秩越低压在 kernel 侧的额外算力就越小。
- **[Read What Matters: Query-Adaptive Quantization for KV Caches](https://arxiv.org/abs/2610.11245)**（`2610.11245`）：KV 条目是**在未来的 query 还未知时**就被存下的，而每个解码 query 需要的精度位置并不相同。这篇把这个错配拆成**两个独立预算**：保留多少位，与每个 query 实际取回多少位。ReadKV 把每个 key 和 value 存成**渐进码**（progressive code），其**前缀支持不同的重建精度**；对每个 query，先用它**分配 key 的通道前缀**、用重建出的 key 算注意力，再用这次注意力**分配 value 的 token 前缀**，而**已存储的条目不改动**。每一级都在固定预算下优化一个标定过的失真目标，论文证明了在**递减细化增益**下的分配是精确最优的，并把目标与注意力输出误差联系起来；还给出一个有限维注意力族，证明**在同一读取预算下，query 相关的访问严格优于任何 query 无关的读取器**（即使对手的编解码器不受限）。六个基座模型上，从 8-bit cache 里平均读 4 bit 使 C4 困惑度最多升 **0.66%**，而逻辑读取量约为 16-bit cache 的四分之一、保留容量为其一半；在同样的 payload-read 预算下，它稳定优于「存 4 bit 并整读 4 bit」。A10G 上 8K token、batch=1、单层的负载中，一个受限的 8-bit ReadKV 读取器在 2-bit 平均 payload 预算下比被测 TurboQuant 编解码器**延迟低 39%**。对算子组：**「存多少位」与「每步搬多少位」是两个可以分开调的旋钮**——长上下文解码的瓶颈是每步搬运的字节数而非权重，渐进码让读取量而非存储量成为一等预算。
- **[SparseDecoding: Decoding-Aware Pruning for Accurate and Efficient LLM Inference](https://arxiv.org/abs/2610.12327)**（`2610.12327`）：解码阶段是访存瓶颈，Hessian 引导的逐层免训练剪枝之所以能加速，是因为它减少了**解码时从显存读出的非零参数**。但这条路线有两个漏洞：其一，典型做法用**预先收集的自然序列**算 Hessian，而解码时喂给模型的是**它自己生成的 token**，两者存在分布漂移，**自然序列上算出的 Hessian 与生成序列上的不同**，进而让生成期的激活分布偏离剪枝时所用的那套、损伤剪枝后模型的表现；其二，真正带来加速的既有 LLM 剪枝方法大多针对**稀疏矩阵-矩阵乘（SpMM）**，而对**主导解码的稀疏矩阵-向量乘（SpMV）**支持有限。SparseDecoding 两头都补：算法侧用**稠密模型自回归生成过程中**逐层收集的激活来构造校准矩阵（**排除 prefill**），让剪枝目标与解码激活对齐；系统侧实现了一个**带位掩码索引与定步长遍历的优化 N:M 稀疏矩阵-向量 kernel**。Llama-3.1-8B、Llama-3.3-70B、Qwen3-14B/32B 上，长文本生成基准稳定优于标准固定文本校准，A100 上端到端墙钟解码加速最多 **1.48×**。对算子组：**解码期只有 SpMV 算数**——把 SpMM 的稀疏格式直接搬到解码上，收益会被访存模式吃掉；而校准矩阵该由「模型自己走出来的分布」产生，这条与 10-08 期 OnlineQAT 的 on-policy 恢复是同一个观察的两个场景。

**线性注意力与 KV 量化的桥接**

- **[Bridging KV-Cache Quantization and Linear Attention: From Theory to Pretrained Weight Migration](https://arxiv.org/abs/2610.11214)**（`2610.11214`）：KV-cache 量化把每个 KV 条目压成离散码但**保留全部条目**，线性注意力把多份历史 KV **循环聚合进一个定长连续状态**但会引入干扰——这篇问的是**能否在同一个机制里同时做「逐 KV 压缩」与「多 KV 聚合」**。答案是 RAM-Net：通过**在一个离散地址空间上的软分配**充当这座桥，这些分配决定的是**与每个地址相关联的连续 slot 状态如何被循环更新**。在一个受限的 RAM-Net 构造下，论文证明**软地址分配把硬量化匹配扩展成一种可分离的读写重叠**，它能**局部逼近全注意力的相似度**并支持循环聚合；这些联系进一步给出了基于**软量化中间构造**的 Transformer→RAM-Net 权重迁移路径。九个 0.3B–7B 的预训练 Transformer 上，每个模型只用 **500M token** 的预算，RAM-Net 在六个常识与知识任务上平均找回教师相对随机猜测的 **87.1%** 精度增益。对算子组：**地址空间上的软分配同时是「码本」和「循环状态」**——这条桥意味着量化注意力 kernel 与线性注意力 kernel 不必是两套实现，读写重叠的那部分可以共用。
- **[V-CoLA: Vision Token Compression with Linear Attention](https://arxiv.org/abs/2610.11251)**（`2610.11251`）：VLM 的计算开销主要来自视觉 token 占满输入序列，于是视觉 token 压缩成为关键方向；但随着**混合线性注意力**架构（如 Qwen3.5）出现，为 softmax 注意力设计的既有压缩方法**难以迁移**——论文的分析显示**基于注意力与基于相似度的方法都会出现明显退化**。V-CoLA 是专门为线性注意力设计的免训练 token 压缩框架：用一个**唯一性感知的重要度判据**挑出关键视觉 token，配一个**自适应 token 合并策略**完成压缩，且所有部件都在实现层做了适配以**兼容线性注意力的 chunk 式并行**。多个基准上，只保留 **50.0%** 视觉 token 时达到原性能的 **99.5%**，低至 **12.5%** 时仍有 **88.0%** 以上，prefill 加速 **1.86×–6.15×**。对算子组：**换掉注意力机制就换掉了「什么 token 重要」的定义**——线性注意力下 chunk 内部没有 softmax 的归一化结构，压缩判据必须重新设计，且实现要顺着 chunk 并行来写。

**卷积与分解原语**

- **[SV-TAD: Native Sparse Convs for Efficient Temporal Action Detection](https://arxiv.org/abs/2610.11579)**（`2610.11579`）：为把十亿参数的 ViT 用到长视频上，近期做法是冻结骨干、只训轻量卷积适配器——参数高效，但**不减少推理期计算**。token 选择能砍注意力开销，**却破坏了卷积适配器所依赖的空间网格结构**，逼出一个昂贵的稠密重建，把大半潜在加速又还了回去。这篇引入**原生稀疏二维卷积**这一原语，让这类适配器**第一次能直接在动态剪枝后的 token 集合上高效工作**：接进 SV-TAD 后，VideoMAEv2-L 的计算量降 **64%**、推理快 **2.2×**，仍在 THUMOS-14 与 ActivityNet-1.3 上保持 SOTA；扩到 InternVideoNext-L 时以约**一半的计算**超过此前 SOTA；稀疏形式还天然支持辅助任务 token，改善了 ATTACH 上的细粒度装配检测。对算子组：**「剪枝后要不要还原成稠密」是个 kernel 设计决策**——稀疏卷积把 token 集合当作一等公民直接消费，代价是必须自己处理不规则邻域；这也解释了为什么此前这类适配器的加速大多停在离线。
- **[MCL: Meta Convolution Layer](https://arxiv.org/abs/2610.11117)**（`2610.11117`）：动态卷积让 CNN 按输入内容调整卷积核，但它把**有效核写成少数基核的线性混合**——混合规模一大，表达力受限且优化变难。这篇回到函数视角，提出 Meta Convolution Layer：**直接把卷积核建模成输入条件的函数 W(x)**，用**高阶多项式展开**实现，并以借鉴深度多项式网络的**嵌套残差块**搭出一个结构化的多项式元网络来**生成单个输入自适应核**，从而把表达力与「基核的显式数量」解耦、同时缓解训练不稳定。MCL 是可与标准卷积叠加的插件，CNN 与 transformer 骨干都能接入：ResNet-18/50/101 在 ImageNet 上 Top-1 分别提升 **6.61% / 3.42% / 3.05%**。对算子组：**核从「混合」变成「按输入生成」**——算子侧多了一次元网络的推理，少了一次基核加权；是否划算取决于元网络相对主卷积的比重，这正是自定义 kernel 可以直接对比的账。
- **[D-SLR: The Disjoint Row-Sparse plus Low-Rank Decomposition](https://arxiv.org/abs/2610.10636)**（`2610.10636`）：为重建而压缩矩阵仍默认用截断 SVD——只用一个低秩结构去逼近数据；常见做法是再加一个**与之重叠**的行稀疏分量以进一步压低残差，但解这个联合问题往往需要迭代求解器并调正则参数。这篇提出的 D-SLR 是一个**截断 SVD 的闭式替代品**，且效果不劣于后者：它限制每一行**要么被原样存储、要么由低秩拟合近似，绝不两者兼有**。在平方误差下这一限制**不带来任何代价**——联合最优解可以在每个非平凡秩与存储行数（形状）下以**更少的参数**通过不相交的形式达到；当存储行数为零时 D-SLR 退化为截断 SVD，因此同等代价下永不更差。算法会**把整条「误差对参数」的权衡曲线打出来**，之后再按给定的误差目标或参数预算（或某个选择规则）挑解，**整张网格加求解一共只花三次 SVD、无调参无正则**；并给出每个形状上一个**无假设的事后下界**，从而对任何其他秩与存储行组合的潜在收益给出**可计算证书**。合成数据与真实数据（LLM embedding 表、网络流量、高光谱图像）上验证了增益并量化了该证书。对算子组：**「稀疏 + 低秩」不必是迭代优化问题，也可以是一次闭式分解**——而且不相交约束在平方误差下免费，这对之后按行分派的 kernel 是更友好的布局。
