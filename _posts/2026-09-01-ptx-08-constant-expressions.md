## TL;DR

常量表达式用 C 的运算符把常量串成算式，在**编译时**算好。求值规则的主线只有一条：每一步的结果类型要么是 `.s64` 要么是 `.u64`，而这个类型决定 `>>`、`/`、`<` 这类「看符号下菜」的运算怎么算。规则比 C 简化——只留 64 位整数、去掉整数与浮点之间的 cast，并把 `%`（余数）和移位这些 C 里「实现相关」的灰区全部钉死。读完这期，你就能预测任意一个常量表达式会被编译器算成什么值。

## 一、概念铺垫：为什么要把「怎么算」钉死

写代码时，有些值不想硬编码成一个裸数字，而是想「写成一个算式，让编译器去算」。比如一个地址偏移 `4 * 4`、一个掩码 `(1 << 5) - 1`、一个条件值 `(x > 0) ? 1 : 0`。PTX 允许你把这些算式直接写在操作数的位置，编译器在编译期把它算成一个确定的常量。

但「编译时算」有个前提：**怎么算必须唯一确定**。C 的常量表达式求值有一些灰色地带——负数的右移是算术还是逻辑、负除数的余数怎么取、溢出怎么办，这些在不同实现里可能不同。PTX 的做法是把它们全部钉死：给每个运算符、每种类型组合都规定一个明确的结果，不给实现留自由度。这一节（§4.5.4–4.5.6）讲的就是这套钉死的规则。

而这套规则的主线，就是**类型**。一个常量表达式里，每个字面量都有类型（上一期讲过：`.s64` 或 `.u64`），每一步运算又会产出一个新类型。有符号还是无符号，决定了一个运算符——尤其是右移 `>>`、除法 `/`、比较 `<`——的语义。所以整个求值规则，本质上是在回答一个问题：**每一步算出来，结果是什么类型**。

## 二、文档语义：表达式能写什么、怎么算

### §4.5.4 能写哪些运算

常量表达式能用的运算符分两层。**所有**常量表达式都能用：常量字面量、一元加减、基本算术（加减乘除）、比较运算符、条件三元 `?:`、以及括号。**整数**常量表达式额外还能用：一元逻辑非 `!`、位反 `~`、余数 `%`、移位 `<<` `>>`、位运算 `&` `|` `^`、逻辑运算 `&&` `||`。

一个明确的不支持项：**整数和浮点之间不能 cast**（`(.s64)`、`(.u64)` 这种整数内部转换可以，但 `(int)1.5` 或 `(float)1` 不行）。这是 PTX 比 C 收紧的地方。

求值顺序沿用 C 的运算符优先级。先看图，从高到低：

```text
常量表达式运算符优先级（§4.5.4 Table 4，从高到低）：

  ( )                  括号
  + - ! ~              一元：正、负、逻辑非、位反
  (.s64) (.u64)        类型转换
  * / %                乘、除、余
  + -                  加、减
  << >>                左移、右移
  < <= > >=            有序比较
  == !=                相等、不等
  &                    位与
  ^                    位异或
  |                    位或
  &&                   逻辑与
  ||                   逻辑或
  ?:                   条件三元
```

这张表和 C 完全一致，不必背，用到时回来查即可。

### §4.5.5 求值规则：类型怎么流转

这是本节的核心。规则可以收敛成一条主线加四个「看符号」的坑。

**主线：通常算术转换（usual arithmetic conversions）。** 一句话——**如果任一操作数是无符号，就把两个操作数都转成无符号**。文档叫它「归一化」，是 C 那套规则的简化版（PTX 只处理 64 位整数，所以转换只有「有符号 ↔ 无符号」这一种）。加、减、乘、除、位运算、比较这些二元运算，都要先做这个转换，再算。

**坑一：右移 `>>`，有符号补符号位，无符号补 0。** 右移的结果类型跟着第一操作数走（第二操作数一律当无符号）。第一操作数是 `.s64` 就做算术右移（高位补符号位），是 `.u64` 就做逻辑右移（高位补 0）。同样的位模式，两种解释差出一个符号位：

```text
  -8 >> 1           = -4             .s64：算术右移，补符号位 1
  0x…F8 >> 1        = 0x7…FC         .u64：逻辑右移，补 0
```

**坑二：比较 `< <= > >=`，无符号参与时先转换再比。** 比较也做通常转换，所以一个「负的有符号数」和「无符号数」比，负数会先被转成一个巨大的无符号数。经典例子：

```text
  -1 < 1            = 1（真）         有符号比较
  -1 < 1U           = 0（假）         通常转换：-1 变成巨大的无符号数
```

第二行里 `1U` 无符号，触发通常转换，`-1` 被转成无符号——在 64 位下它是 `0xFFFFFFFFFFFFFFFF`，比 `1` 大得多，所以结果是假。这正是「类型决定结果」最直观的体现。

**坑三：除法 `/` 也看符号。** 有符号除法按有符号算（`-8 / 2 = -4`），一旦某个操作数无符号，通常转换后就是无符号除法——`-8 / 2U` 里 `-8` 被转成巨大的无符号数再除以 2，结果不是 `-4` 而是一个天文数字。

**坑四：余数 `%` 把操作数当无符号。** 这是 PTX 明确和 C 划清界限的地方：C 里负数取余的行为是实现相关的，PTX 直接把 `%` 的操作数当作无符号来算。所以 `-5 % 2` 在 PTX 里，是把 `-5` 当无符号（巨大的正数）再对 2 取余，和你在 C 里预期的 `-1` 不一样。

除了这四个坑，还有几条「结果类型」的固定规则值得记住：一元逻辑非 `!`、逻辑与或 `&& ||`、相等 `== !=`、有序比较，结果都是 `.s64` 且值只能是 `0` 或 `1`；一元位反 `~` 把源当无符号、结果是 `.u64`；移位的结果类型跟着第一操作数。条件运算符 `?:` 要求第一操作数是整数，后两个要么都是整数、要么都是浮点，结果取后两者通常转换后的类型。

### §4.5.6 一张总结表

文档在 §4.5.6 用一张表（Table 5）把上面的规则压平。这里只摘最关键的一列——**结果类型**：

| 运算符 | 结果类型 |
|--------|----------|
| `+ - * /`（整数） | 通常转换后的类型 |
| `/` 里若含无符号 | 无符号 |
| `%` | 操作数当无符号 |
| `<< >>` | 同第一操作数 |
| `! && \|\| == != < > <= >=` | `.s64`（值 0 或 1） |
| `~` | `.u64` |

把这张表和上面的「四个坑」对照着看，就抓住了求值规则的全部：**二元运算先做通常转换，然后「看符号」的运算符按转换后的符号性计算，结果类型跟着规则走**。

## 三、反汇编与讲解：表达式被折叠成一个立即数

常量表达式是在**编译时**求值的，所以真实反汇编里看不到算式本身，只能看到它的「计算结果」。下面用一个内核验证这一点。

CUDA 源码：

```cuda
__global__ void constExprKernel(int *out) {
    int i = threadIdx.x;
    out[i] = (42 * 2 + 1) << 2 | 0x3;
}
```

真实 PTX（Compiler Explorer，NVCC 13.3.0，`-arch=sm_90a -ptx -O3`，指令原样贴入）：

```nasm
        mov.u32         %r1, %tid.x;            // int i = threadIdx.x;
        mul.wide.s32    %rd3, %r1, 4;           // i * 4（字节偏移）
        add.s64         %rd4, %rd2, %rd3;       // out[i] 的字节地址
        mov.u32         %r2, 343;               // 整个表达式被算成了 343
        st.global.u32   [%rd4], %r2;            // out[i] = 343
```

注意 `mov.u32 %r2, 343` 这一行：源码里那个 `(42 * 2 + 1) << 2 | 0x3` 的算式，在 PTX 里只剩下一个光秃秃的立即数 `343`。我们来验算一遍编译器的结果：`42 * 2 + 1 = 85`，`85 << 2 = 340`，`340 | 0x3 = 343`。整个算式的每一步都在编译时完成，最终固化成一条 `mov` 的立即数——这就是「常量表达式编译时求值」最直观的证据。

顺带说一句：常量表达式不止能出现在「等号右边」，还能直接写进 PTX 指令的操作数里（比如地址偏移写成 `[%rd + 4*4]`）。但 nvcc 生成的 PTX 通常已经把这种算式折叠好了，所以我们看到的多半是「已经算好的数字」而非算式本身。

## 小结

- 常量表达式用 C 的运算符串起常量，在编译时求值；规则比 C 简化——只 64 位整数、不支持整数↔浮点 cast。
- 主线是**通常算术转换**：任一无符号，两个都转无符号。
- 四个「看符号」的坑：右移 `>>`（有符号补符号位、无符号补 0）、比较 `<`（先转换再比）、除法 `/`（无符号除法结果迥异）、余数 `%`（操作数当无符号，和 C 不同）。
- `! && || == !=` 和比较的结果都是 `.s64`（值 0 或 1）；`~` 结果是 `.u64`；移位结果类型跟第一操作数。
- 真实反汇编里，`(42*2+1)<<2|0x3` 被折叠成一个立即数 `343`——编译时求值的最直接证据。
