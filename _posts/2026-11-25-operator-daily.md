- **[Joule is FLOP: Optimizing Tensor-Core Kernels Beyond Latency Hiding at the GPU Power Wall](http://arxiv.org/abs/2611.32440v1)**（`2611.32440`，cs.DC，11-24）：当 tensor-core kernel 的平均板卡功耗贴近 GPU 功耗上限时，运行时间约等于每次调用的能耗除以该上限——**被计算掩盖了延迟的数据搬运照样耗能**，减少这部分流量即使不减少周期数，也能抬高可持续频率、缩短执行。Joule 把硬件事件计数、数据通路的物理能耗与跨电压域的非线性电压缩放合成成本模型，在功耗上限下解出可持续频率与运行时间；再叠加跨存储层级与跨 die 的数据搬运下界，得到「功耗感知的光速」（PSoL），把结构性差距与实现差距分开量化。该分析直接指导两类优化：在 B200 上用满 TMEM 容量的宽 tile kernel，配细粒度异步轮转把累加器读回与 tensor-core 计算重叠；以及同时权衡读共享、局部性与负载均衡的功耗感知空间/时间 tile 调度。给定实测事件计数，模型在 B200 上的平均能耗预测误差 **0.69%**。60 个 dense-layer shape 上，相对穷举挑选的 cuBLAS 算法几何平均快 **4.94%**（B200）、**6.64%**（H100 NVL）、**2.12%**（RTX PRO 6000）；8 块 B200 上的 fused Mega-MoE 相对上游 DeepGEMM（die-local expert weights）提升 **2.60–5.17%**。作者称论文发表后开源。
- **[DeCo-Attention: Decompose to Compensate for Low-Precision Attention](http://arxiv.org/abs/2611.32035v1)**（`2611.32035`，cs.CV，11-24）：视频扩散 Transformer 里数万 token 的自注意力主导生成时间，且随序列长度平方增长；用 GPU 的 FP4 矩阵乘本可提速，但 Q、K 的 4-bit 舍入会引入大误差，而 softmax 的指数会放大 QK^T 的误差——作者证明该项主导了整个注意力的误差。DeCo-Attention 是免训练的训练/系统协同设计：用 per-head 特征分解找出 Q、K 舍入误差集中的少数主方向，把轻量补偿项作为**额外通道**拼到 Q、K 上，于是 FP4 的 QK^T 在算注意力分数的同时修正自己的舍入误差；QK 一旦跑在 FP4，softmax 就成了新的瓶颈，因此又对 softmax 做了优化，让 FP4 的算力增益真正转化为端到端加速。实现上 QK 用 FP4、注意力其余部分在 GB300 与 VR200 上用 FP8，在 RTX PRO 6000 上则全部 FP4。Wan2.2 上三种配置的注意力 kernel 分别比 BF16 快 **2.13× / 2.49× / 2.82×**，整段生成快 **1.55× / 1.68× / 1.80×**；四个视频生成模型上，FP8 配置的 LPIPS 与前序 8-bit QK 方法相当，全 FP4 配置的 LPIPS 低于前序全 4-bit kernel。
- **[FlashQLA: Efficient Context Parallelism for Gated DeltaNet](http://arxiv.org/abs/2611.32039v1)**（`2611.32039`，cs.LG/cs.DC，11-24）：Gated DeltaNet 靠循环状态更新取得线性复杂度，但 chunk 之间的顺序依赖限制了并行度——长上下文、小 batch 或单卡 head 级并行不足时尤其明显。FlashQLA 是面向 GDN 的上下文并行执行框架：用 decay-aware 的边界状态预处理压低跨卡边界的准备开销；Dual CP 在多个并行层级之间共享 summary 计算，把序列并行铺到更多 GPU 上；再加负载自适应的 Auto CP 与 CP-aware 的 kernel 协同设计。单卡上相对 Flash Linear Attention（FLA）前向快 **1.7–3.1×**、反向最高 **4.4×**；8 卡、上下文长至 100 万 token 时，Dual CP 相对 FLA KCP 前向最高 **4.8×**、前向+反向合计 **4.4×**。
- **[Generalized Tensor Parallelism: Powering Trillion-Parameter LLM Training at 10+ EFLOP/s](http://arxiv.org/abs/2611.32057v1)**（`2611.32057`，cs.DC，11-24）：作者指出五种常用并行（data / tensor / sequence / context parallelism 与 FSDP）在 linear 层上都是同一个框架的特例——generalized tensor parallelism（GTP）：每层的参数与激活都被切分，且任一方都可先 all-gather 再物化使用。这个视角的关键差异在调度粒度：FSDP 把参数 all-gather 当作整个 Transformer block 之前的一步，先抬高峰值显存、又推迟了其后的 GEMM；GTP 把它看作矩阵乘某一个输入上的可选预处理，因此可以**按 GEMM 而不是按 block** 调度 all-gather——发得足够早以掩盖通信、又足够晚以限制显存。实现在 NVIDIA/Megatron-LM 开源：内部 2T 参数 MoE 在 12,288 块 GB300 上达到 **13.0 model EFLOP/s**、弱扩展效率 **98%**，并在 512 卡上跑 100 万 token 序列；256–1024 卡区间，三个 MoE 模型上吞吐为 Megatron-FSDP 的 **1.05–1.55×**，DeepSeek-V4-Pro 代理模型上为调优过的 3D 并行（含流水线并行）方案的 **1.27–1.31×**。
- **[Shifter Quantization: Compact Representations for Native Integer Computation](http://arxiv.org/abs/2611.33080v1)**（`2611.33080`，cs.LG，11-24）：分组量化能在低位宽下保住精度，但「每组一个 scale」使标准整数 MMA 无法覆盖完整点积——要么退化成低效的组内小 MMA，要么先把操作数反量化回浮点。Shifter Quantization（SQ）换了个思路：通过**追加并移位共享位**，把分组量化后的权重重建为原生位宽的整数操作数，使一个常规整数 MMA 就能跨组完成点积；其变体 Shifter Integer（SHI）进一步把格式压到可直接用 INT4 kernel。以投影误差与 KL 散度衡量，SQ/SHI 优于标准分组量化，解码与 prefill 实测也更快：2-bit 下 SQ2/SHI2 在 Q2_K checkpoint 上的 4096-token prefill 吞吐是 llama.cpp 的 **2.71–3.77×**，WikiText-2 KL 降低 **6.6–7.8%**；4-bit 下 SQ4 各模型与 prompt 长度上为 NInfer 分组整数基线的 **1.43–2.47×**，KL 低 **24–40%**；8-bit 下 SQ8 单 batch prefill 吞吐比 vLLM 在线 FP8 高 **27.4%**、KL 低 **72.7%**。
- **[RankServe: Rank-Aware CPU-GPU Scheduling for Memory-Constrained MoE Serving](http://arxiv.org/abs/2611.31869v1)**（`2611.31869`，cs.DC，11-24）：MoE 的低秩压缩能压低专家池的显存占用，但压缩后各专家的秩不同，存储、传输与执行成本随之不等；显存受限时，仅凭专家热度与传输代价已不足以决定哪些专家值得常驻 GPU。RankServe 的做法是把「常驻 GPU」与更便宜的非常驻路径（在 CPU 上算，或传权重上来再算）放在每个专家各自的秩与 token 负载下比较，把估算出的节省按 routing 需求累加，再按**每字节节省**排序决定常驻集合；常驻状态按近期 routing 历史更新，miss 路径按当前 token 负载选择，并允许临时在 GPU 上执行而不做 cache admission。运行时支持可变秩，用 grouped matmul 直接算异构因子，无需按最大秩补齐。在 vLLM 上实现，单机 CPU-GPU 平台、三个 MoE 模型、batch 1–32 五档，相对每种配置下最快的基线，TTFT 几何平均快 **1.69–2.29×**、TPOT 快 **1.71–2.48×**。
- **[Accelerating Equivariant Interatomic Potentials for Molecular Dynamics through Radial tabulation and Kernel Fusion](http://arxiv.org/abs/2611.31865v1)**（`2611.31865`，cond-mat.mtrl-sci/cs.PF，11-24）：等变机器学习原子间势（MLIP）精度接近量子化学，但算力与显存开销限制了分子动力学能跑的长度与时间尺度；即便张量积（TP）已被加速，NequIP 卷积中**逐边的径向权重求值与存储**仍是这两项开销的主因。JET-MLIPs 是可套用到预训练 NequIP 家族势函数、无需重训的 GPU 后端：用分段三次 Hermite 查表替换径向 MLP，并把查表、球谐、TP 与近邻聚合**融合进单个 kernel**，力计算过程中不再物化逐边径向权重与 MLP 中间量。在 5632 原子的液态电解液上，对 SevenNet、MACE、NequIP-OAM、Nequix、EquFlash 五个家族的 15 个已发布势函数，单块 H200 上 LAMMPS 每步耗时快 **1.5–5.9×**、峰值显存降 **2.4–24×**（相对各自已有的 TP 加速后端），且保持 fp32 精度与动力学稳定性；由此可在单卡上对约 10⁴ 原子体系做多纳秒的输运性质模拟。
- **[MXFP4 for LLM Inference: Complementary Post-Training Quantization Techniques and Their Interactions](http://arxiv.org/abs/2611.32873v1)**（`2611.32873`，cs.LG/cs.AI，11-24）：microscaling 格式靠每 16 或 32 个元素共享一个 scale 来实现激进低精度，但其精度取决于数值格式与 rotation、PTQ 算法、scale 选择三者的相互作用。作者在 6 个 LLM、三种格式（MXFP6 / MXFP4 / NVFP4）上系统变化 Hadamard rotation 粒度、PTQ 算法与 scale 选择策略，核心结论是**配方随格式而变**：MXFP4 与 NVFP4 都能支撑可用的 4-bit 推理，但让一个受益的技巧未必能迁移到另一个——MXFP4 显著受益于 rotation 与带误差校正的 PTQ，NVFP4 从 rotation 得到的收益较小，与其更细的 scale 粒度已经吸收了块内变化一致。据此提出 Midmax：一种免标定的 scale 选择策略，专门缓解 2 的幂次块 scale 的截断误差，在多数 MXFP4 配置上提升精度。MXFP6 激活配 MXFP4 权重可找回 4-bit 下损失的大部分精度，Llama-3.1-8B 上达到或超过其内部 BF16 基线。另一项消融显示：给 MXFP4 加上 NVFP4 固有的 per-tensor macroscale 并不改善平均精度，说明仅靠全局重缩放无法解决 E8M0 块 scale 对 MXFP4 的限制。
