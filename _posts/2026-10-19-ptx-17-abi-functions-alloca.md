> 本文是 [PTX 专栏](/ptx/) 第 17 期，对应官方文档 §7.1–7.3（含 §7.1.1）。

## TL;DR

PTX 不直接暴露某种固定的调用约定、栈布局和 ABI，而是提供一层较高的抽象，支持多种 ABI 实现。函数用 `.func` 声明/定义：声明给出「可选返回参数 + 函数名 + 可选输入参数」的接口，定义再加上函数体；函数必须先声明或定义再调用。`call` 把控制权交给被调函数并隐式保存返回地址，`ret` 返回到 `call` 之后。标量和向量基类型参数可以直接用 `.reg` 寄存器表示；结构体/联合体会被扁平化成寄存器或 `.param` 空间的字节数组，按值传递时用 `.param` 字节数组。使用 ABI 时 `.reg` 形参至少 32 位，子字标量要提升到 32 位或改用 `.param` 字节数组。实参的 `st.param` 必须紧邻 `call` 之前，返回值的 `ld.param` 必须紧邻 `call` 之后，且不能带谓词。§7.2 说明变参函数的旧支持已从规范中移除，PTX 6.0 起可以用「无长度数组参数」实现变参。§7.3 的 `alloca` 在当前线程的 local memory 栈上运行时分配存储，用返回的指针配合 `ld.local`/`st.local` 访问；`stacksave`/`stackrestore` 用于保存和恢复栈指针，便于释放。

## 一、概念铺垫：ABI 为什么要被抽象

ABI（Application Binary Interface，应用程序二进制接口）是一组底层约定：参数放在哪些寄存器或栈位置、返回值怎么传、栈帧怎么布局、调用者保存哪些寄存器、被调用者保存哪些寄存器。发起调用的函数叫调用者（caller），被调用的函数叫被调用者（callee）。不同 GPU 架构、不同编译器、不同语言运行时可能有不同的 ABI。

PTX 的设计目标之一，是不把这些细节写死在指令集里。文档开篇说：PTX 不暴露某种特定调用约定、栈布局和 ABI 的细节，而是提供略高层的抽象，支持多种 ABI 实现。§7 介绍实现这种隐藏所需的特性：函数定义、函数调用、参数传递、栈上分配（`alloca`）。

这带来一个关键区分：**PTX 里的 `.reg` 和 `.param` 是「逻辑位置」，不等于最终的物理寄存器或栈槽。** 文档明确说，选择 `.reg` 还是 `.param` 传递参数，不影响参数最终放在物理寄存器还是栈上；真正的映射由 ABI 定义以及参数顺序、大小、对齐决定。理解这一点，才不会把 `.param` 直接当成「栈」，也不会把 `.reg` 直接当成「硬件寄存器」。

## 二、文档语义

### §7.1 函数声明与定义

PTX 用 `.func` 指令声明和定义函数。函数**声明**给出接口（原型）：可选的返回参数列表、函数名、可选的输入参数列表。函数**定义**在接口之外再给出函数体。函数必须先声明或定义，才能被调用。`.reg` 是寄存器状态空间，函数内的标量/向量寄存器变量放在这里。

最简单的函数没有参数和返回值：

{% raw %}
```nasm
.func foo
{
    ...
    ret;
}

    ...
    call foo;
    ...
```
{% endraw %}

`call` 把控制权转移到 `foo`，并隐式保存返回地址；`foo` 里的 `ret` 把控制权转移到 `call` 的下一条指令。这里的「隐式保存返回地址」是 PTX 层面的语义，具体保存到哪个寄存器/栈位置由 ABI 决定。

带返回值和参数的函数，接口写成：

```text
.func (.reg .u32 %res) inc_ptr (.reg .u32 %ptr, .reg .u32 %inc)
      └── 返回参数 ──┘  └名称┘  └──────── 输入参数 ────────┘
```

文档示例：

{% raw %}
```nasm
.func (.reg .u32 %res) inc_ptr ( .reg .u32 %ptr, .reg .u32 %inc )
{
    add.u32 %res, %ptr, %inc;
    ret;
}

    ...
    call (%r1), inc_ptr, (%r1,4);
    ...
```
{% endraw %}

`inc_ptr` 的返回参数是 `%res`，输入参数是 `%ptr` 和 `%inc`。调用点 `call (%r1), inc_ptr, (%r1,4)` 把返回值写进 `%r1`，实参是寄存器 `%r1` 和常量 `4`。标量和向量基类型的输入/返回参数可以直接用寄存器变量表示；调用点的实参可以是寄存器或常量，返回值可以直接放进寄存器。**调用点的实参和返回变量，类型和大小必须与形参一致。** 形参是函数接口里声明的参数，实参是调用点实际传入的值。

使用 ABI 时，`.reg` 形参至少 32 位。源代码里的子字（subword，小于 32 位的标量，例如 8/16 位整数）对象要先提升到 32 位寄存器，或者改用 `.param` 空间的字节数组。这条规则约束的是 PTX 接口，不是某个具体硬件的寄存器宽度。

### 结构体与联合体：扁平化到 .param 字节数组

`.param` 是 PTX 的参数状态空间，用来在调用者和被调用者之间传递参数和返回值。C 的结构体和联合体会被扁平化成寄存器或字节数组，在 PTX 里用 `.param` 空间内存表示。文档例子：

```c
struct {
    double dbl;
    char   c[4];
};
```

这个结构体在 PTX 里变成 12 字节的字节数组，按 8 字节对齐，保证 `.f64` 字段的访问满足自然对齐。按值传递时用 `.param` 空间：

{% raw %}
```nasm
.func (.reg .s32 out) bar (.reg .s32 x, .param .align 8 .b8 y[12])
{
    .reg .f64 f1;
    .reg .b32 c1, c2, c3, c4;
    ...
    ld.param.f64 f1, [y+0];
    ld.param.b8  c1, [y+8];
    ld.param.b8  c2, [y+9];
    ld.param.b8  c3, [y+10];
    ld.param.b8  c4, [y+11];
    ...
    ... // computation using x,f1,c1,c2,c3,c4;
}

{
     .param .b8 .align 8 py[12];
     ...
     st.param.b64 [py+ 0], %rd;
     st.param.b8  [py+ 8], %rc1;
     st.param.b8  [py+ 9], %rc2;
     st.param.b8  [py+10], %rc1;
     st.param.b8  [py+11], %rc2;
     // scalar args in .reg space, byte array in .param space
     call (%out), bar, (%x, py);
     ...
```
{% endraw %}

`.param` 空间在这里有两种角色：

- 对被调用者 `bar`：`y` 是 `.param` 形参，接收调用者传进来的结构体；`ld.param` 按字段偏移读取。
- 对调用者：`py` 是调用者函数体内声明的 `.param` 字节数组，先把结构体字段用 `st.param` 写进去，再把 `py` 作为实参传给 `bar`。

`bar` 的 `.reg` 形参 `x` 和返回参数 `out` 是标量，直接走寄存器；结构体 `y` 走 `.param` 字节数组。文档的调用点 `call (%out), bar, (%x, py)` 同时展示了两种实参：寄存器 `%x` 和 `.param` 字节数组 `py`。

### 参数传递的限制

文档分别列出了调用者和被调用者的限制。

调用者：

| 场景 | 允许的实参 |
|------|-----------|
| 一般参数 | `.param` 变量、`.reg` 变量、常量 |
| 形参是 `.param` 字节数组 | 必须是类型、大小、对齐都匹配的 `.param` 字节数组，且声明在调用者的局部作用域 |
| 形参是 `.param` 基类型标量/向量 | `.param` 或 `.reg` 变量（类型、大小匹配），或能表示成该形参类型的常量 |
| 形参是 `.reg` | `.param` 或 `.reg` 变量（类型、大小匹配），或能表示成该形参类型的常量；寄存器至少 32 位 |

另外，所有用于传参的 `st.param` 必须紧挨着对应的 `call` 之前，所有用于取返回值的 `ld.param` 必须紧挨着 `call` 之后；中间不能有控制流改变，且这些 `st.param`/`ld.param` 不能带谓词。文档给出的理由是：这能让编译器优化，并保证 `.param` 变量不会在调用者栈帧里占用超过 ABI 所需的空间；`.param` 变量只是在调用点为「数据可能分散在多个位置」的情况提供一种映射方式。

被调用者：

| 项目 | 规则 |
|------|------|
| 输入/返回参数 | 可以是 `.param` 或 `.reg` 变量 |
| `.param` 参数对齐 | 必须是 1、2、4、8、16 字节的倍数 |
| `.reg` 参数大小 | 至少 32 位 |
| `.reg` 支持的类型 | 基类型标量和向量；非 ABI 模式（不按 ABI 约定编译的 legacy 模式）下也包括子字对象 |

再次强调：`.reg` 与 `.param` 的选择不决定参数最终在物理寄存器还是栈上。物理位置由 ABI 定义、参数顺序、大小和对齐共同决定。

### §7.1.1 与 PTX 1.x 的差异

PTX 1.x 的形参只能放在 `.reg` 空间，不支持数组参数；结构体这类对象被扁平化成多个寄存器传递或返回，因此 PTX 1.x 支持多个返回值。

PTX 2.0 起，形参可以放在 `.reg` 或 `.param` 空间，`.param` 空间支持数组。对 `sm_20` 及更高目标，函数只允许一个返回值，放不进寄存器的对象用 `.param` 字节数组返回；`sm_1x` 目标继续支持多个返回寄存器。

文档还给出两条边界：

- PTX 只对 `sm_20` 及更高目标实现基于栈的 ABI。
- PTX 3.0 起，使用 ABI 时禁止模块作用域的 `.reg` 和 `.local` 变量，只允许函数作用域；不使用 ABI 时仍允许模块作用域。遇到 ISA 3.0 之前、含模块作用域 `.reg`/`.local` 的旧 PTX，编译器会静默禁用 ABI。

### §7.2 变参函数

§7.2 很短，而且是一条重要现状：**规范中原本未实现的变参函数支持已被移除。** 文档只保留一句：PTX 6.0 支持把「无长度数组参数」传给函数，可以用它来实现变参函数；具体见 `.func` 指令。

这里的「无长度数组参数」不是 C 的 `...` 语法，而是把一组实参打包成一个数组，作为一个参数传递。§7.2 本身不展开具体写法，本文也不越过章节去讲 `.func` 指令的完整语法。

### §7.3 alloca

`alloca` 在当前线程的 local memory 栈上运行时分配存储。local memory 是每个线程私有的本地内存空间；`alloca` 返回的指针可以配合 `ld.local`/`st.local` 访问分配到的存储。

为了便于释放 `alloca` 分配的存储，PTX 提供两条辅助指令：

- `stacksave`：把当前栈指针（stack pointer，指向当前栈顶）的值读进一个局部变量；
- `stackrestore`：用保存的值恢复栈指针。

`alloca`、`stacksave`、`stackrestore` 的完整指令语法和语义在 §9.7.18 的 Stack Manipulation Instructions，本文只按 §7.3 的范围说明它们在 ABI 抽象中的角色。

## 三、文档示例与讲解

§7 是 ABI 抽象章节，下面的讲解以文档语义和最小示例为主。§7.1 的两个文档示例已经足够说明接口、参数传递和 `.param` 字节数组。

### 示例一：寄存器参数与返回值

{% raw %}
```nasm
.func (.reg .u32 %res) inc_ptr ( .reg .u32 %ptr, .reg .u32 %inc )
{
    add.u32 %res, %ptr, %inc;
    ret;
}

    ...
    call (%r1), inc_ptr, (%r1,4);
    ...
```
{% endraw %}

逐行看：

- `.func (.reg .u32 %res) inc_ptr (...)`：`%res` 是返回参数，类型 `.u32`；`inc_ptr` 是函数名；`%ptr`、`%inc` 是输入参数，类型都是 `.u32`。
- `add.u32 %res, %ptr, %inc`：函数体把两个输入相加，结果写进返回参数 `%res`。
- `ret`：返回到调用点。
- `call (%r1), inc_ptr, (%r1,4)`：调用 `inc_ptr`，返回值写进 `%r1`；第一个实参是寄存器 `%r1`，第二个是常量 `4`。实参类型/大小与形参匹配：`%r1` 是 `.u32`，`4` 可以表示成 `.u32`。

这个例子只用了 `.reg` 空间，没有 `.param`；它展示了 PTX 函数接口的最基本形态：返回参数、输入参数、调用点实参一一对应。

### 示例二：结构体按值传递

`bar` 的定义和调用点如下（与上文相同，集中看数据流）：

{% raw %}
```nasm
.func (.reg .s32 out) bar (.reg .s32 x, .param .align 8 .b8 y[12])
{
    ...
    ld.param.f64 f1, [y+0];
    ld.param.b8  c1, [y+8];
    ld.param.b8  c2, [y+9];
    ld.param.b8  c3, [y+10];
    ld.param.b8  c4, [y+11];
    ...
}

{
     .param .b8 .align 8 py[12];
     ...
     st.param.b64 [py+ 0], %rd;
     st.param.b8  [py+ 8], %rc1;
     st.param.b8  [py+ 9], %rc2;
     st.param.b8  [py+10], %rc1;
     st.param.b8  [py+11], %rc2;
     call (%out), bar, (%x, py);
     ...
```
{% endraw %}

数据流可以画成：

```text
调用者                                     被调用者 bar
.param py[12]  ── st.param 写字段 ──┐
.reg   %x      ─────────────────────┼──> formal: x (.reg), y (.param 字节数组)
                                    │        │
call (%out), bar, (%x, py)          │        ├─ ld.param.f64 [y+0]   → f1
                                    │        └─ ld.param.b8  [y+8..11] → c1..c4
.reg   %out    <── 返回值 ──────────┘
```

要点：

- `bar` 的 `.param .align 8 .b8 y[12]` 是形参：12 字节、8 字节对齐。调用者必须提供同类型、同大小、同对齐的 `.param` 字节数组。
- 调用者的 `py` 在函数体内声明，是局部 `.param` 变量；`st.param.b64 [py+0], %rd` 写 `double` 字段，`st.param.b8 [py+8..11]` 写 4 个 `char` 字段。
- `call (%out), bar, (%x, py)` 中，`%x` 对应 `.reg` 形参 `x`，`py` 对应 `.param` 形参 `y`；返回值写进 `%out`。
- `bar` 内部用 `ld.param.f64 [y+0]`、`ld.param.b8 [y+8..11]` 按偏移读取字段。字段偏移和结构体布局由 ABI/编译器决定；这里文档给出的布局是 `double` 在 0，4 个 `char` 在 8–11。

这个例子说明 `.param` 不只是「栈」：它是调用者与被调用者之间的**参数/返回值空间**。对调用者，它承载要传出的值和要接收的返回值；对被调用者，它承载收到的参数和要返回的值。

### 示例三：alloca 的语义流程

§7.3 只给语义，不给指令语法；具体语法在 §9.7.18 的 Stack Manipulation Instructions。这里用伪代码表示流程：

```text
p = alloca(size)       // 运行时在当前线程的 local memory 栈上分配 size 字节
st.local [p], value    // 用返回的指针访问分配到的存储
...
save = stacksave       // 保存当前栈指针
...
stackrestore save      // 恢复到保存点，释放 alloca 分配的存储
```

- `alloca` 在当前线程的 local memory 栈上分配存储，返回一个指针；之后用 `ld.local`/`st.local` 通过这个指针访问。
- `stacksave` 把当前栈指针的值读进一个局部变量；`stackrestore` 用保存的值恢复栈指针。文档说这两个指令是为了方便释放 `alloca` 分配的存储。
- `alloca`、`stacksave`、`stackrestore` 的指令语法和完整语义在 §9.7.18，本文只按 §7.3 的范围说明它们在 ABI 抽象中的角色。

```text
每个线程的 local memory 栈
┌─────────────────────┐
│ 已有栈帧             │
├─────────────────────┤
│ alloca 分配的存储区  │
└─────────────────────┘
   stacksave 保存当前栈指针
   stackrestore 恢复到保存点
```

## 小结

- PTX 不暴露固定的调用约定、栈布局和 ABI，而是提供高层抽象，支持多种 ABI 实现。
- 函数用 `.func` 声明/定义：声明给接口，定义加函数体；必须先声明/定义再调用。`call` 隐式保存返回地址，`ret` 返回到 `call` 之后。
- 标量和向量基类型参数可以直接用 `.reg`；结构体/联合体扁平化成寄存器或 `.param` 字节数组。使用 ABI 时 `.reg` 形参至少 32 位，子字标量提升到 32 位或改用 `.param` 字节数组。
- `.param` 是调用者传参/收返回值、被调用者收参/返回值的空间；`.param` 字节数组实参必须与形参类型、大小、对齐匹配，并在调用者局部作用域声明。
- 传参的 `st.param` 必须紧邻 `call` 之前，取返回值的 `ld.param` 必须紧邻 `call` 之后，不能有控制流改变，也不能带谓词。
- `.reg` 与 `.param` 的选择不决定物理寄存器/栈位置；物理映射由 ABI 定义、参数顺序、大小和对齐决定。
- PTX 1.x 形参仅 `.reg`、无数组参数、支持多返回值；PTX 2.0+ 支持 `.param` 和数组，`sm_20+` 单返回值，大对象用 `.param` 字节数组返回；栈式 ABI 仅 `sm_20+`。PTX 3.0+ 在 ABI 模式下禁止模块作用域 `.reg`/`.local`。
- §7.2：变参函数的旧支持已从规范移除；PTX 6.0 起可用无长度数组参数实现变参。
- §7.3：`alloca` 在每线程 local memory 栈上运行时分配，用返回指针配合 `ld.local`/`st.local` 访问；`stacksave`/`stackrestore` 保存和恢复栈指针，便于释放。
