## TL;DR

**Tensor（张量）**是 PTX 对「内存里的多维矩阵」的一种描述，由四个属性定义：**维度数**、**各维大小**、**元素类型**、**各维步长**。它是 Hopper 架构 TMA（Tensor Memory Accelerator）机制的数据布局基础——tensor 指令把全局内存里的数据当多维结构看待、把共享内存里的当线性数据看待。访问 tensor 有两种模式：**tiled**（按块保留多维布局）和 **im2col**（把数据重排成列，给卷积用）。tiled 模式靠 Bounding Box（边界框）和 traversal stride（遍历步长）定位数据，共享内存侧还能用 swizzling 重排布局以提升访存性能。

## 一、概念铺垫：为什么需要「张量」这个抽象

前几期讲的都是标量、向量、数组这些「规则」的数据形状。但矩阵乘法、卷积这类计算，处理的是**多维、带步长、有 padding** 的大块数据。如果让每条拷贝指令都自己去算「第几维、跳多少、边界在哪」，既繁琐又容易错。

于是 PTX 引入 **tensor** 这个抽象：把内存里的一块多维数据，用「维度、大小、元素类型、步长」四个属性完整描述出来。有了它，一条 tensor 指令就能理解「这是一块 3D 的、每维多大、行尾有没有 padding」的数据，从而高效地在全局内存和共享内存之间搬动——这正是 Hopper 的 TMA（Tensor Memory Accelerator）干的事。这一期讲清楚 tensor 这个「数据布局语言」，具体的 TMA 指令留到第 40 期。

## 二、文档语义：tensor 的定义与访问

### §5.5.1 tensor 是什么：四个属性

一个 tensor 由四个属性定义：**维度数**（1D–5D）、**各维大小**（每维的元素个数）、**元素类型**、**各维步长**。先看图：

```text
一个 2D tensor（§5.5.1）：维度=2，大小=[H, W]，元素类型=.f16，步长=[stride0, stride1]

  沿 W 维（stride1 = 相邻元素间距）
  ┌────┬────┬────┬────┬────┐
  │ 0  │ 1  │ 2  │ 3  │ 4  │  ← 行 0
  ├────┼────┼────┼────┼────┤
  │ 5  │ 6  │ 7  │ 8  │ 9  │  ← 行 1
  ├────┼────┼────┼────┼────┤
  │ 10 │ 11 │ 12 │ 13 │ 14 │  ← 行 2
  └────┴────┴────┴────┴────┘
  沿 H 维（stride0 = 相邻行的首元素间距，可能含 padding）
```

**步长（stride）**是理解 tensor 的关键：它描述「沿某维走一步，地址跳多少」。正常情况下 stride1 就是元素大小，但如果行尾有 padding（为了对齐），stride0 就会大于「W × 元素大小」——多出来的就是 padding。所以 tensor 用步长来隐式表达 padding，而不是单独存一个 padding 字段。

**元素类型**很丰富：位类型（`.b32`、`.b64`）、子字节类型（`.b4x16`、`.b6x16_p32` 等，用于 4-bit/6-bit 量化数据）、整数（`.u8` 到 `.s64`）、浮点（`.f16`、`.bf16`、`.tf32`、`.f32`、`.f64`）。其中子字节类型是给低比特量化（INT4/INT6）用的，tensor 指令会把它们按位打包搬运。

### §5.5.2 访问模式：tiled 与 im2col

访问 tensor 数据有两种模式：

- **tiled（平铺）模式**：源 tensor 的多维布局在目的地被**原样保留**。适合矩阵乘法这类「按块搬数据」的场景。
- **im2col 模式**：把 Bounding Box 里的元素**重排成列**。im2col 是「image to column」的缩写，是卷积计算里的经典技巧——把卷积核扫过的每个 patch 展开成一列，卷积就变成了矩阵乘。

### §5.5.3 tiled 模式：Bounding Box 与 traversal stride

tiled 模式的核心是**Bounding Box（边界框）**——一次访问 tensor 里的一个子块。先看图：

```text
Tiled 模式：用 Bounding Box 一块一块地访问（§5.5.3）

  tensor 整体（多维）
  ┌──────────────────────────┐
  │ ┌──────────┐             │
  │ │ Bounding │             │  ← 一次访问一个子块
  │ │   Box    │             │
  │ └──────────┘             │
  │            ┌──────────┐  │
  │            │  下一个   │  │  ← traversal stride 决定块间跳过多少
  │            │   Box    │  │
  │            └──────────┘  │
  └──────────────────────────┘
```

Bounding Box 有和 tensor 相同的维度数，其**每个维度的大小必须是 16 字节的倍数**，起始地址也要 **16 字节对齐**。tensor 指令里的 tensor 坐标指定 Bounding Box 的起始偏移，配合「box 大小、越界模式、遍历步长」共同决定访问哪些元素。

**traversal stride（遍历步长）**：当 Bounding Box 沿某维遍历 tensor 时，它指定每次跳过多少元素。默认是 1（不跳）。

**越界访问（OOB）**：当 Bounding Box 越过 tensor 边界时，有两种处理——**zero fill**（越界元素填 0）或 **OOB-NaN fill**（填一个特殊的 NaN）。这是给卷积这类「边缘可能要补零」的计算准备的。

### §5.5.6–5.5.7 布局变换：interleave 与 swizzling

数据在全局内存和共享内存里的布局可以不同，这是为了访问性能。两个相关概念：

**interleave（交错）**：针对 channel 维，把连续的 channel 元素分组交错存放。支持无交错、8 字节交错（C8）、16 字节交错（C16）。

**swizzling（重排）**：共享内存侧的数据布局按某种模式重排，以提升 bank 访问效率。先看图：

```text
Swizzling：共享内存里的布局重排（§5.5.7，以 32 字节 swizzle 为例）

  无 swizzle：  0  1  2  3  4  5  6  7
  32B swizzle： 1  0  3  2  5  4  7  6   ← 相邻 16 字节对调

  （每个编号单元是 16 字节；64B/128B swizzle 的重排模式更复杂）
```

swizzle 有 32B、64B、96B、128B 几种，128B swizzle 下还有 16B/32B/32B+8B-flip/64B 几种 atomicity 子模式。这些重排的动机是：矩阵乘访存时，相邻线程访问的数据如果落在不同 bank，就能并行不冲突——swizzling 正是为了「散开」bank 访问。

### §5.5.8 tensor-map：描述符

最后，tensor 的所有属性被装进一个 **tensor-map**——一个 128 字节的不透明对象，可以放在 `.const`、`.param`、`.global` 空间，描述 tensor 的属性（维度、大小、步长、元素类型）和访问属性（越界模式、swizzle 模式等）。tensor-map 由 CUDA API 创建（如 `cuTensorMapEncodeTiled`），第 40 期讲 TMA 指令时会看到它作为指令操作数登场。

## 三、这些布局最终通向哪里

这一期没有反汇编——因为 tensor 是「数据布局」层面的抽象，它的使用者（TMA 指令 `cp.async.bulk.tensor` 等）属于第 40 期的内容。这里用一段伪代码点一下「tensor 布局如何被指令使用」，把抽象的布局和具体的指令接上头：

```text
// 概念示意（不是真实可编译代码）：把全局 tensor 的一块平铺拷进共享内存
cp.async.bulk.tensor.2d.shared::cta.global.tile
    [共享内存地址],                    // 目标：线性共享内存
    [全局 tensor 基址, {x, y}],        // 源：多维 tensor + 起始坐标
    tensorMap;                         // 描述维度/步长/元素类型/越界/布局

// 指令根据 tensorMap 知道：
//   - 这块 tensor 是几维、每维多大
//   - 步长多少（哪里有 padding）
//   - 越界怎么填（zero / NaN）
//   - 共享内存侧要不要 swizzle
```

可以看到，tensor-map 把这一期讲的所有「布局知识」打包成一个描述符，交给指令去执行。理解了 tensor 的四个属性、tiled/im2col 两种模式、以及 interleave/swizzle 两种布局变换，就理解了 TMA 这套机制的数据基础——第 40 期讲指令时，这些概念会一一对号入座。

## 小结

- tensor 是内存里多维矩阵的描述，四个属性：维度数（1–5D）、各维大小、元素类型、各维步长。
- 步长隐式表达 padding；元素类型含整数、浮点、位、子字节（量化）。
- 两种访问模式：tiled（保留多维布局）和 im2col（重排成列，给卷积）。
- tiled 模式用 Bounding Box 分块访问，大小 16 字节倍数、16 字节对齐；traversal stride 控制块间步进；OOB 支持 zero fill / OOB-NaN。
- 布局变换：interleave（channel 交错）与 swizzling（共享内存重排，提升 bank 访问）。
- tensor-map 是 128 字节描述符，打包所有属性；tensor 指令（TMA）在第 40 期展开。
