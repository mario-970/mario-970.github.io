> 本文是 [PTX 专栏](/ptx/) 第 6 期，对应官方文档 §4.1–4.4。

## TL;DR

PTX 的语法骨架就三件事：**源格式**、**语句**、**标识符**。源是纯 ASCII 文本，可用 C 预处理器处理，每个模块必须以 `.version`、`.target` 开头；语句只有两种——以点开头的 **directive** 和以 opcode 开头的 **instruction**，两者都可有可选 label、都以分号结尾；标识符走扩展 C++ 规则，但额外允许 `%`、`$`、`_` 作首字符，其中 `%` 开头的被预留给 `%tid` 这类预定义量。读完这期，前面几期贴过的 PTX 每一行属于什么、由什么组成，都能说清。

## 一、概念铺垫：先把「怎么读」学明白

前五期贴了不少 PTX 代码——`.param`、`ld.global.u32`、`@%p1 bra`、`$L__BB2_2:`……我们一直是「边读边猜」：知道每段大概在干什么，但没停下来问一句「这一行凭什么长这样、它的每一截是什么」。语法章就是补上这一课。

语法是语言的骨架。PTX 和 C/C++ 一样，是一套有严格书写规则的文本语言：什么是一个合法的语句、什么能拿来做名字、空白和注释怎么算。掌握它不需要理解任何一条指令的语义——只需要知道「怎么读、怎么分块」。有了这套规则，往后读任何一期反汇编，都能像拆句子一样，把一行 PTX 拆成「主谓宾」。

这一期覆盖语法的前半部分：源文件长什么样（§4.1）、注释怎么写（§4.2）、语句怎么组成（§4.3）、名字怎么起（§4.4）；常量的写法属于下一期（§4.5）。

## 二、文档语义：§4.1–4.4

### §4.1 源格式：ASCII 文本 + 预处理 + 模块头

文档给源格式定了五条规矩。

**第一，纯 ASCII 文本，换行符分行。** PTX 源模块就是普通的 ASCII 文本，行与行之间用换行符（`\n`）分隔。没有二进制、没有编码花活。

**第二，空白等价，只用来分隔 token。** 空格、制表符、换行这些空白字符彼此等价，除了把一个个 token 隔开之外，其余一律被忽略。也就是说 `add r1, r2` 和 `add    r1 , r2` 在语法上是一回事——空白多一个少一个不影响含义。

**第三，可以用 C 预处理器。** PTX 源可以直接交给 C 预处理器 cpp 处理，以 `#` 开头的行是预处理指令，常见的几个是 `#include`、`#define`、`#if`、`#ifdef`、`#else`、`#endif`、`#line`、`#file`。这意味着 PTX 也能享受宏、条件编译、头文件包含这套 C 系工具。

**第四，大小写敏感，关键字一律小写。** PTX 区分大小写，而且所有关键字都用小写——所以 `ADD` 不是关键字，`add` 才是。这一条配合后面 §4.4 的标识符规则，共同划清了「保留字」和「用户名字」的边界。

**第五，模块头：`.version` 打头，`.target` 随后。** 每个 PTX 模块**必须**以一条 `.version` 指令开头，声明本模块用的 PTX 语言版本；紧跟着一条 `.target` 指令，声明假定运行的目标架构。这就是为什么前几期贴的真实 PTX 里，函数体之前总会有 `.version 9.3` 和 `.target sm_90a` 两行——它们是模块的「出生证明」，缺一不可。

### §4.2 注释：照搬 C/C++

PTX 的注释语法完全沿用 C/C++：`/* ... */` 是不嵌套的块注释、可以跨行；`//` 是行注释，从 `//` 一直延续到行尾。两个细节要注意：注释**不能**出现在字符常量、字符串字面量、或另一个注释的内部；注释在语法上被当作空白处理——也就是注释等于不存在，只是给人看的。

前几期反汇编里行尾那些 `// 读入参数 x` 就是我加的注释，它们对编译器而言就是空白。

### §4.3 语句：两种，都以分号结尾

文档对语句的定义一句话：一条 PTX 语句要么是 **directive**，要么是 **instruction**；语句以**可选的 label 开头**，以**分号结尾**。这是整个语法章最核心的一句，先看图：

```text
一条 PTX 语句的解剖（以 instruction 为例）：

   label:  @p   opcode.类型    d, a, b;      // 注释
     │      │       │          │   │
     │      │       │          │   └─ 源操作数（逗号分隔）
     │      │       │          └───── 目标操作数（永远在最前）
     │      │       └─────────────── 指令名 + 类型修饰（.b32 / .f32 …）
     │      └─────────────────────── 守卫谓词 @p / @!p（可选）
     └────────────────────────────── 标签（可选）
```

对照文档 §4.3 自己给的四行示例，把上面的解剖图落到实处：

```text
        .reg     .b32 r1, r2;        // directive：声明两个 .b32 寄存器
        .global  .f32  array[N];     // directive：声明一个 .f32 数组

start:  mov.b32   r1, %tid.x;        // instruction，带 label "start"
        ld.global.b32 r2, array[r1]; // instruction，目标 r2、源 array[r1]
```

前两行是 directive（点开头，声明东西），后两行是 instruction（opcode 开头，干事情）。第三行 `start:` 就是那个可选 label，贴在 instruction 前面给它起个名字，方便别处跳转过来。

### §4.3.1 directive：点开头，永不与标识符撞名

directive 关键字都以点开头，所以**不可能**和用户自定义的标识符冲突——因为标识符（§4.4）不允许以点开头。这一个设计就把「语言保留字」和「用户名字」彻底分开了。

PTX 的 directive 数量不少，文档 Table 1 列了 30 多个，覆盖几类用途：模块与链接（`.version`、`.target`、`.entry`、`.func`、`.extern`、`.weak`、`.visible`、`.noreturn`、`.alias`、`.common`）、存储与变量声明（`.reg`、`.global`、`.local`、`.shared`、`.const`、`.param`、`.sreg`、`.tex`、`.align`）、属性与约束（`.maxnreg`、`.maxntid`、`.reqntid`、`.maxnctapersm`、`.minnctapersm`）、调试信息（`.file`、`.loc`）等。前几期我们已经反复撞见其中几个：`.visible .entry` 标出 kernel 入口、`.param` 声明函数参数、`.reg` 声明寄存器。

本节不逐个展开每个 directive 的语义——那是后面「状态空间」「指令」各章的活。这里只要抓住它们的共同点：**点开头、做声明或控制、不与标识符冲突**。

### §4.3.2 instruction：opcode + 操作数，目标在前

instruction 由**一个 opcode** 开头，后跟**逗号分隔的零个或多个操作数**，以分号结尾。操作数可以是寄存器变量、常量表达式、地址表达式，或 label 名——四种。

两个关键规矩：

**其一，目标操作数在前，源操作数在后。** 这和 AT&T 汇编一致，和 Intel 语法相反。所以 `mov.b32 r1, %tid.x` 读作「把 `%tid.x` 搬进 `r1`」，而不是反过来。

**其二，可选的守卫谓词（guard predicate）。** 每条 instruction 都能带一个条件执行开关，写法是 `@p`，其中 `p` 是一个谓词寄存器；还可以取反写成 `@!p`。它的位置在 label 之后、opcode 之前。这正是第 4 期反汇编里 `@%p1 bra $L__BB2_2` 的来源——`%p1` 为真的线程才执行这条 `bra`，`@!%p1` 则是为假的线程才执行。

所有 opcode 关键字（`add`、`mov`、`ld`、`st`、`bra`……）都是保留字，文档 Table 2 列了一份完整的保留清单，用户标识符不能和它们重名。

### §4.4 标识符：扩展 C++ 规则 + 三种特殊首字符

用户自定义标识符遵循「扩展 C++」规则。文档用两条正则表达得很精确：

```text
followsym:   [a-zA-Z0-9_$]                    // 允许的后续字符
identifier:  [a-zA-Z]{followsym}* | {[_$%]{followsym}+
```

翻译成人话：标识符要么以**字母**开头，后面跟零个或多个字母、数字、下划线、美元符；要么以**下划线 `_`、美元符 `$`、百分号 `%`** 之一开头，后面跟**至少一个**字母、数字、下划线或美元符。PTX 不规定标识符最大长度，但建议所有实现至少支持 1024 个字符。

和 C/C++ 相比，唯一的新东西是**百分号 `%`**：C/C++ 不允许 `%` 作标识符首字符，PTX 允许。文档明确说，允许 `%` 是为了**避免命名冲突**——比如区分用户自己起的变量名和编译器生成的名字。这也解释了前面反汇编里那些 `$L__BB2_2`（label，`$` 开头）和 `%r1`、`%tid`（`%` 开头）为什么合法。

`%` 开头还有一个更深的用途：PTX **预定义**了一个常量和一批特殊寄存器，它们都以 `%` 开头（文档 Table 3）。这些名字是语言自带的，用户不能重新定义。前几期已经见过不少：

| 预定义标识符 | 含义 |
|--------------|------|
| `%tid` | 线程在 CTA 内的 thread id（`%tid.x` 就是 threadIdx.x） |
| `%ntid` | CTA 每维的线程数 |
| `%ctaid` | 当前 CTA 在 grid 中的 block id |
| `%laneid` | 线程在 warp 内的 lane id |
| `%warpid` | warp id |
| `%smid` | 当前 SM 的 id |
| `WARP_SZ` | warp 大小（即 32） |

这些以 `%` 开头的特殊寄存器，正是 §4.4「百分号避免冲突」这条规则落地的第一现场：用户起名避开 `%` 前缀，就不会和这些预定义量撞车。

## 三、反汇编与讲解：用真实 PTX 对照语法

语法是抽象规则，最好的验证方式不是新编一段代码，而是拿前面已经拿到的真实 PTX，逐行指出「这一截对应哪条语法」。下面摘第 4 期 divergeKernel 真实反汇编的几行（NVCC 13.3.0，`-arch=sm_90a -ptx -O3`），它麻雀虽小、五脏俱全，几乎覆盖了本节所有规则：

```nasm
.visible .entry divergeKernel(int*, int const*)(
        .param .u64 divergeKernel(int*, int const*)_param_0,
        .param .u64 divergeKernel(int*, int const*)_param_1
)
{
        ld.param.u64    %rd2, [divergeKernel(int*, int const*)_param_0];   // 注释（§4.2）
        @%p1 bra        $L__BB2_2;                  // 守卫谓词 + label 操作数
        bra.uni         $L__BB2_1;
$L__BB2_2:                                          // 标签声明
        st.param.b32    [param0+0], %r1;
        ret;
}
```

对照语法逐条看：

- **`.visible .entry ...(...)` 是 directive。** `.visible`、`.entry` 都以点开头（§4.3.1），声明这是一个对外可见的 kernel 入口。`divergeKernel(int*, int const*)` 里的 `divergeKernel` 是用户标识符——字母开头、后面跟字母，正是 §4.4 的第一种合法形式。
- **`.param .u64 ...` 也是 directive**，声明函数参数。参数名 `divergeKernel(int*, int const*)_param_0` 是编译器生成的长名字，里面混了字母、括号、下划线、数字——但都是 `[a-zA-Z0-9_$]` 里的字符，符合 `followsym` 规则。
- **`ld.param.u64 %rd2, [...]` 是 instruction**：opcode 是 `ld`，目标操作数 `%rd2` 在前、源操作数 `[...]` 在后（§4.3.2「目标在前」），`.u64` 是类型修饰。
- **`@%p1 bra $L__BB2_2` 展示了守卫谓词**：`@%p1` 就是 `@p` 的实例（`p` = 谓词寄存器 `%p1`），放在 opcode `bra` 之前；`$L__BB2_2` 是 label 名——`$` 开头，合法（§4.4 的第二种形式）。
- **`$L__BB2_2:` 是标签声明**，行尾的冒号把它和「引用 label」区分开：声明时带冒号，跳转时不带。
- **行尾 `// ...` 是注释**，按 §4.2 被当作空白，对语义零影响。

需要说明一点：这段摘录去掉了 `.version` 和 `.target` 两行模块头——那正是 §4.1 第五条说的「必须打头」的两行，它们在 godbolt 的输出里被裁剪掉了（第 1 期起就讲过这个坑），这里按文档语义补一句：完整模块的最前面一定有 `.version 9.3` 和 `.target sm_90a`。

## 小结

- 源格式：ASCII 文本、空白等价、可用 cpp 预处理、关键字小写；模块必须以 `.version`、`.target` 开头。
- 注释：照搬 C/C++（`/* */` 与 `//`），当作空白，不能嵌套。
- 语句两种：**directive**（点开头，做声明/控制，不与标识符冲突）和 **instruction**（opcode + 操作数）；都可有可选 label、都以分号结尾。
- instruction 两条规矩：**目标操作数在前、源在后**；可选**守卫谓词** `@p` / `@!p` 在 label 之后、opcode 之前。
- 标识符走扩展 C++ 规则，额外允许 `_`、`$`、`%` 作首字符；`%` 用于避免命名冲突，`%tid` 等预定义量都以 `%` 开头。
- 真实反汇编里，`.visible .entry`/`.param` 是 directive，`ld`/`bra` 是 instruction，`@%p1` 是守卫谓词，`$L__BB2_2:` 是标签——每一条都能落到本节规则上。
