## TL;DR

- **「近似算子的误差该在哪一侧记账」是今天的头号线索**：**DyRA** 指出低秩/结构化分解近似的是**权重**，但决定精度的却是**输出激活**——权重空间的小误差会被输入激活放大，于是改为在推理时对**输出残差**做**输入自适应**的动态校正（直接优化输出的低秩因子），视觉/语音/语言模型上一致改善精度-效率权衡，DINOv3 端到端 **1.5×** 加速且精度退化比纯权重近似基线**低 3 倍以上**；**VisionMX** 把 MX 后训练量化的误差拆成三处具体来源（块尺度的表示方式、部分小卷积权重张量与**非均匀元素格点**对不齐、非负激活白白浪费了有符号码），用**有界权重舍入 + 可折叠的仿射激活修正**补回来。
- **KV cache 继续往 1–2 bit 压，而且开始动「在哪个空间里量化」**：**TaSQ** 不再纠结码本怎么选，而是把 **VQ 的目标空间**重新裁剪——query 引导的通道加权、跨头归一化、协方差感知的通道分组，三者都**兼容 RoPE 且可折进投影权重与码本**，因此**保留原有查表结构、服务端开销可忽略**，单张 RTX 6000 Ada 上 SGLang 实现支持 **14×** 更大 batch、峰值吞吐 **1.87×**（对 BF16）；**SlimKV** 把 token 与 feature 两侧一起压，抓手是一个**位置不对称**发现（去掉 key 侧 RoPE 对 beacon token 的伤害远小于原始 token），据此在 **latent 空间直接做 attention**、省掉全维重建，128K 下 attention 最高 **7.34×**、端到端解码 **3.38×**。
- **融合 kernel 与「自动生成 kernel」两端各有一个硬读数**：**ByteSplat** 把 3DGS 的前向与反向光栅化**融成单个 kernel** 并将中间结果留在片上，再用**同时考虑渲染质量与逐 tile 共享内存约束**的硬件感知剪枝控制片上占用、用**梯度稀疏性**剔掉零梯度通信，片外流量降 **63.4%**、反向跨 GPU 通信量降 **65.8%**、8 卡训练最高 **6.1×**；而 **D2K-Bench** 给的是个方向性结论——把专家级设计指导（L1 算法洞见 / L2 数据流设计 / L3 底层优化技巧，含层级间依赖）喂给 LLM agent，26 个任务上的正确率 **93.1%→98.5%**、几何平均加速 **1.69×→2.49×**，说明**当前瓶颈在「设计发现」而不在「写代码」**。

## 三、arXiv 论文（算子内核）

- **[DyRA: Dynamic Residual Approximation for Efficient Matrix Multiplication in DNNs](https://arxiv.org/abs/2610.02882)**（`2610.02882`）：把权重矩阵替成低秩等**结构化形式**是压稠密乘的常规手段，但既有方法**近似的是权重、而决定推理精度的是输出激活**——权重空间里很小的误差会被输入激活放大成明显的输出误差。DyRA 的立场是：**矩阵乘更有效的近似方式，是直接优化输出的低秩因子**。做法是**输入自适应**地在推理时**动态近似并校正**结构化权重近似引入的**输出残差**，从而在同一计算预算下把稠密矩阵乘拟合得更准——本质上是「**结构化计算 + 输入相关的校正项**」的组合。在视觉、语音、语言模型上一致优于纯结构化权重近似：DINOv3 上端到端 GPU 加速 **1.5×**，同时精度退化比权重侧基线**降低 3 倍以上**。对算子组的价值在于它把「近似」从一个**静态的权重变换**变成**运行时多出来的一小段残差校正**——需要评估的正是这段校正算子的实际形状（是否又是一个小 GEMM）以及它与主算子的融合代价；摘要只给端到端加速与精度，**未给校正算子的单独开销或 FLOP 账**。

- **[VisionMX: Unlocking Microscaling Post-Training Quantization for Vision Models](https://arxiv.org/abs/2610.03218)**（`2610.03218`）：MX（microscaling）格式是**硬件已支持**的低精度路线——低比特元素配**共享的块尺度**，但它在**视觉模型**上的影响基本没人系统看过。这篇先做误差归因：直接把视觉模型转成 MX，误差集中在三处——（1）**块尺度的表示方式**本身，（2）**部分小卷积权重张量与元素格点对不齐**（MX 的元素分布是**非均匀**的，小张量尤其吃亏），（3）**非负激活**（如 ReLU 之后）**用不上有符号码**，白白浪费码点。据此提出 **VisionMX**：对权重做**有界舍入（bounded rounding）**优化，对激活施加一个**可折叠的仿射修正**（foldable affine correction，即修正项能折进前级算子、不在热路径新增算子）。在图像分类、目标检测、语义分割、暗光增强四类任务、多种 MX 风格格式上评测，优于直接转换与所对比的 PTQ 基线，**在架构对 MX 转换最敏感处恢复最多**。边界：摘要**没有任何吞吐/延迟数字**，收益全部是保真度口径；且它只覆盖视觉模型，不涉及 LLM 的 MX 路径。

- **[Tailoring the Quantization Space for 1-Bit KV Cache Compression](https://arxiv.org/abs/2610.03027)**（`2610.03027`）：KV cache 是长上下文推理的内存瓶颈，矢量量化（VQ）是激进压缩的常用路线，但**在 1-bit 这一档明显退化**：每个码本要用有限的质心代表更多通道，容量越来越不够用。**TaSQ** 的转向很关键——它不去改码本怎么设计，而是**改 VQ 的目标空间**：把 **query 引导的通道加权**、**跨头归一化**、**协方差感知的通道分组**三者组合起来，让目标空间更好地反映**缓存激活的误差敏感度与统计结构**。工程上最要紧的是这些变换**兼容 RoPE、且能直接折进投影权重与码本**，因此**保留了常规 VQ 的查表结构、服务端只增加可忽略的开销**。在通用、长链式思维推理、长上下文检索三类基准上一致优于既有低比特 KV VQ 基线，且保持推理稳定性。实测：单张 **RTX 6000 Ada** 上，其 SGLang 实现支持**至多 14× 更大的 batch**、峰值吞吐达 BF16 基线的 **1.87×**。对算子组这就是那类「**变换折进权重、运行时算子形态不变**」的低成本量化前处理——与 10-03 那期 GCBT 的「折进权重、只多一个 2×2」同源，但 TaSQ 的收益是带吞吐数字的。

- **[SlimKV: Joint Token-Feature KV Cache Compression with Reconstruction-Free Beacon Attention](https://arxiv.org/abs/2610.02953)**（`2610.02953`）：既有 KV 压缩分两派各有硬伤——**token 侧**方法减少缓存状态但靠**驱逐或合并**，有信息损失风险；**feature 侧**方法压每个 token 的 KV 维度，但**要应用位置编码就得做全维重建**，反而卡住解码速度。**SlimKV** 是**问题无关（question-agnostic）的 token-与-feature 联合**压缩：用**低秩感知的训练**把长上下文压成带 latent KV 表示的 **beacon 记忆状态**，并按层自适应分配秩。它最关键的一步是个**位置不对称**的发现：**移除 key 侧的 RoPE** 对 **beacon token** 与**原始 token** 的伤害并不一样，**beacon token 的退化小得多**；于是训练 beacon 的 KV 投影时施加 **K-RoPE-free 约束**，从而**允许在解码期直接在 latent 空间做 attention**，规避了重建延迟。结果：LongBench 上 **16×/32×** 压缩优于基线，**4×/8×** 下保持领先且**保留未压缩模型 96% 以上的分数**；Needle-in-a-Haystack 验证跨证据位置稳健；效率上 **128K 长度**时 attention 最高 **7.34×**、端到端解码 **3.38×**（对未压缩模型）。对算子组的看点是「**把重建这一步从热路径彻底删掉**」——省的不只是显存，还有每步解码里那次全维还原。

- **[Gated Slot Attention-2: Two-Sided Associative Memory Correction in Linear Attention](https://arxiv.org/abs/2610.02816)**（`2610.02816`）：线性 attention 的固定大小循环记忆不好管，近期两条路线各有分工——**delta-rule 变体**对「与 key 关联的 value」做**精确校正**，**slot 类架构**（如 Gated Slot Attention）分**两阶段**建模 key 记忆与 value 记忆。这篇的观察是二者**互补**：delta rule 提供有效的**记忆校正**，两阶段结构提供**在关联两侧操作**的自然位置。据此提出 **Gated Oja Rule** 做 **key 侧校正**，并用**解耦的擦除/写入控制**把它扩展为 **Gated Oja Rule-2**；进而给出 **GSA2**，通过**共享的 latent slot** 把 **Gated Oja Rule-2（key 侧）** 与 **Gated Delta Rule-2（value 侧）** 组合起来，凑成**双侧**校正。为可训练性，另推导了一个**硬件高效的 chunkwise 并行算法**。实验上一致优于强线性 attention 基线，同时保持**线性时间**建模与**常数内存的循环解码**。

- **[CHASE-VLA: Post-Training Quantization Framework for Vision-Language-Action Models with Chunk-Aware Scale Estimation](https://arxiv.org/abs/2610.02666)**（`2610.02666`）：VLA 模型把视觉观测与语言指令映射为连续机器人动作，其瓶颈在**基于扩散的动作专家（AE）**——AE 在去噪步与策略查询中被**反复调用**，而**固定的校准尺度**与随去噪进度、目标动作而变的激活范围**对不上**。**CHASE-VLA** 用的信号很有针对性：直接从策略里拿一个**VLA 特有的现成量**——**生成的 action chunk（含尚未执行的未来后缀）**。它把**已生成的 chunk 作为因果动作上下文**，连同**去噪步分组信息**一起，去**自适应地估 AE 的激活尺度**，而不是只做静态尺度匹配；于是可以在**不改动预训练策略**的前提下，把 AE 里的 **MLP 与 attention 投影双双量化到 W4A4**。结果：LIBERO 上 **π₀.₅** 平均成功率 **97.3%**，即把 AE 的两个投影都压到 W4A4 后**恢复 FP16 级性能**；量化后 AE 线性层**权重存储减少 73.4%**，单 chunk 访存分别减少 **70.9%**（π₀.₅）与 **71.2%**（GR00T N1.6），而预测器本身的开销**不超过所省存储的 1.26%**。对算子组：**W4A4 落到 MLP 与 attention 投影**意味着这两类 kernel 都要吃 4-bit 激活，而**尺度是逐 chunk 动态算的**——量化参数的「重算频率」进了解码循环，这是要单独算的账。

- **[16-bit Precision of Convolutional Neural Networks on Microcontroller Units for 8-bit Costs](https://arxiv.org/abs/2610.03402)**（`2610.03402`）：这篇走的是**与主流相反的方向**——在微控制器上不做 8-bit 而是做 **16-bit（W16A16）**，主张在 **Armv7E-M** 这类架构上，**高位宽反而更快更省电**。论文分析了 Armv7E-M 的架构，解释 16-bit 方案性能优势背后的原理（即**8-bit 在这些核上并不天然划算**），并在回归与分类任务上评估经验量化误差、在 MCU 部署上量测时间与能量。结论：相比 8-bit 方案量化误差**低约 10 倍**，而推理时间与能耗**相当或更好**。**边界要说清**：这是**微控制器**（CPU 类核，非 GPU/NPU），且是**部署与量测**导向、**没有 kernel 级实现细节**——它与 10-03 那期 RiP 卷积同属「**限制来自激活内存与指令集，而非算力**」的边缘侧场景，读它的价值在于提醒「**位宽选择要跟着目标 ISA 走**」，而不是一条可直接移植到 GPU 的结论。

- **[ByteSplat: Efficient Distributed 3D Gaussian Splatting Training via Intra- and Inter-GPU communication reduction](https://arxiv.org/abs/2610.02851)**（`2610.02851`）：3DGS 训练大规模场景吃显存和算力，多卡扩容解决容量问题，但**性能严格受限于数据搬运**。作者定位了两个主导瓶颈：**前向与反向光栅化期间反复的片外访存**，以及**跨 GPU 的部分高斯梯度通信**。ByteSplat 三招对应很干净：其一，把**前向与反向光栅化融合进单个 GPU kernel**，将中间结果**留在片上**以消除冗余片外传输；其二，融合后片上占用上升，于是引入**硬件感知剪枝**，打分时**同时考虑渲染质量与逐 tile 的共享内存约束**；其三，利用**梯度稀疏性**把**零值部分梯度**从跨 GPU 通信中剔除，用 GPU 高效的**编码/解码 kernel** 压缩剩余记录、并在**梯度归属的 GPU 上直接聚合**，同时降低通信量与本地聚合开销。六个数据集上：**片内片外流量减少 63.4%**、**反向跨 GPU 通信量减少 65.8%**，**8 卡**训练最高 **6.1×** 加速且保持重建质量。对算子组的直接参考是那两条**通信侧**手法——**用稀疏性剔零 + 在归属地聚合**，是做集合通信（尤其 all-reduce 类）时最值得复用的一档优化。

- **[D2K-Bench: Can LLM Agents Turn Expert Designs into Efficient GPU Kernels?](https://arxiv.org/abs/2610.03226)**（`2610.03226`）：LLM agent 生成的 GPU kernel 常常还是不如专家实现，但**光看运行时间看不出差距出在「没找到设计」还是「没实现好」**。D2K-Bench 是个**诊断型**基准：**26 个任务、85 个工作负载**，度量 agent **把专家设计指导转化为高效 GPU kernel** 的能力。指导分三层——**L1 高层算法洞见、L2 数据流设计、L3 底层优化技巧**，并**显式包含层级之间的依赖**。实验控制得很干净：给指导与不给指导的成对运行**共享任务描述、工作负载、工具、硬件与 350 轮预算**；另有互补评估看**独立提出的设计**与**生成代码里真正实现的设计属性**。五个模型、**NVIDIA B200** 上：指导把 130 个「模型-任务」对的**正确率从 93.1% 提到 98.5%**，26 个任务上的 **Performance Score 从 1.46 到 1.95**；对三个在两个 run 里都 26 个任务全对的**前沿模型**（GPT-6-Astra、Claude-Opus-4.8、GPT-5.6-Sol），**几何平均加速从 1.69× 升到 2.49×**；五个模型的**平均实现质量分从 57 升到 70**（满分 100）。它同时**点名了若干始终没能被实现的设计属性**——对算子组，这份「**哪些设计属性 agent 至今做不出来**」的清单，比总分更有参考价值：它约等于一张「**当前自动生成 kernel 的失效模式表**」。
