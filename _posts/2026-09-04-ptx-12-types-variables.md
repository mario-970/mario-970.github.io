## TL;DR

PTX 的类型系统和变量声明，回答「数据长什么样、怎么声明」。基本类型分五族：有符号整数 `.s8`–`.s64`、无符号整数 `.u8`–`.u64`、浮点 `.f16`/`.f32`/`.f64`、无类型位 `.b8`–`.b128`、谓词 `.pred`。类型兼容性的核心规则是「大小相同即可互换」——尤其 `.b32` 能和任何 32 位类型互操作。变量声明要写明「空间 + 类型 + 名字」，还能声明向量（`.v2`/`.v4`，最长 128 位）、数组、初始化器和对齐。

## 一、概念铺垫：类型是数据的「形状」，变量是「容器」

前面几期一直在用 `.u32`、`.f32`、`.pred` 这些后缀，但没停下来问它们是什么。这一期补上。PTX 的**类型**规定了「一段数据占多少位、这些位怎么解释」——`.s32` 是 32 位有符号整数，`.f32` 是 32 位浮点，`.b32` 是 32 位「不解释的位」。**变量声明**则把类型和状态空间绑到一起，给数据起个名字。

理解这一章的关键，是抓住一条贯穿始终的规则：**类型由「基本类型 + 大小」两个维度决定**。基本类型是「怎么解释位」（整数/浮点/位/谓词），大小是「多少位」（8/16/32/64/128）。这条规则既决定了哪些类型能互相配合，也决定了向量、数组这些复合形状怎么搭。

## 二、文档语义：类型与变量

### §5.2.1 基本类型：五族

基本类型反映目标架构原生支持的数据类型，每个基本类型都指定「基本类型 + 大小」。寄存器变量总是基本类型，指令也在这上面操作。先看 Table 8 的全貌：

| 基本类型 | 类型说明符 |
|----------|-----------|
| 有符号整数 | `.s8` `.s16` `.s32` `.s64` |
| 无符号整数 | `.u8` `.u16` `.u32` `.u64` |
| 浮点 | `.f16` `.f16x2` `.f32` `.f64` |
| 位（无类型） | `.b8` `.b16` `.b32` `.b64` `.b128` |
| 谓词 | `.pred` |

五族里，前四个按「大小」铺开（8→64 位，位类型还多了 128 位），谓词单独一族（1 位）。`.f16x2` 是个特例——它既是浮点族的成员，又是一个「打包」类型（两个 `.f16` 打包在一起，见 §5.2.5）。

文档给了一条很重要的**类型兼容性**规则：两个基本类型兼容，当且仅当它们**基本类型相同且大小相同**；有符号/无符号整数只要**大小相同**就兼容；位类型与**任何相同大小**的基本类型兼容。这条规则解释了日常写法——`.s32` 和 `.u32` 能直接配合（同为 32 位整数），`.b32` 能装下任何 32 位数据（它不解释位，所以和谁都兼容）。

### §5.2.2–5.2.5 类型的花边：子字、替代浮点、打包

§5.2 其余几节讲类型的「特殊用法」，这里提纲挈领：

**子字大小的受限使用（§5.2.2）。** `.u8`、`.s8`、`.b8` 这些「不到一个字」的类型，只允许用在少数指令里——`ld`、`st`、`add`、`sub`、`min`、`max`、`neg`、`cvt`。为了方便，`ld`/`st`/`cvt` 允许源/目标操作数比指令类型宽，这样窄值可以用普通宽度的寄存器来装载。

**替代浮点格式（§5.2.3）。** 除了 `.f16`/`.f32`/`.f64` 这些基本浮点类型，PTX 还支持一批「替代格式」：`bf16`（8 位指数 7 位尾数）、`e4m3`/`e5m2`（8 位微型浮点）、`tf32`（TensorFloat-32，矩阵乘专用）、`e2m1`/`e2m3`/`e3m2`/`ue8m0`/`ue4m3` 等。它们不能当基本类型用，只能由特定指令（主要是矩阵乘 `mma` 系列）当作源/目标格式。这些格式到第 38–40 期讲 Tensor Core 时再展开。

**定点格式（§5.2.4）。** `s2f6` 是 8 位有符号定点数（2 位整数 + 6 位小数），也仅供特定指令使用。

**打包类型（§5.2.5）。** 某些指令并行处理多组输入输出，用「打包」格式把 2 个或 4 个同类型值塞进一个更大的值。比如 `.f16x2`（两个 `.f16` 塞进 `.b32`）、`.u8x4`（四个 `.u8` 塞进 `.b32`）、`.e4m3x4`（四个 `.e4m3` 塞进 `.b32`）。打包类型的变量要用对应大小的**位类型**声明（如 `.b32` 装 `.f16x2`）。

### §5.4 变量声明：空间 + 类型 + 名字

变量声明描述「变量的类型和它的状态空间」，语法上一行写清几件事：空间、类型和大小、名字、可选的数组大小、可选的初始化器、可选的固定地址。文档的例子：

```text
.global .u32 loc;                    // 全局空间，一个 u32
.reg    .s32 i;                      // 寄存器空间，一个 s32
.const  .f32 bias[] = {-1.0, 1.0};   // 常量空间，f32 数组，带初始化器
.global .u8  bg[4] = {0, 0, 0, 0};   // 全局空间，u8 数组
.reg    .v4 .f32 accel;              // 寄存器空间，4 元素 f32 向量
.reg    .pred p, q, r;               // 寄存器空间，3 个谓词
```

注意一个约束：**谓词变量只能在寄存器空间声明**。其余几个关键点：

**向量（§5.4.2）。** 用 `.v2` 或 `.v4` 前缀声明长度 2 或 4 的向量，必须基于基本类型，且**总长不能超过 128 位**（所以 `.v4 .f64` 不允许——4×64 超了）。三维向量（如三维 grid 坐标）常用 `.v4` 表示，第四个元素做填充。

**数组（§5.4.3）。** 数组声明类似 C 的定长数组，每维大小是常量表达式。带初始化器时，第一维可以省略，由初始化器元素个数推断。

**初始化器（§5.4.4）。** 目前只支持 `.const` 和 `.global` 两个空间的变量初始化；这两个空间里没有显式初始化器的变量默认初始化为 0。初始化器用 C 风格的大括号嵌套列表，数组初始化器可以不完整（剩余位置填默认值）。

**对齐（§5.4.5）。** 用 `.align N` 指定字节对齐，`N` 必须是 2 的幂。所有访存指令都要求地址按访问大小对齐。

**参数化变量名（§5.4.6）。** 编译器前端常生成大量寄存器名，PTX 支持简写：`%r<100>` 一次性声明 `%r0`、`%r1`…`%r99` 这 100 个变量，不用逐个写。

## 三、反汇编与讲解：类型宽度和向量落地

下面这个内核同时踩到 8 位整型和 128 位向量，看它们在 PTX 里的类型后缀长什么样。

CUDA 源码：

```cuda
__global__ void typeKernel(char *c, float4 *v, const int *in) {
    int i = threadIdx.x;
    c[i] = (char)in[i];
    float4 f = make_float4(in[i], in[i]+1, in[i]+2, in[i]+3);
    v[i] = f;
}
```

真实 PTX（Compiler Explorer，NVCC 13.3.0，`-arch=sm_90a -ptx -O3`，指令原样贴入）：

{% raw %}
```nasm
        ld.global.u32   %r2, [%rd9];            // 读 in[i]（.u32）
        add.s64         %rd10, %rd5, %rd7;      // c[i] 的字节地址
        st.global.u8    [%rd10], %r2;           // 写 c[i]：.u8 类型（8 位，char）
        ld.global.u32   %r3, [%rd9];            // 再读 in[i]
        add.s32         %r4, %r3, 1;            // in[i]+1
        add.s32         %r5, %r3, 2;            // in[i]+2
        add.s32         %r6, %r3, 3;            // in[i]+3
        mul.wide.s32    %rd11, %r1, 16;         // i*16（float4 是 16 字节）
        cvt.rn.f32.s32  %f1, %r3;               // int → float（.f32.s32 转换）
        cvt.rn.f32.s32  %f2, %r6;               // 转 in[i]+3
        cvt.rn.f32.s32  %f3, %r5;               // 转 in[i]+2
        cvt.rn.f32.s32  %f4, %r4;               // 转 in[i]+1
        st.global.v4.f32 [%rd12], {%f1, %f4, %f3, %f2};   // 向量写：.v4.f32（128 位）
        ret;
```
{% endraw %}

两个类型在这段反汇编里一目了然：

**`.u8`——8 位无符号整型。** `st.global.u8 [%rd10], %r2` 里的 `.u8` 就是 char 对应的类型。有意思的是，数据从 32 位寄存器 `%r2` 搬进 8 位地址——这正是 §5.2.2 说的「`st` 允许源操作数比指令类型宽，窄值用宽寄存器装载」：`.u8` 指令只取 `%r2` 的低 8 位写出去。

**`.v4.f32`——128 位浮点向量。** `float4` 编译成 `.v4.f32`，一条 `st.global.v4.f32` 把 4 个 `.f32` 一次写进内存。花括号里的 `%f1, %f4, %f3, %f2` 就是那 4 个浮点寄存器拼成的 128 位向量——正好是 §5.4.2 说的「`.v4` 向量，最长 128 位」。注意编译器调整了元素顺序（`%f1, %f4, %f3, %f2` 而非 `%f1, %f2, %f3, %f4`），因为 `make_float4` 的四个分量 `(in[i], in[i]+1, in[i]+2, in[i]+3)` 分别被 `cvt` 转换后，寄存器分配的顺序和源码分量顺序不必一致——PTX 层面只关心「4 个 f32 装进一个 .v4」，不关心它们对应的源码语义顺序。

**顺带看到 `cvt.rn.f32.s32`。** 这是「类型转换」指令，`.f32.s32` 两个后缀表示「从 `.s32` 转成 `.f32`」——类型系统的「基本类型 + 大小」在这里体现得最清楚：指令要同时知道源类型和目标类型，才能正确解释那些位。

## 小结

- 基本类型五族：`.s*`（有符号）、`.u*`（无符号）、`.f*`（浮点）、`.b*`（位）、`.pred`（谓词）。
- 类型兼容性：基本类型相同且大小相同才兼容；`.s`/`.u` 大小相同即兼容；`.b` 与任何同大小类型兼容。
- 子字 `.u8/.s8/.b8` 限于 `ld/st/add/sub/min/max/neg/cvt`；`.f16x2` 等打包类型要用位类型声明。
- 变量声明 = 空间 + 类型 + 名字（+ 数组/初始化器/对齐）；谓词变量只能在寄存器空间。
- 向量 `.v2`/`.v4` 最长 128 位（`.v4 .f64` 非法）；数组/初始化器/对齐 `.align` 用法同 C 风格。
- 反汇编里，`.u8` 指令取宽寄存器的低 8 位；`float4` 编译成 `st.global.v4.f32` 一条向量写；`cvt.rn.f32.s32` 同时标出源、目标类型。
